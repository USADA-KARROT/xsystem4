# 第一階段：Numof／Count／Find 介面修正

日期：2026-09-20。**本階段已完成修正、局部回歸與完整引擎編譯；停在這裡等待使用者決定是否進入第二階段。** 沒有啟動遊戲，也沒有執行 observer／Join／timer 真實腳本整合。

## 做了什麼

修改本任務隔離副本 `work/stage2/source/src/hll/Array.c` 與 `src/ffi.c`。保留先前 18 個檔案的 checkpoint 修改；本輪沒有改動外部原始專案、遊戲或存檔，也沒有推送 GitHub。

- 按實際宣告分流 8 個重載：Numof #20／21、Count #22／23、Find #42／44／46／48。沒有使用固定遊戲函式編號選擇處理器。
- Numof 與 Count 無條件版共用邏輯元素數；predicate 版真正執行回呼並計算符合條件的元素數，不累加回傳的整數值。
- Find 分開值版、predicate 版和區間版。區間採 `[begin,end)`，不包含 end；負 begin 夾到 0，end 夾到長度，未命中回 -1，命中回原陣列的 logical index。
- 回呼依宣告區分單槽值、兩槽 interface／wrapped interface 和 primitive 引用。引用傳 owner page／index，避免把元素值誤當 page。
- 回呼若重新配置、釋放或改變陣列長度，先由 owner 同步 page，再明確報錯；防止外層使用或寫回已釋放的 page。本輪不承諾支援回呼改變陣列結構的原版語義。
- 值搜尋限於型別明確的 int／enum／bool／float／string。字串按內容比較，float 的正負零相等、NaN 不等；struct、interface、option、多維與型別已抹除的 generic page 明確拒絕。這避免把未知物件 handle 當成正確原版比較規則。

原版傾印檔的 jump table 證明 Numof／Count 兩對重載分別共用入口；Find helper 證明 begin／end exclusive 的範圍規則。資料身份與限制見 [原生契約](第一階段-Array證據-2026-09-20/native-contract.md)。
