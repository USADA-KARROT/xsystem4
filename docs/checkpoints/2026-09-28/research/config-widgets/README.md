# 設定畫面的核取方塊、單選群與視窗設定

2026-10-11。程式 `705aac6`（視窗設定與滑鼠游標設定）、`537d3ec`（核取方塊、單選群、橫向捲軸的數值與事件），以及 `5cbaafa` 裡屬於這一組的部分（兩處註解與探針 W13）。一起推送的五個 commit 的第三、四、五個，前面是 `58eda8d`，推送後的 HEAD 是 `5cbaafa`。實作、突變與並排量測是在 `4682a89` 上做的，之後才接到 `58eda8d` 上；另外兩個 commit 見[對白逐字淡入](../dialogue-fade/README.md)。

這一步讓設定七頁、系統選單與確認框的核取方塊和單選群可以顯示、可以點，橫向捲軸有數值與捲動事件，視窗設定照原版的型別表保存。**橫向捲軸的把手與拖曳、按鈕的文字沒有做**；視窗設定與游標設定只保存、不生效。

## 症狀（修改前，實機）

先前的交接文件把「開設定頁會清掉設定」記成靜態推論。動手前先在未修改的 `4682a89` 上以函式的進出追蹤證實：

| 操作 | 看到的 |
| --- | --- |
| 開設定第 1 頁 | 第一幀讀到訊息速度 0.5、已讀跳過速度 1.0，同一幀寫回的是 0、0；第二幀起讀到的都是 0 |
| 切到「信息」頁 | 第一幀讀到四個勾著的設定（點擊解除跳過、點擊解除自動、訊息視窗動畫、已讀文字變色）都是 1，同一幀寫回 0；按「返回遊戲」時把清掉的值存進 `AFConfig.asd` |
| 關掉設定再開 | 讀到的仍是 0、0 與四個 0 |
| 切到「窗口」頁 | 5 秒內呼叫切換全螢幕 225 次，每幀一次。這一項用的是「把切換改成只記一行日誌」的診斷建置：未修改的建置會真的切成全螢幕，沒有跑 |

畫面上，七頁、系統選單與確認框都沒有核取方塊；「信息」頁的已讀文字樣本是白的（原版金黃：已讀變色一進這一頁就被關掉）。

## 根因

1. **核取方塊、單選群、橫向捲軸的函式庫函式是空殼**（讀取回 false 或 0），pactex 載入器也不建這三種元件。設定頁的腳本每一幀都是「把設定寫進元件 → 更新 → 從元件讀回、寫進設定」，所以讀到的 0 當場成為設定值。
2. **`SystemService` 視窗設定的型別表對不上這個遊戲**。這裡的表是上游為較早的遊戲寫的：2 是垂直同步、3 是記住視窗位置與大小、4 是全螢幕非作用中最小化、5 與 6 是兩個確認；這個遊戲的原版只有 0–4，2、3、4 的意義都不同，預設值也不同。核取方塊能點之後，「窗口」頁的「最小化」那一格會開關垂直同步並寫進 `WindowSetting.json`，「輸入」頁的兩個確認寫到別的欄位；停在這兩頁時每幀覆寫那個檔。這一項是第一次審查指出、提交前修掉的。
3. 游標設定只收一個型別，腳本用三個：核取方塊做出來之後，被拒絕的那兩格一勾就會被取消。

## 做法

- **`705aac6`**（`src/hll/SystemService.c`）：AIN 是 v14 以上時走自己的五格表（初值五個 1；型別 1 存原數，其餘存 0 或 1；其他型別回 false）。值存在 `WindowSetting.json` 的 `"v14"` 物件，**值改變才寫檔**（原版在關視窗時寫；這裡沒有對應的收尾時機）。型別 2 不再接垂直同步。**五個值都只保存、不生效**：畫面一律保持比例、只有一種放大濾鏡、全螢幕失焦不最小化、沒有視窗選單、關視窗時不問腳本。v13 以前完全是原來的程式。游標設定在 v14 收三個型別，各存一個旗標，只保存、不存檔。
- **v14 不再讀 `wait_vsync`**：舊建置在這個遊戲寫下的 `wait_vsync` 其實是「最小化」那一格的值，從來不是對垂直同步的選擇，所以不讀，下一次寫檔時消失。垂直同步的預設本來就是關；副作用是 v14 的遊戲目前沒有設定可以把它打開。
- **判別用的是 AIN 版本**，和專案其他地方一致；這張表只從這個遊戲的執行檔確認，別的 v14 遊戲若仍用舊表，會被一起帶到新表（目前支援的 v14 遊戲只有這一個）。
- **`537d3ec`**，核取方塊與單選群（新檔 `src/parts/checkbox.c`、`src/hll/pe_v14_checkbox.h`；載入在 `pe_v14_activity.c`）：pactex 的 21 個鍵與成員清單、勾選的入口、啟用、互斥、四個函式庫函式（依 AIN 的宣告形狀綁定，查找是取得或建立）。**不做內部元件**：方框與文字合成到元件自己的三個狀態，像素與可點範圍和原版兩個內部元件疊起來相同。沒有任何事件的元件不把訊息入列（腳本本來就會丟掉）。存檔格式沒有動。
- **`537d3ec`**，橫向捲軸（`src/parts/scrollbar.c`）：載入和直向的一樣的四個量；位置與比率的讀寫（四個函式，同樣是取得或建立）；照原版送訊息 21；載入的值算已回報。最後一點只對橫的做：少了它，聲音頁載入在最大位置的三條會把音量 100 寫成 99。直向的捲軸原版也一樣，但資料裡載入值不是 0 的兩個畫面沒有路線可看，沒有動。
- **`5cbaafa`**：兩處註解（這張表的依據只有這個遊戲；核取方塊按下後拖開的差異，見下）與探針 W13 的補強。

### 點擊先記下來，下一次元件更新才套用

第一版在點擊當下就切換，探針全過，實機卻時好時壞：點了第二個方框，畫面上沒有勾，關掉再開也沒有。原因是這個移植版除了元件更新，`system.Peek` 也跑一次輸入更新；按下如果是在那裡被看到，切換就落在腳本「寫設定 → 更新 → 讀回」的括號外面，下一幀的「先寫」把舊值寫回方框。原版沒有這個問題：它的輸入更新只在元件更新裡。

所以點擊時只記下元件號碼與當時的事件 ID，值在下一次元件更新（輸入之後）才換；MouseClick 仍在按下當下入列，`ChangedFlg` 在值真的改變時入列。元件被釋放、換成別的型別、輸入重設時，還沒套用的點擊會被丟掉。**之後做橫桿的拖曳也要這樣**：比率若在 `system.Peek` 裡就改掉，同樣會被蓋回去。

這帶來的差異：按下若是在 `system.Peek` 裡被看到，腳本處理 MouseClick 時方框還是舊值，新值與 `ChangedFlg` 晚一幀（原版同一批；遊戲掛在核取方塊上的點擊處理都是設成固定值，不讀方框）；按住期間顯示的是新值的按下圖（原版是舊值的，放開才換）；**按下後把游標拖開再放開，原版不切換，這裡已經切換**。事件 ID 換了就丟掉點擊、還沒套用的超過 8 筆就丟掉，是這裡自己的防護，沒有原版依據。

> 2026-10-12 更新：這一節的做法已拿掉（`aa541a7`）。v14 的 `system.Peek` 不再跑輸入更新，所以延後的理由不存在了，「之後做橫桿的拖曳也要這樣」的前提也跟著不成立。核取方塊改在放開時當場切換（游標還在它上面時，在它的 MouseClick 之後），點擊紀錄與它的防護一起拿掉。上面列的差異不再有：按住時是舊值的按下圖、拖開再放開不切換，這兩項和原版的錄影對過；MouseClick 與 `ChangedFlg` 在同一次更新，只有探針。見 [input-model](../input-model/README.md)。

## 用舊建置開過設定頁的存檔資料夾

**`537d3ec` 之前的建置只要開過設定畫面，那個存檔資料夾的設定可能已經被清掉並存檔，換新建置後不會自己回來。** 新建置照實讀寫現有的值；程式不會自動改檔。

- 怎麼發生的：開過哪一頁，那一頁的設定當場被寫成 0 或不勾；按「返回遊戲」或存檔時寫進 `AFConfig.asd`。
- 看起來像移植版的毛病、其實是那個資料夾的設定：第 1 頁三個速度是 0，**文字顯示變得很慢**（訊息速度 0 是 4 倍的間隔）；「信息」頁九項全不勾（預設勾著的是四項），已讀的字不變色；「信息窗口」頁的透明度與亮度是 0；聲音頁最下面的三個核取方塊、「輸入」頁的四個確認、「窗口」頁的「降低ＣＰＵ使用率」、遊戲設置頁的網路連線都不勾。
- 不進存檔、只影響當次執行的：五條音量與消音、游標三項。`WindowSetting.json` 裡留下的 `wait_vsync` 不必處理。
- 補救：最簡單是刪掉那個資料夾的 `AFConfig.asd`，遊戲會用預設值重建，存檔本身（`SaveData*.asd`）不受影響。或進設定畫面逐頁重設：核取方塊重新勾；橫桿目前拖不動，只能按那一列最右邊的「初始化」（第 1 頁的三個有字，另外兩頁的目前是沒有字的白色按鈕）。

## 驗證

- 探針：新模式 `config-widgets` 13 案（各案內容見 [harness](../../harness/README.md)）：合成的 pactex 經正式載入器、函式庫函式經 AIN 的宣告呼叫，期望的像素與訊息依原版的算式。設定頁的迴路在探針裡是直接呼叫函式庫函式，沒有跑腳本的包裝；真位元組碼的端到端只有實機路線。
- 修前失敗（[before／after](before-after.txt)）：`58eda8d` 上 13 案中 12 案失敗，`705aac6` 上 11 案；`537d3ec` 上全過（第五個 commit 對 W13 的補強是守衛，修前就過）；修正後全過；兩種字元規則結果相同。實作時在 `4682a89` 上同樣是 12 案失敗（通過的是 v13 的守衛）；接在審查前的那一版上是 5 案失敗（橫向捲軸的訊息與位置、視窗設定、點擊紀錄）。
- 反向檢查：38 處刻意改壞，每一處都有案例失敗。「讓 v14 的型別 2 去設垂直同步」第一次沒有被抓到：探針沒有視窗，看不到交換間隔；改成讀舊表的垂直同步旗標之後抓到。**仍然看不到的**是「只呼叫設定垂直同步的函式而不動那個旗標」的寫法，靠的是程式本身與實機的設定檔內容。這是在 `4682a89` 上的最終版做的；接到 `58eda8d` 時程式檔都是乾淨套用（衝突只有 harness 的兩個清單檔），筆記裡沒有之後重做的紀錄。
- 既有探針的斷言沒有改。預設與 GBK 各 94 模式 VERDICT PASS、sanitizer 0（[預設](verify-default.txt)、[GBK](verify-gbk.txt)；推送後在 `5cbaafa` 上跑的）。
- GUI（[摘要](gui-summary.json)，`RUN_RANDOM_SEED=20261008`，推送前在 `5cbaafa` 的原始碼上）：十條路線沒有斷言、VM 錯誤或堆疊溢位；九條的對白行數與雜湊和前一組相同，`noskip` 的行數因為另外兩個 commit 而不同（見對白逐字淡入那一份）。
- 下一節的實機與量測都是提交前在 `4682a89` 上的工作副本做的，用的是不在例行清單裡的路線（逐頁切換、逐格點擊、關掉再開、存檔確認、讀取確認、聲音頁、重啟後讀回）；推送後的十條路線只看過設定第 1 頁、系統選單與存檔確認框的畫面，沒有重量。自動路線都不點「全屏」。

## 實機上的改變（與原版並排）

- **設定值不再被清掉**：同一條「開設定 → 信息頁 → 返回遊戲 → 再開」的路線，再開之後讀到的仍是 0.5、1.0 與四個 1（修改前全是 0）。逐幀追蹤 64 幀、讀到與寫回的值都不變的那一次，用的是點擊當下就切換的第一版；最終的原始碼追蹤的是再開之後的頭幾幀。已讀文字樣本是金黃。
- **七頁的核取方塊**：以 pactex 的座標在兩邊各取一個視窗量外框，57 個可見的方框裡 52 個完全相同，5 個只差右緣 1 px（原版的截圖是 JPEG）。說明文字的底部和原版裁在同一列。這是審查前量的；審查後的七頁與它只差第 5、6 頁的幾個勾。
- **勾選狀態**：第 1、2、4、6 頁與原版相同（第 3 頁沒有核取方塊）；「輸入」頁的「存檔時進行確認」與遊戲設置頁的兩格，新遊戲是勾、原版的截圖不勾，那是拍原版時那份設定的值。另一條路線在存檔確認框勾「以後不再顯示此信息」再按確定，腳本把那個設定寫成 0，之後「輸入」頁八格的勾選與原版完全相同。
- **點擊**：點方框與點它的字都會切換；單選群互斥，點已勾的那一個不變；關掉設定再開，值都留著。系統選單的八個方框外框與原版相同（勾著的暗像素 463 對 463、停用的 406 對 406），滿四個之後其餘變灰、點了沒有反應（點擊的這幾步沒有原版畫面，依據是腳本）。
- **讀取確認框**：方框的外框與原版相同；那一行字除了第一個字的左緣早 2 欄，每個字的欄界都一樣，但整行高 1 列。同一個框的粗體標題也高 1 列，不粗的那一行相同：是粗體字在字格裡的位置，不是核取方塊的版面，沒有改。
- **視窗設定**：點掉三格後關設定再開，三格都還是不勾；檔案裡只有 `"v14"` 物件、沒有 `wait_vsync`，之後設定頁每幀把值寫回去也不再寫檔。拿那個存檔資料夾重新啟動，三個值讀得回來。逐頁切換而不點任何東西的路線不產生這個檔。
- **聲音頁**：事件鏈通了（設位置 → 下一次更新一則訊息 21 → 事件寫音量），「初始化」有反應。**但下面三條的數值是 0，原版約 80**（由原版截圖的把手位置估的）。原因在混音器，不在捲軸：這裡只有三個聲道，那三條對應的聲道 6–8 不存在，讀寫都落空，預設音量又固定回 100。按「初始化」因此聽不出差別，也不會寫壞別的聲道。
