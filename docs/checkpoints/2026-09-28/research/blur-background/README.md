# CG 構築背景、混色填色與灰階

2026-10-10。G16 已審查整合 `83b09ac`、`8787a31`，推送後以 ls-remote／GitHub branches API 雙源核對。預設／GBK各88模式PASS，提交後9條GUI完整結束。

## 症狀與根因

pactex 載入器沒有接受首步為命令 2（以 CG 建表面）的構築手順，據點、春銷、設定等畫面因此顯示原始清晰圖片。設定頁還缺少手順末尾命令 4 的壓暗。共 23 個狀態使用 11 個 CG，手順形狀為 (2,28,27)、(2,27,28)、(2,27,28,4)、(2,15,28,27)、(2,3)。

手順形狀統計：`(2, 15, 28, 27)` 1處、`(2, 27, 28)` 1處、`(2, 27, 28, 4)` 7處、`(2, 28, 27)` 12處、`(2, 3)` 2處，共23處。AIN 的 `AddPartsConstructionProcess` 僅一個宣告／一個直接 CALLHLL，形狀為 `void(int, wrap<array<int>>, wrap<array<float>>, wrap<array<string>>, wrap<array<int>>, int)`；本組不改該腳本分派，新增支援在 pactex 載入器。

## 原版依據

- 命令 2：`0x4fbf40` → `0x50ac80`；先釋放表面 `0x4fbf72`，再按 CG 尺寸建立，載入失敗後沒有表面並停止後續手順 `0x4fb675`。
- 命令 4：`0x4fc190` → `0x5ac510` → `0x4922a0`；RGB 各為 `floor((255-A)*d/255)+floor(A*c/255)`，兩個商分開截斷，alpha 保留；查表由 `0x491660` 建立。
- 命令 15：`0x4fe870` → `0x5ad7b0` → `0x5ad8f0`；灰階為 `(306R+601G+117B)>>10`，alpha 保留。
- 命令 27／28 沿用既有模糊操作與測試模型，本輪沒有重做整個模糊演算法。
- CG 通道：原版命令 5 在 `0x4fc378` 檢查 alpha，RGB 圖在 `0x4fc400` 成功跳過該命令。移植版 RGBA texture 並未保留此來源通道區別。

## 修正及審查

首步 2 的 pactex 狀態接受上述已核對的 2／3／4／15／27／28 手順；新增 CPU 混色與灰階操作。v14 CG 載入失敗會清空表面／尺寸並停止後續操作；v13 保留既有行為。新操作在 enum 尾端追加，XPE 存檔升第 10 版，保留第 7–9 版讀取。

獨立初審發現新起始 CG 路徑還接受 alpha 操作，RGB 圖接命令 5、alpha=0 會變透明。修訂在建立 plan 階段拒絕整份未支援手順，沿用原有 CG fallback，避免先執行部分前綴；首步 0 的原有接受集合不變。這是保守的相容界線，不能稱所有 CG 手順都與原版相同。

## CG 百分比倍率調查

原版 `0x50ac80` 使用 CG-info 的 vtable +0x2c／+0x30。一般 CG、DCF、PCF 的 getter `0x45fd70` 回固定 100；CCR 類型由 `cuti` 的七整數記錄最後兩項取正數倍率，經 `0x45fb90` 建構，getter `0x45fc90`／`0x45fca0` 讀欄位。非 100 時在 `0x50ae0a`–`0x50ae38` 算整數縮放尺寸。

本組 23 狀態的 11 個唯一 CG 已核對實際檔頭，全是 QNT，走一般 100% 路徑；元件縮放都是 (1,1)。libsys4 沒有 CCR／cuti 及資源倍率 API，本組沒有變動 submodule 或實作 CCR。沒有全面檢查整個資源庫內容，也未驗證快取是否可被其他路徑改寫。

## 探針

`construction-cg` G1–G9：CG 尺寸／顏色／alpha、兩方向模糊與順序、混色截斷、灰階、拒絕形狀與載入失敗、XPE roundtrip／舊版本、v13、極端數值及 RGB CG fallback。使用在記憶體生成的 PNG 與 probe 專用資產管理器副本，正式引擎不含測試掛點或遊戲資產。

新增 G9 在未審版 `ee54909` 實際失敗，總計 1／9 fail、san=0，G1–G8 通過。獨立複審已結清該Medium、沒有剩餘High／Medium。修後支線default／GBK各87PASS，整合主線後default／GBK各88PASS、san=0；`array-construct`14案及本模式9案全過。正式提交後before在主線修前 `0ded2b3` 為8／9失敗、`ee54909` 為1／9失敗，皆san=0並已還原。提交後9條GUI均完整duration、exit0、error0，對白逐位元組與G15基準相同。

## 保留範圍

腳本路徑命令 4 仍是既有 GPU 混色，命令 15 仍未實作；pactex 拒絕的形狀沿用 fallback，而非重現原版部分執行後失敗。8192 尺寸上限與超界 alpha 拒絕是安全界線。舊存檔的 CG 狀態讀回仍保持舊畫面，須 activity 重載才會建立新構築狀態。存讀檔實機、商店、派遣結果、GameOver、附錄及設定第 2–7 頁未驗證。背景模糊不等於地圖左緣淡出或設定控制項已修好。
