### 腳本與 pactex 的量測【AIN】【量】

- **pactex**：195 個、2706 個元件（含根）。每個元件都有兩個音效鍵；非空的各 110 個，而且是同一批元件，指針、點擊各只有一個名稱。這 110 個分布在 43 個 pactex：按鈕 83、低等級部件 15、檢查ボックス 9、パネル 2、豎滾動條 1。其中 2 個帶音效的元件位在另一個帶音效的元件底下（同一個畫面）。110 個的游標穿透旗標全是 0（語義審查者另外量的）。
- **オン指針表示連動**：非空的只有 4 個，都在設定第 6 頁：四個說明文（低等級部件，沒有子元件）各連到同一個 activity 裡名稱唯一的一個檢查ボックス；四個目標自己的 pactex 音效是空的，它們的音效由腳本設。
- **腳本設名稱的地方**：IParts 的 `OnCursorSE`／`ClickSE` 的 set 呼叫 `Parts_SetSoundName(n, 名稱, 2／3)`。遊戲本體呼叫 set 的只有四處：`UserConfig::SetSound`（設定各頁的 activity 讀入後，對每個按鈕、檢查ボックス與橫捲軸設兩個名稱）、`StateMark@SetClickable`（可點擊時設、否則設空字串）、`CustomerInfoView@SetClickable` 的 lambda、`MapPlayerUnitView@CreateClickTarget`。名稱也只有那兩個。音效名的 Get、連動的 Set／Get 只有編輯器呼叫；遊戲本體不在執行時設連動，連動只來自 pactex。
- **`Parts_PlaySound`**：只有 `AFL_Parts_PlaySound` 等三個包裝；另兩個由 `CSpriteParts@PlayOnCursorSE`／`PlayClickSE`（ISpriteParts 的介面槽）呼叫，介面槽的呼叫點太多，靜態分不出遊戲本體有沒有呼叫【未確定】。
- **點擊落空音**：遊戲本體只有 `parts::detail::WaitForClick` 結尾設空字串；`GetClickMissSoundName` 沒有呼叫者。
- **腳本的通道號碼**：KiwiSoundEngine 的 `GetFreeID`、`IsExistID` 沒有呼叫點，全是固定號碼：音樂 1、2；循環音效 3–8；音效 10、11；語音 12；系統音效 14–19（用完會 Unprepare）；背景音效 20；背景語音從 21 往上數。腳本不用的是 0、9、13。修前的 `PlaySe` 也在同一個池（5、6、7、15；G11 會把它移到 SE 表）。

### 推論【推】

- **SE 3 的 40 ms 同名抑制**（沒有追進 PlaySe）：G11 的補查讀到 `Music@InitSystemSound`（FUNC 30232）把 SE 0–4 設成同一組參數：40 ms 內同名不重播、可同時播。照這個讀法，原版同一個名稱在 SE 3 上播出未滿 40 ms 時，下一次 PlaySe 不播；不同名稱各播各的。
  - **範圍**（語義審查 A-L1 更正）：帶音效的元件游標穿透旗標全是 0，一被進入就停住走訪，所以同一次更新不會同時新進入兩個帶音效的元件，巢狀的那 2 個也一樣。兩邊的差別只在「40 ms 內第二次新進入同名音效的元件」，例如快速劃過相鄰的按鈕：原版推定只響第一次，移植版每次都響。
- **群組**：PlaySe 的通道依 timemap 掛群組，指針音與點擊音的兩個檔在群組 2（G11 讀的）。移植版的匿名通道照 timemap 掛群組；錄音的增益等於音效群組的鏈（見〈實機錄音〉），兩邊一致。
- **連動目標的 vtable +0x50 讀哪個旗標沒有讀到**：推定是游標走訪的進入旗標，或 widget 層的同義判斷。中文版原版在游標不在目標上時說明框是空的，和這個讀法一致。+0xb4 的初值沒查：初值若是 1.0，頁面打開後的 100 ms 內會先淡出。
- **子元件也跟著淡**：`0x535260` 乘進的是往下傳的 alpha。
- **被連動隱藏的元件原版不會被進入**（語義審查 A-L2）：原版把 +0xb4 乘進 alpha，游標走訪只進入 alpha 大於 0 的元素；`0x535260` 到元素 alpha 的路徑沒有確認。
- **停用按鈕的 `Parts_GetSoundName` 回按鈕自己的名稱**：由 `0x5285b0` 從按鈕元件（W+0x21c）抄名稱的寫法推得。檢查ボックス、捲軸有沒有同樣的清空沒讀；パネル、豎滾動條在原版播不播也沒讀（只有低階部件 widget 的更新會同步名稱）。
- **名稱不在封存時**：原版的 PlaySe 會照樣試，推定靜默失敗。

## 做法

- **pactex**：在 `pactex_apply_properties` 讀兩個音效鍵（CN 版的 GBK 拼法），存進第 2、3 格，根元件（`pactex_load`）與子元件（`pactex_create_component`）兩條路徑都會走到。連動的名稱先記下，在 `pactex_load` 結尾於同一個 activity 內解析，前後順序無關；空字串、找不到都不連，根元件的兩個別名（`""` 與根的固定名稱）不看。
- **名稱槽**：每個元件四格。v14 的 `Parts_SetSoundName`／`GetSoundName`：號碼大於 0 時取得或建立元件，0 以下什麼都不做。
- **播放**：設第 2、3 格時，就把名稱換成音效封存裡的號碼（存在既有的 `on_cursor_sound`／`on_click_sound`），進入與放開照 G3 接好的位置播。`Parts_PlaySound`：2 播第 2 格、3 播第 3 格，其他不播。
- **停用的按鈕**：進入與放開都不播（等效於原版清空內部元件的兩個名稱），`Parts_GetSoundName` 仍回名稱，重新啟用後照播。
- **連動**：v14 的 Get 換成真的讀取，沒有連動是 0；v14 的 Set 對來源取得或建立，目標只記號碼、不為它建元件。顯示的判斷抽成 `parts_link_shown`：連動目標進入中才畫，沒有連動、號碼沒有元件時照畫（不建出目標）。
- **存檔**：名稱存成選用區塊 `PSND`，放在 `PWHE` 之後、`PCID` 之前，只在有元件帶名稱時寫。內容是記號、數量，以及每個帶名稱的元件的號碼與四個名稱（各自的長度，再逐位元組，和字串規則無關）。存檔版本仍是 XPE 13。讀回時用名稱重算號碼；沒有 `PSND` 時名稱是空的，號碼用元件記錄裡的；區塊讀不下去時只記警告、略過，存檔其餘部分照讀。
- **點擊落空音**：`SetClickMissSoundName`／`GetClickMissSoundName` 存取一個字串，不播放。
- **匿名通道**：改成自己的通道物件，不再借 wav 池的空號（見〈匿名通道〉）。
- **適用範圍**：新的綁定只在 AIN 版本 14 以上、而且 AIN 的宣告形狀相符時註冊（v15 會共用）；`PSND` 也只為它們寫。v14 之前的遊戲照舊：共用的 `PE_GetOnCursorShowLinkPartsNumber`／`PE_SetOnCursorShowLinkPartsNumber`（GUIEngine、GoatGUIEngine 與舊版 PartsEngine 也用）沒有連動回 −1、Set 兩邊都取得或建立；連動的舊繪製判斷與號碼 API 不變。匿名通道的改動**不限 v14**。

### 移植策略（不是原版行為）【移】

- **Set 時就換成號碼**：原版在低階部件下一次更新時才把名稱抄過去（`0x565200`），播放時以名稱經 `PlaySe(3)` 播（`0x5ba830`）。移植版在 Set 時就以名稱查音效封存，輸入照號碼播。探針的每一案在 Set 和觀察之間都至少有一次更新，所以兩種時序都會通過（探針審查 M1）。
- **名稱不在封存就不播**：空字串或封存裡沒有的名稱是 −1，不播，也不向封存要資料；原版推定照樣試、靜默失敗，聽起來相同。改名成封存沒有的名稱之後，也不沿用舊的號碼（探針審查 M2）。
- **停用按鈕的 `Parts_PlaySound` 也不播**：原版的這個呼叫走 widget 的低階部件，沒有追；移植版比照進入與放開，一律不播。審查者的突變 R3、R8（停用按鈕照播）存活，沒有案守（見〈突變〉）。遊戲本體有沒有呼叫 `Parts_PlaySound` 靜態分不出。
- **沒有 40 ms 同名抑制**：範圍見〈推論〉。播放都經過 `audio_play_sound` 這一處，G11 推送後可以改走 SE 3，照原版的參數抑制。
- **連動立即顯示或隱藏，只隱藏元件本身**：原版約 100 ms 淡入淡出（+0x44），並乘進子元件的 alpha；移植版瞬間切換，子元件照畫。遊戲的四個說明文沒有子元件。
- **被連動隱藏的元件仍被游標走訪進入，並像顯示中一樣擋住走訪**（語義審查 A-L2）：移植版的走訪只看顯示旗標與 alpha，不看連動。第 6 頁的四個說明元件不穿透游標，所以隱藏時游標經過它們仍會進入（收到 MouseEnter／OnCursor），走訪也停在那裡。原版推定不會進入（見〈推論〉）。第 6 頁的說明框底下沒有可互動的元件（審查者看過並排圖），目前看不到影響。
- **連動的 Set 只保留大於 0 的號碼**（語義審查 A-I1）：原版原樣寫入，負數也存、Get 讀回負數；移植版把 0 以下當成沒有連動，Get 回 0。原版的 Get 走取得或建立，移植版的 Get 不建元件。這兩個 HLL 只有編輯器呼叫【AIN】，遊戲本體不受影響。
- **SJIS 拼法的 pactex 鍵沒讀**（語義審查 A-I2）：三個鍵只比對 CN 版的 GBK 位元組，不猜 SJIS 拼法。SJIS 的 pactex（例如英文版）跑這個移植版時，pactex 來的滑過音、點擊音與連動照舊沒有；腳本以 `Parts_SetSoundName` 設的名稱（設定各頁的 `UserConfig::SetSound` 等）不經過 pactex，新綁定也只看 AIN 版本與宣告形狀、不看字集（讀程式），所以推定照新邏輯播；英文版沒有在移植版上實測（推送前公開內容覆核 P-L2）。
- **State 0–3 以外**：不寫，Get 回空字串（原版是越界存取）。
- **點擊落空音**：存取、不播；Set 之前 Get 是空字串（推定原版是預設建構的空字串：`0x53ed10` 沒有寫 +0x1e4，子物件的建構子沒讀）。
- **`linked_from` 只記最後一個連到它的元件**（輸入用它標記重畫）；遊戲的四個連動目標各不相同。重複的短名稱取 activity 裡第一個同名的元件；原版名稱表遇到重複短名稱怎麼處理沒讀。
- **點擊音與 MouseClick 的先後**：原版先送 MouseClick 再播（`0x578992` → `0x5789bc`）；移植版的放開處理先播再送，G3 之前就是這樣，這一組沒有動。音量在混音時才乘，所以同一次更新裡的先後推定聽起來相同【推】：錄音裡點音效橫桿那一下是靜音、按重設鈕那一下是恢復後的音量，照原版的順序也會得到這兩個結果。

## 匿名通道：不再借 wav 池的空號

### 舊作法與撞號

- **讀程式**（基準 `d3908e5`）：
  - `audio_play_sound`／`audio_play_archive_data` 用 `wav_get_unused_channel()` 取號，也就是 wav 池裡最小的空號；這和腳本經 KiwiSoundEngine 用的號碼是同一個池。匿名槽有 64 個。
  - `audio_update` 每幀把匿名槽記著、「不在播」的號碼 unprepare。
  - 腳本 Prepare 同一個號碼時，會把那個號碼的舊通道關掉；匿名槽仍記著那個號碼。
- **會撞到**【推】：第一個匿名聲音拿 0（腳本不用）；同時有第二個以上時，拿的是當下最小的空號，幾乎都是腳本的固定號碼，例如音樂只用了 1 時的 2、還沒用的循環音效 3–8、用完 Unprepare 而空著的系統音效 14–19。點擊音不到半秒，點完馬上滑到下一顆鈕就會同時有兩個。撞到時有兩種後果（讀程式）：
  1. 腳本 Prepare 那個號碼時，引擎的聲音被換掉，滑過音或點擊音被切掉。
  2. 下一幀 `audio_update` 看到那個號碼「不在播」（腳本 Prepare 好、還沒 Play），就把腳本的通道關掉；之後腳本的 Play 失敗，或播到別的聲音。
- **探針量到**【量】：PS15 在 `d3908e5` 上，照遊戲的號碼走（腳本在 1 放音樂；A 鈕的指針音與點擊音；腳本 Prepare(2)；下一幀游標進入 B 鈕；腳本 Play(2)）：
  - 指針音拿到 0、點擊音拿到 2，`IsPlay`、`IsExistID` 對 0、2 都是真；
  - 腳本 Prepare(2) 之後，混音裡只剩 2 個聲音（應有 3 個）；
  - 下一幀之後腳本的 Play(2) 回真，但混音裡是 3 個聲音（應有 5 個）。
  - 「`audio_update` 關掉了腳本的 2，B 鈕的指針音又拿走 2，所以腳本的 Play(2) 播的是引擎的聲音」是由電平推得的，沒有直接觀察通道的資料來源【推】（證據審查 B-L5）。
- 修前滑過音幾乎不播（號碼永遠 −1），所以碰不到；G4 接上之後每次新進入都播。
- **原版沒有這個問題**【反】：元件的 CSound 走 `PlaySe(3, 名稱)`（`0x5ba830` → `0x4a3340`），SE 表和一般 ID 表是兩張表（`0x4a2f00`）。

### 做法【移】

- 匿名通道直接存通道物件：開檔方式和 `wav_prepare` 相同（音效封存、bStreaming 0，所以 v14 照 timemap 的列掛群組），`audio_update` 自己關掉播完的，`audio_reset` 也關掉它們。腳本的號碼完全看不到這些聲音（`IsPlay`、`IsExistID` 都是假），和原版 SE 表與一般 ID 表分開的結構一致。
- **不限 v14**：元件的指針音與點擊音、`Parts_PlaySound`、元件動作的音效（motion）與 flash 的聲音，以及 DALKDemo 主選單的兩個選單音（切換選項與點擊），都走這裡（`audio_play_sound` 與 `audio_play_archive_data` 的呼叫點，讀程式；DALKDemo 一項是推送前公開內容覆核 P-L1 補的）。其他遊戲（例如 SACT2 系）以前在池裡看得到這些聲音，現在看不到；沒有實測。
- 附帶修正：`audio_play_archive_data` 在沒有空的匿名通道時，原本漏掉交給它的資料（標頭說它接管所有權），現在會釋放。探針沒有這一案（flash 的聲音；遊戲有沒有走到沒查）。
- v14 不會呼叫 `audio_reset`（只有 SACT2 的 `_ModuleFini` 會），PS15 的那一段是給其他遊戲的防守。

## 提交說明的讀法

`7baaa12` 的提交說明在提交前另做了一次逐句查證（對證據與反組譯），沒有和量測相反的句子；查證時收窄的幾處已經寫進提交說明。下面幾句的範圍以這裡為準。程式不 amend：改寫會換掉雜湊與執行檔裡的版本字串，提交後驗收的執行檔就對不上 commit。

- 「Measured on a build of this code」：錄音、九條路線與第 6 頁並排用的是實作完成時的建置（`7dd0a1f3…`）。審查後的修正沒有改程式，但重建（修前檢查與突變會 touch 原始檔）把那支執行檔覆蓋掉了；它和提交的程式碼相同是推論：原始碼的雜湊全部相同、檔案大小相同、同一個建置目錄與工具鏈，加上一個實驗（只 touch 一個檔再建，兩支新的執行檔只差 LC_UUID、一筆 N_OSO 與程式碼簽章，`__TEXT`、`__DATA` 逐位元組相同）。
- 「buttons, check boxes and a slider … play the cursor sound at each new enter」：滑過量到的是按鈕、檢查框與一條橫捲軸。「clicks on buttons and a check box play the click sound」：點擊只量到按鈕與一個檢查框（BGM 的靜音框）；點橫桿那一下因為同一格就把音效設成 0，分不出來。
- 「each matching its sound file at the gain the volume settings give」：精確的說法是「乘上增益之後，到 float32 的捨入都相同」；增益依總控、音效橫桿與音效群組的內部音量而定，按重設鈕那一下的指針音中途從 0 變成 0.60420（見〈實機錄音〉）。
- 「Two disabled buttons are silent when entered」：停用按鈕只量了進入，沒有量點擊。「two hovers with the sound effect volume at 0」：只量了兩次滑過。
- 「That ID could be one of the script's fixed IDs …」：撞號是讀程式加 PS15 量到；誰佔了號碼是推論（見〈匿名通道〉）。
- 「40 mutants are caught」：作者的 40 個，在審查後的最後一棵樹上跑（提交的 15 個檔和它逐檔相同），其中 R1、R2、R2b 是語義審查者寫、原樣收進作者表的。存活的六個見〈突變〉。
- 「Default and GBK suites pass 121 modes」：指提交前的兩輪；提交後兩組也各 121 模式 PASS（見〈驗證〉）。
- **程式註解與探針檔頭**（推送前公開內容覆核 P-I1；不 amend，排給下一個碰這兩個檔的程式提交）：探針檔頭的日期寫 2026-10-25，harness README 用程式提交日 10-26；檔頭 PS15 的說明把 20 與 21 起都寫成背景音效、全是固定號碼，腳本的讀法是背景音效 20、背景語音從 21 起由計數器往上數（見〈腳本與 pactex 的量測〉）；`src/parts/render.c` 的「fades it over 100 ms」是由 +0x44 的預設值 100 推得的約 100 ms（見〈反組譯看到的〉）。

### 實機錄音（提交前的建置）

- **做法**：SDL 的磁碟音訊驅動（float32、44.1 kHz、立體聲），和 G1、G2 相同；錄的是混音器交給裝置的樣本，不是喇叭。音量種子把 BGM 與語音設成 0（總控、音效 80），錄音裡只剩音效。參考從遊戲工作副本的音效封存唯讀取出、照引擎的方式解碼（只放在私人工作區）。在整段錄音裡找參考的位置（正規化互相關 0.9 以上），每一處算最小平方增益與殘差；滑過音與點擊音重疊時兩個一起擬合；按重設鈕那一下逐 1024 frame（一個混音塊）量增益。修前的執行檔（G3b 提交後的建置，程式等於 `d3908e5`）跑同樣的排程。自動輸入只移動或點擊；8 趟（修前修後各 4 趟，含第 6 頁那兩趟）都是 exit 0、錯誤 0、`XSYS4_NO_DESKTOP_WARP=1`，桌面游標前後不變。
- **據點**（名稱來自 pactex）：
  - 游標每次新進入可用的按鈕（4 顆，共 6 次），都錄到指針音，殘差比錄音低 147.4 dB，增益 0.60420；停在沒有名稱的中性點不響。
  - 兩顆停用的灰色鈕滑過時數位靜音（峰值 0）。這兩顆在 pactex 裡有音效名（證據審查者核對），所以量到的是停用的處理。
  - 游標停在一顆鈕上 3 秒後點擊：點擊音，−147.3 dB。進據點之前的兩次導覽點擊（排程是移過去再按）：點擊前 92.9 ms 有一個指針音，兩個一起擬合，殘差 −146.7 dB，增益都是 0.60420。
- **設定的聲音頁**（名稱來自腳本 `UserConfig::SetSound`）：
  - 滑到一個分類按鈕兩次：指針音，−147.4 dB、0.60420。
  - 點音效橫桿最左，把音效設成 0；之後兩次滑過：數位靜音（峰值 0）。點橫桿那一下本身沒有聲音：移過去和按下在同一格，指針音開始的那一格音效就變成 0，所以這一下分不出橫桿有沒有名稱，由下一趟補驗橫桿的滑過。
  - 滑到音效的重設鈕再點：指針音的前 3 個混音塊增益 0（錄音數位靜音），從點擊音開始前的那一塊（−23.2 ms）起是 0.60420，接著點擊音也是 0.60420；峰值殘差最大 4.95e−8（兩個聲音重疊的那一塊）。指針音的起點前後各錯一塊時殘差升到 7e−2，所以這個對齊不是任意的；兩個增益都當常數一起擬合，在這一下只有 −32.6 dB。也就是說，聲音的音量在混音時即時乘上音效橫桿，橫桿一變，正在播的聲音跟著變。
  - 恢復後再滑過兩次：−147.4 dB、0.60420。
- **其他元件種類**：第 6 頁的兩個檢查框、BGM 橫桿的軌道與把手（同一個元件，兩次）、音效與 BGM 的靜音框，滑過都是 −147.4 dB；點 BGM 的靜音框兩下，點擊音兩次都是 −147.3 dB。所以腳本設名稱的三種元件（按鈕、檢查框、橫捲軸）都會響。
- **修前**：三趟在開場的聲音之後全程數位靜音。
- **增益**：0.60420 正好是總控 0.8 × 音效 0.8 × 音效群組的內部音量（G2 量到的值），所以這兩個聲音是在音效群組裡播的。「和音效檔相同」精確的說法是「乘上增益之後到 float32 的捨入相同」（逐樣本最大差 2.85e−8 與 6.23e−8；證據審查 B-I2）。證據審查者另用匹配追蹤把三趟有音量種子的修後錄音整段分解：開場之後都只由這兩個參考（增益 0.604199）組成，沒有多出或重複的聲音；據點那一趟分解後剩下的峰值 6.2e−8，設定那一趟剩下的只在重設鈕那一段（增益在聲音中途改變，見上）。
- **開場的聲音**：每一趟的前 7 秒都有三段聲音，修前修後都有，不是這一組的聲音：0–8 秒內兩個參考的正規化互相關最大 0.16，0.3 以上的位置是 0 個；第一段的峰值只有兩種，在修前修後之間互換，是幾個重疊聲音的相位差。
- **進設定頁的那一次導覽點擊**：提交說明查證時記下，這一下在 0.9 門檻的掃描裡，預期時刻附近沒有點擊音的匹配，約 270 ms 後只有一個殘差 −53.2 dB 的匹配（那是指針音的匹配，不是點擊音；報告沒有討論）。文件定稿時對既有證據查過：0.3 門檻的掃描在那裡有點擊音（互相關 0.8998，略低於 0.9），它前 92.9 ms 有指針音，和其他導覽點擊的排法相同；約 0.3 秒後的那個指針音，時刻對得上點擊後設定頁出現、游標下的元件新進入的那幾行日誌。證據審查者的匹配追蹤也把這一段分解成這三個聲音，增益都是 0.6042。所以是三個聲音重疊，讓點擊音的互相關略低於門檻；−53.2 dB 推定是那個指針音和點擊音的尾巴重疊所致【推】。沒有另做三個聲音一起的最小平方擬合。
- 錄音只在提交前的建置上做過；提交後沒有重錄（程式碼相同；執行檔的關係見〈提交說明的讀法〉）。
