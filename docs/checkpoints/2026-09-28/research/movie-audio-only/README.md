# 片頭影片的純音訊預載止崩

2026-10-18。程式 `b31bc51`，基準 `ba493bd`，libsys4 固定 `247f544`。

分工：

- Codex（10/16）：修正、探針與提交前的實機。
- Claude（10/18）：最終證據審查、提交與提交後驗證。

提交前、後的預設與 GBK 各 102 個模式 PASS。**這一步只讓遊戲走得過片頭，片頭仍是黑畫面**：APEG 的影像還沒有解碼。

## 症狀

10/14 的實機：從第 2 天的自動存檔一路玩下去，第一次撤退之後的劇情觸發開場動畫，引擎在這時 SIGSEGV。先前依程式推論說「會是黑畫面配片頭歌」，這個推論不對。

全遊戲只有這一個影片檔（`Movie/Op.apeg`），所以這次當機會擋住主線。

## 原因（讀程式，探針重現）

`movie_load()` 接受「有音訊、沒有影像串流」的檔案。這時它不建影像解碼器，`video.queue` 留在 NULL，`video.finished` 設成 true。APEG 目前只會抽出內嵌的 Ogg Vorbis，所以一定走這條路。

載入最後的預讀 `preload_packets()` 卻無條件呼叫 `av_fifo_can_read(mc->video.queue)`，於是 NULL 解參考。`read_packet()`（含讀到結尾時寫入的空封包）、`free_decoder()` 與 `movie_draw()` 的純音訊分支，本來就會先檢查影像那一邊，只有預讀漏了。

## 修法

沒有影像佇列時，把它的封包數當 0。其餘都不變：

- `format_mutex` 的範圍。
- 必須有音訊串流的條件。
- 兩個佇列合計十個封包的預讀門檻。
- 一般影音的路徑：兩個佇列都存在時，算式和原本相同。

只有影像的檔仍然拒絕。

結束條件也不變：純音訊影片在音訊解到結尾時結束。這和既有對原版播放器的靜態研究一致（`0x449ff0`、`0x44a4c0`：影片的時鐘與結束都跟著音訊的位置）。這一步沒有為它另外讀原版。

## 與原版還不同、沒做與沒驗證

- **片頭沒有影像**。`movie_draw()` 純音訊分支畫的其實是透明像素（全 0 的 RGBA），畫面上看起來是黑的。
- 聲音沒有錄音或聽測。探針用的是 SDL 的 dummy 驅動。
- 片頭之後的一段劇情是按住 Control 快進的，2 秒一張的取樣沒有拍到其中幾個畫面。第 3 天據點的教學頁出現之前就停止了。
- 沒有正常讀檔清單讀得到的「片頭前」存檔。地圖快照 `103.asd` 是戰敗重試用的，不是一般存檔。片頭後的第 3 天自動存檔已寫出，但還沒有重新讀取，不能算驗過的檢查點。
- 既有、這次沒動的影片問題（讀程式；止崩之後純音訊影片才真的走得到）：
  - 音訊解碼出錯、`movie_play()` 失敗、沒有空的混音聲道或音訊裝置打不開時，`movie_is_end()` 永遠不會成立。
  - 同一支影片呼叫兩次 `movie_play()` 時，`movie_free()` 只停最後一個聲道，前一個聲道會讀到已釋放的記憶體。
  - 純音訊時，載入之後的補包都在音訊執行緒裡做。
  - 抽出音訊的暫存檔用 `/tmp` 底下可預測的檔名。
- 探針的界限：MA4 的 30 ms 不保證釋放前已經進入過音訊 callback；預讀的封包數不驗；MA6 只是讀回貼圖的對照。
- Windows、Linux 沒有建置。
