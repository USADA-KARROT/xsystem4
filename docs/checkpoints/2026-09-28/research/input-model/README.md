# 輸入模型：元件的點擊在放開時送

2026-10-12。程式 `aa541a7`（基底 `8a58add`）。

這一步讓 v14 的可點擊元件照原版在滑鼠左鍵**放開**時才收到自己的點擊，每次放開都先送全畫面點擊；核取方塊的切換、`GetActiveParts`、`system.Peek` 跟著改成原版的樣子。前一步（[dialogue-fade](../dialogue-fade/README.md)）只把「沒有點到可點擊元件」的全畫面點擊移到放開，這一步把剩下的補齊。**右鍵與中鍵沒有做**：第一版做了，審查查出兩處與原版不符，整塊拿掉，回到修改前「右鍵、中鍵對元件輸入沒有作用」。鍵盤的按鍵訊息、焦點訊息、雙擊也不在這一步。v13 以前的程式不變。

## 症狀

修改前。前三項是實機（引擎內建的點擊；未修改的 `cebc334`，它的輸入程式與 `8a58add` 相同）；第四項是程式的行為，引擎內建的點擊不能拖，沒有修改前的實機：

- **用滑鼠點 AUTO 按鈕進不了自動模式**（鍵盤 A 可以）：按下當下自動模式打開並前進一句，67 ms 後被解除，之後 15 秒沒有再前進。
- **按任何按鈕之後緊接的第一句不淡入**：清空後兩幀內整句出現。
- **從設定頁按「返回遊戲」，對白被推進一頁**；原版停在原來那一頁。
- **核取方塊按下後把游標拖開再放開，仍然切換**，按住時顯示的是新值的按下圖；原版拖開不切換，按住時是舊值的按下圖。

## 根因

四個症狀是同一個原因：**可點擊元件的點擊在按下時送，原版在放開時送。** 按鈕因此在鍵還按著的時候就動作，腳本的下一個等待把它當成「已經按著的鍵」：

- AUTO：自動模式打開後，下一句的等待看到左鍵還按著，照「點一下解除自動模式」的規則把它解除。
- 第一句不淡入：顯示迴圈第一圈看到有鍵按著，就把句子顯示完。
- 返回遊戲：設定頁在按下時關閉，回到對白的等待時左鍵還按著；放開時腳本自己的 `CASClick` 把它算成一次點擊而前進。這條路不經過全畫面點擊，所以前一步把全畫面點擊移到放開沒有動到它（「更早就有」是由那一次的 diff 靜態推定的，沒有在舊的建置上實測）。
- 核取方塊：切換綁在按下。

另外兩件事讓「只把點擊搬到放開」還不夠。`GetActiveParts` 回的是「最近被點的元件」，等待中恆為 0，腳本拿它判斷「這一下是不是按在可點擊元件上」時永遠是否。`system.Peek` 也跑一次輸入更新，放開若由它看到，按鈕的點擊比腳本自己的按鍵判斷早一圈分派，順序和原版相反（實作前的推演：AUTO 先打開，回呼才看到放開，又把它解除；所以這兩件要一起改）。

腳本（兩邊跑同一份）：

- 對白的按鍵等待除了自己的 `CASClick`（看過按下、現在放開才算），還要 `GetActiveParts` 回的不是可點擊的元件才前進。原版按在按鈕上放開的那一圈，active 就是那顆按鈕，所以**點按鈕不會順便讓對白前進**；按在空白處或訊息視窗上才前進。
- `WaitForClick` 每圈只跑一次元件更新，之後 `GetClickPartsNumber` 大於 0 就結束。
- 訂閱全畫面點擊的正式場景只有 `SceneContext`（左鍵、右鍵、滾輪）與 `SceneBattle`（右鍵），其餘在開發工具。經 `SceneContext` 掛左鍵的場景 11 個，都是「點任意處關閉或繼續」；掛右鍵的約 35 個；據點兩種都沒有掛。
- 沒有只靠 `system.Peek` 收滑鼠訊息的等待迴圈（實作者與兩位審查者各自搜過，結論相同）。
- 自動模式的等待是腳本算的：沒有語音的頁約（字數 + 5）× 100 ms × 速率，從等待開始起算；有語音的頁是語音播完後 150 ms。
- 沒有任何事件的元件收到 MouseClick 時，腳本的分派直接丟掉。

## 做法

只有左鍵。`src/parts/input.c`（主體）、`src/parts/checkbox.c`、`src/hll/system.c`、`src/hll/pe_v14_message.c`、`src/hll/pe_v14_activity.c`，以及 `parts.c` 與兩個標頭的宣告：

- **按下**只記住游標下的元件並把它設成焦點；可點擊的元件顯示按下圖。不送任何訊息。
- **放開**先送全畫面點擊（訊息 4、元件 0、鍵碼 1、放開時的位置），再送被按下的元件自己的點擊：它可點擊而且游標還在它上面時才送，點擊音效與 `GetClickNumber` 跟著它。游標離開了就不送，拖回來再放開會送。`GetClickNumber` 只在那一次更新有值。
- **進入輸入作用域時已經按著的鍵**，放開時也送全畫面點擊（BeginInput 取樣，EndInput 回到外層時再取樣）。前一步的「只有作用域內看到的按下才算」拿掉：按鈕的點擊移到放開之後，按鈕開出來的新場景開始時鍵已經放開，不會再收到同一次點擊的放開。
- **核取方塊在放開時切換**，在它的 MouseClick 之後、游標還在它上面時。先前的「點擊先記下來，下一次元件更新才套用」拿掉：輸入更新只在元件更新裡跑之後，延後的理由不存在了。
- **`GetActiveParts`** 改成作用域內最後一次按下時游標下的元件（沒有目標是 0）；放開與移動不變，BeginInput、EndInput 與元件釋放時清 0。
- **v14 的 `system.Peek`／`PeekAll` 不再跑輸入更新**。
- 拿掉「只有 pactex 的點擊許可而沒有事件的元件當成擋板」的權宜做法（見 [click-permission](../gui-visual/click-permission.md)）：這種元件照原版收到自己的 MouseClick，腳本丟掉；全畫面點擊每次放開都送，靠它關閉的對話框不受影響。
- v13 以前：釋放元件時不清按住的狀態、`system.Peek` 照舊跑輸入更新，兩處都以版本判斷保留原來的行為。

刻意和原版不同的地方：

1. **右鍵與中鍵沒有做。** 按下與放開對元件輸入都沒有作用，也不改焦點；和這一步之前相同。
2. **「游標還在元件上」**用「被按下的元件就是現在游標下最前面的目標」代替原版的 +0x1ac。按下之後有可點擊又透過游標的元件疊到它前面時不同：原版照送，這裡不送。
3. **停用的按鈕**不收自己的 MouseClick、不設 `GetClickNumber`、不播音效；全畫面點擊照送（先前連全畫面點擊也不送）。原版在輸入這一層不擋，所以這是移植版的權宜，沒有原版對照。
4. **`GetActiveParts` 的重設時機**：這裡 BeginInput、EndInput 之後立刻是 0，值在按下的那一次輸入更新就換。原版最外層的 EndInput 只重設還在管理器五個槽裡的元素，值在輸入更新之後才重算，而且每個作用域物件各有一份。
5. 沒有做的訊息：KeyTrigger／KeyDown／KeyPress／KeyUp（型別 15–18）、Focus／LostFocus（19／20）、雙擊；游標不在視窗內時原版不送滑鼠訊息，這裡沒有這個判斷。

## `noskip` 路線

這條路線不按住鍵、每 1.2 秒點一下，以牆上時間（405 秒）截止，行數等於截止時走到哪一頁。提交後的這一次是 **226 行，前一組的 221 行是它的前段**。提交前在同一份原始碼上的那一次是 224 行，多的是最後一頁的三句，每兩次點擊之間最多一頁。

第一版的那一次同樣是 224 行。審查的驗證者把它和另外五份紀錄（舊模型四次都是 221 行，新模型的另一次也是 221 行）依自動點擊的序號分頁：序列完全相同，沒有任何一次點擊走了兩頁；多出的一頁來自自動點擊的按下落在「等待開始」前後一個影格（按下在等待開始之後才算作用域內的按下）。提交前的那一次（224 行）和新模型 221 行的那一次差兩次點擊的目標，沒有逐頁對齊去證明是同一種影格邊界；新模型有沒有把這個邊界整體移了一個影格，樣本太少，沒有判定。**這條路線只能比前段是否相同，不能比行數與雜湊**（同 [dialogue-fade](../dialogue-fade/README.md)）。

## 與原版的對照（60 fps 錄影）

原版是 Wine 上的專用副本，暫時改用一個空的存檔資料夾（真實存檔沒有被開啟），滑鼠的移動、按下、放開分開送。移植版從外面送真實滑鼠。兩邊都是 60 fps 無損的螢幕錄影，量的是對白文字區的亮像素數、AUTO 按鈕與方框的平均色。只有左鍵。

| 操作 | 原版 | 移植版 |
| --- | --- | --- |
| 點 AUTO（一頁放了一陣子再點，按住 60 ms） | 放開後約 0.25 秒前進一頁，之後繼續自動前進 | 放開後 0.2 秒前進，之後繼續自動前進 |
| 按住 AUTO 1.5 秒 | 按住期間是按下圖、對白不動；放開才動作 | 沒有單獨做；拖回的那一段按住 1.75 秒，期間不動，放開才動作 |
| 按住 AUTO、拖到對白區放開 | 移開後回普通圖；放開後 4 秒文字不變，沒有進自動模式 | 移開後回普通圖；放開後文字不變，沒有 AUTO 的點擊 |
| 拖開、拖回、放開 | 拖回後按下圖又出現；放開 15 幀後前進 | 同樣的順序；放開 19 幀後前進 |
| 按鈕之後緊接的第一句 | 清空後約 1 秒內逐漸出現 | 約 50 幀逐漸出現 |
| 設定頁按「返回遊戲」 | 回到對白後 4.9 秒文字不變（另一段 4.8 秒） | 返回後 5 秒沒有新的對白 |
| 核取方塊：按住 | 舊值的按下圖（方框平均色 130/13/131） | 舊值的按下圖（128/13/128） |
| 核取方塊：拖開、在外面放開 | 不切換，樣本文字不變 | 不切換，樣本文字不變 |
| 核取方塊：按住再放開 | 切換 | 切換（那一段在錄影時間之外，畫面是另一條路線的截圖） |

- **真實滑鼠只實測了 AUTO 按鈕與一個核取方塊**（設定「信息」頁）。例行路線用的是引擎內建的點擊（按下 100 ms 後放開），不能拖；拖開與拖回在其他元件上只有探針。
- AUTO 按鈕的五個狀態（on-cursor、按下、拖開、拖回、放開）兩邊顏色的順序相同，但背景是不同的一頁，只比按鈕；核取方塊是同一個畫面。方框的平均色差在 5 以內，on-cursor 的圖移植版略暗，原因沒有查。
- 第一句的淡入只比到「逐漸出現」，逐字的間隔沒有另外量。
- 「自動模式中在對白區點一下：解除、不前進」移植版兩次都是；原版這一次的兩段點擊都落在文字出現途中或轉場中，判定不了（前一步量過）。
- **頁面剛顯示完就點 AUTO 沒有同一頁的對照**：原版量到的是一句短的（放開後 0.4 秒前進），移植版是另一頁的三行（5.2 秒後）。自動等待是腳本算的、兩邊跑同一份，長度隨那一頁而定，所以這不是已證實的差異；同一頁的對照還沒有做。
- 對白中按右鍵隱藏與恢復訊息視窗，兩邊型態相同（不是同一個畫面）。修改前的建置不送任何右鍵訊息就已經如此，所以它不靠這裡的元件輸入；「走的是腳本自己輪詢右鍵的那條路」是由腳本的函式名稱推定的，那一段沒有讀完。這是第一版時看的；右鍵拿掉之後沒有重做實機，依據是上面這一次、靜態，與探針（IM4 裡真腳本的 `CASClick` 以右鍵讀到一次點擊而佇列是空的）。

## 獨立審查

提交前，三個面向（原版語義、腳本面與探針、專找會壞掉的路徑），審查者與實作者不同，最後一位用不同的模型當第二意見；中等以上的八個發現各由一位驗證者試著反駁。審查與驗證都是靜態閱讀，沒有建置或執行。沒有 High。

- **成立的 Medium 兩件，都在第一版的右鍵與中鍵**：右鍵、中鍵的元件點擊也設了 `GetClickNumber`（原版只有左鍵的分支寫那個旗標；兩位審查者各自指出）；把「右或中鍵按下時取消拖放」誤讀成「讓左鍵的按下失效」，探針還把相反的結果固定下來。那一塊沒有原版對照，所以處置是整塊拿掉，照查到的原版行為改寫註解，探針 IM4 改成守住現況。
- **被駁回的兩件**：「剛顯示完就點 AUTO 要等五秒，根因未定」——自動等待是腳本算的，量到的是不同頁；「遊戲流程裡沒有場景訂閱全畫面點擊」——審查者看的是被截斷的清單，漏掉的正是 `SceneContext` 與 `SceneBattle`。
- **降為 Low 的三件**：`noskip` 多三句（不是一次點擊走兩步，見上）；公開文件還在描述舊行為（這一次一起更新）；「原版點 AUTO 是靠 `GetClickNumber` 讓等待結束而立刻翻頁」（原版的時序不像，移植版在同樣條件下行為相同；留下一個沒解開的疑點，見下一節）。
- **Low**：游標還在元件上的旗標與停用的按鈕（只更正註解，見「刻意不同」的 2、3）；`GetActiveParts` 的重設時機（第 4 點）；拖曳中按右鍵或中鍵的拖放事件（隨右鍵與中鍵一起拿掉）；探針的兩個守衛缺口（共用的點擊輔助函式不直接驗第一筆是全畫面點擊、v13 下釋放按住中的元件沒有案例），這兩個已補。
- 審查也更正了實作筆記的三處：上面 AUTO 與 `noskip` 的兩個說法，以及兩個「沒追到」的位置（游標在元件上的旗標由誰設、`GetClickNumber` 的來源是元素 +5）。這份文件用的是更正後的。

## 與原版的差異與限制

- 上面「刻意不同」的五點。
- **右鍵與中鍵**：這裡完全不送。原版放開時送全畫面點擊（約 35 個場景與戰鬥掛了右鍵）與焦點元素的點擊，按下會換焦點、取消拖放。要做對需要「焦點加鍵表」的模型與原版對照，之後另開一組；據點、戰鬥、各對話框的右鍵在原版做什麼，還沒有對照。
- **`GetClickNumber` 與對白等待的一個疑點沒有解開**：照程式靜態讀，點 AUTO 放開的那一圈 `GetClickNumber` 有值，`WaitForClick` 理應結束；移植版的實機紀錄裡等待沒有在那一圈結束。原版照反組譯也理應結束，錄影卻不像。驗證者傾向兩邊是同一個腳本層的原因，沒有證實。
- 進入作用域時已經按著的鍵放開送全畫面點擊、按住期間作用域結束或重開：只有探針，沒有實機專測。
- 沒有事件而 pactex 標成可點擊的元件現在收到自己的 MouseClick：沒有實機專測（靠全畫面點擊關閉的感情事件結果對話框沒有路線走到）。
- 掛了全畫面左鍵的 11 個場景，點在它們自己的按鈕上會先後觸發兩個處理；審查的推演是同一個關閉動作，沒有實機。
- 「左鍵按住時按右鍵，左鍵的點擊照送」與原版一致，是靜態推演。
- 點擊音效改在放開時播，沒有對照聲音。
- 沒有用真實滑鼠測的：元件的拖放（戰鬥的拖曳範圍）、捲軸；讀檔的確認框、標題畫面的各按鈕、劇情回顧頁內的操作沒有點。
  > 2026-10-12 更新：讀取確認框的「確定」與標題的「新遊戲」「讀取」現在有路線點過（`6267ed3`，見 [system-reset](../system-reset/README.md)），用的是引擎內建的點擊；真實滑鼠仍然沒有。
- 原版沒有讀的部分：取消拖放時呼叫的兩個函式的內部與它送的事件名稱、元件釋放清焦點的函式、放開後左鍵的槽清不清、哪些元件屬於哪個作用域物件；游標走訪只看了偽代碼。
- 只有 v14 改了。
