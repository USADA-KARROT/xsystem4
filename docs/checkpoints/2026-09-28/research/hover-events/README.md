# 滑過事件：v14 把滑鼠進入、移動、離開的訊息送給腳本

2026-10-20。程式 `bf58d4b`，基準 `b0e72d7`（前一組程式 `ecc7aff`），libsys4 固定 `247f544`。提交前、後的預設與 GBK 各 113 個模式 PASS。

UI 盤點的第二組（G3）。

## 症狀

使用者實玩回報：主按鈕游標移上去「都是平面的、沒動作」。原版的滑過有三層：

1. 引擎自己換成滑過的圖：移植版本來就有。
2. 引擎播滑過音：之後的音效那一組（G4）。
3. **腳本的滑過反應**：引擎送出滑鼠進入、移動、離開的訊息，腳本收到才改外觀。例如頁尾按鈕變黃底黑字、人材卡變黃並縱向彈一下、技能按鈕高亮目標、跑馬燈換回預設文字。

移植版在 v14 一個這類訊息都沒送：訊息佇列遇到這些訊息直接丟掉，所以第三層全都沒有。

## 原版依據

只做靜態分析，讀多娜多娜這一支執行檔；另外用英文版原版（沒有殼）在 Wine 上短暫確認了三個情境。英文版和中文版不是同一支執行檔，引擎這一層的行為推定相同。

| 項目 | 位址 | 內容 |
|---|---|---|
| 輸入更新 | `0x547c90` | 每次更新讀游標位置；位置改變時送整個畫面的 MouseMove；位置照原版規則保存（`+0x43`） |
| 走訪 | `0x5471d0` | 由前往後，顯示中、alpha 大於 0、命中的元件都算進入，到第一個不透過游標的元件為止（含它）；不問能不能點 |
| 進入 | `0x577b90` | 第一次送 MouseEnter（0），之後每次更新送 OnCursor（6），座標變了送 MouseMove（1）；設滑過或按下的狀態 |
| 離開 | `0x577cf0` | 送 MouseLeave（2），狀態回普通 |
| 左鍵槽 | `0x547460` | 放開的那次更新就清空 |
| 焦點 | `0x545c70`、`0x564cc0` | 焦點是元件自己的旗標，不在管理器的槽裡；BeginInput 只對焦點送 LostFocus（20） |
| 範圍邊界 | `0x5461a0`、`0x577af0` | 把五個槽都靜默重設（左鍵槽放開時已清空，實際只剩還按著的那個），不送訊息 |
| 沒有位置 | `0x5476b0` | 不走訪，只在按住期間讓按下的元件離開 |

v14 的訊息編號從 0 起算，和舊遊戲從 1 起算的列舉不同。

## 做法

- 照上面的流程送 MouseEnter、MouseMove、MouseLeave、OnCursor、整個畫面的 MouseMove，以及按下換焦點時的 Focus／LostFocus。
- 走訪可以同時進入多個元件；元件的「不透過游標」設定照原版生效。
- 游標不在視窗內時不走訪（推論：原版「有位置」的條件沒有追到底）。
- 訊息佇列改成可成長；原版是沒有上限的佇列，移植版原本只有 64 格，滿了就丟。
- **適用範圍**：只有 v14；v14 之前的遊戲本來就送這些訊息，邏輯不變（`parts_update_mouse` 只拿掉 v14 走不到的分支，探針守著）。

- **兩組 verify**：提交前、後的預設與 GBK 各 113 模式 PASS，見 [verify.tsv](verify.tsv)。
- **和原版並排**（原版是 Wine 上的截圖，只留在私人工作區）：

## 沒做與沒驗證

- **子畫面開著時，底下的按鈕和原版不同**：英文版原版在確認框開著時，底下的存檔鈕維持變暗的黃色，移植版是變暗的洋紅；框關掉時游標若還在原鈕上，移植版會多送一次 MouseEnter（之後接上滑過音就會多響一次）。原因是推論：原版可能只走目前範圍的元件（`0x546520`，它收哪些元件沒有追完），移植版走全部元件；也可能是原版的框背板不擋游標。要在英文版原版「框開著、游標移離存檔鈕」時拍一張才分得出來。排在 HANDOFF 的第 5 項；接上滑過音（第 3 項）之前要先處理或先記下。**2026-10-25 G3b 已處理（程式 `b77f3b8`）**：靜態反組譯讀到原版只走作用中的那一層（`0x53e690`），確認框另開一層，框下的鈕不進不出；移植版照做，探針 `layer-input`，見[子畫面輸入範圍](../layer-input/README.md)。實機上，英文版原版「框開著、游標在存檔鈕上」與中文版原版的讀取確認框只能排除修前的行為；中文版原版的系統選單有同形的一組（選單開著、游標從選單鈕移到別項，選單鈕仍是滑過的顏色），和「背板不擋游標」不符、和「只走作用中層」相符（前提是原版的系統選單也另開一層，推論）。英文版原版存檔框「框開著、游標移離存檔鈕」那一張還沒拍，待補拍確認。HE10 是同一層裡的遮擋，不是確認框的形狀。
- **2026-10-25 補記：G3 帶進來的回歸**：玩家技能演出時，其餘角色的粉紅剪影從 G3 起不見了（敵方回合的剪影還在）。G3 審查前的第一版還有剪影，審查後的修正（一次改了好幾處，包括被點的鈕不再在範圍邊界靜默重設、之後被擋住時會收到 MouseLeave）之後才沒有；上面的例行路線只比對白與點擊，沒有發現。G3b 只走作用中的那一層之後修回（截圖與像素掃描是量到的），見[子畫面輸入範圍](../layer-input/README.md)的〈戰鬥剪影〉；是哪一處改動、哪一則 MouseLeave 造成的，屬推論。
- **人材卡彈一下的動畫**：截圖太慢，抓不到中途的畫面。
- **戰鬥目標的高亮**：被角色的待機動畫蓋過，看不出來。
- **沒有實機走到的滑過反應**：捲軸的高亮、狀態頁的個性欄、研修的三個按鈕、鑑賞模式的縮圖、派遣鈕的黑字。Focus／LostFocus 遊戲本身沒有掛（只有開發工具），只在探針驗過。
- **游標移出視窗時**按鈕停在滑過的外觀，直到游標回來（照原版靜態讀法的推論，英文版沒有測這一項；修改前引擎換圖也是這樣）。
- **範圍外**：右鍵與中鍵的焦點與點擊、按鍵事件（按下時的下沉）、滾輪、拖放與滑動、捲軸以外的內部元件、滑過音與點擊音。
- **其他遊戲與平台**：v14 之前的遊戲（戰國蘭斯）與英文版沒有用這一組的建置跑；Windows、Linux 沒有建置。
