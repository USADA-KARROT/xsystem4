# 元件的 X／Y 旋轉

2026-10-19。程式 `d85df67`，基準 `1a9e4c4`，libsys4 固定 `247f544`。提交前、後的預設與 GBK 各 106 個模式 PASS。

## 症狀

`SetComponentRotateX`／`SetComponentRotateY` 沒有實作：值沒有存，畫的時候當成 0。14 分鐘的試玩裡共呼叫約 1650 次。

遊戲用在兩個地方：

- **戰鬥結算的標題卡片**：一張雙面卡，在 Y 軸上轉。背面是 activity 資料裡轉了 Y 180 度的子元件。修正前背面直接疊在正面上，標題字發灰、偏暗。
- **`AnimateText` 的一種進場動畫**：每個字在 X 軸上從 1000 度轉到 0。種類是隨機的。

## 原版依據

只做靜態分析，讀多娜多娜這一支執行檔。

| 項目 | 位址 | 內容 |
|---|---|---|
| 存值 | `0x58d7a0`、`0x58d840` | 角度原樣存 |
| 矩陣 | `0x535260` → `0x579bb0` → `0x4e6d80` → `0x5c3ae0` | S · Ry · Rx · Rz · T · 父元件；D3DX 旋轉，角度乘 −π/180 |
| 相機 | `0x579970` → `0x5b93f0`／`0x5b9130` | 水平視野 30°、元件在 20 的平面、近 10、遠 30 |
| 投影中心 | `0x5aac60` → `0x57aea0` | 以預設畫面大小的一半為中心（`0x4e6c30` 由 `SystemService.GetDefaultViewWidth/Height` 設） |
| 背面 | 元件四邊形的繪製路徑（`0x46a460` → 繪製器 +0xb8） | 不設剔除模式，裝置預設剔除背面；翻轉以頂點順序補償（`0x5ab250`） |
| 點擊 | `0x57aa60`；依種類 `0x57a6b0`、`0x59c460` | 三角形判定；文字與判定矩形用不帶中心位移的投影，CG 取繪製四角的外接矩形 |

## 做法

- **矩陣**：v14 的元件矩陣在 Z 之後乘上 Rx、Ry。
- **繪製**：有深度的元件經原版的相機畫出（頂點著色器做投影，貼圖做透視校正），背面不畫。沒有深度的元件，數值和修改前完全相同。
- **讀取**：`GetComponentRotateX`／`GetComponentRotateY` 回存的角度。
- **點擊**：有深度的元件用投影後的四角加原版的三角形判定。原版的投影方式依種類不同，這裡一律用繪製的投影，屬於**移植版的選擇**；遊戲裡沒有可點又在轉的元件。
- **兩個在移植版沒有對應東西的函式**，改成有註解的空函式：
  - `PartsEngine.StopSoundWithoutSystemSound`：原版停的是只有 FLAT 元件在用的 SE 2，移植版不播 FLAT 的聲音。
  - `CrayfishLogViewer.SetSaveFolderName`：只給除錯用的紀錄視窗存位置。
- **適用範圍**：所有 v14 遊戲都適用，不分編碼；v14 之前的遊戲不受影響。

## 驗證

- **探針 `parts-rotate-xy`**（10 案，說明見 [harness](../../harness/README.md)）：期望值由照原版步驟另寫的模型算出。修改前 9/10 失敗，見 [before.tsv](before.tsv)。
- **兩組 verify**：提交前、後的預設與 GBK 各 106 模式 PASS，見 [verify.tsv](verify.tsv)。
- **實機**：
  - 戰鬥結算的標題卡片靜止時和原版截圖一致（修改前發灰）。
  - 紀錄裡不再報這四個函式沒有實作，錯誤 0。
- **例行路線**：
  - normal150、haruuri、fightr、config、backlog、savedialog、garage、sysmenu 與片頭重播都跑完：exit 0、錯誤 0，紀錄裡沒有 unimplemented，對白和前一組（技能欄）逐字相同。
  - 點擊目標除了 fightr 都相同；fightr 差 2 處，是已知的兩群現象。
  - 片頭重播經過的兩次戰鬥結算，標題卡片都是亮的（修改前發灰）。片頭 50 張畫面仍和參考解碼器逐像素相同。
  - 見 [routes.tsv](routes.tsv)。

## 與原版還不同、沒做與沒驗證

- **轉動中的畫面沒有原版可比**：
  - 結算卡片轉動時，轉軸比卡片中心偏右約 90 px；背面朝向相機時，整張往右約 180 px，被畫面右緣裁掉。這和矩陣的語義一致（子元件的位移隨父元件鏡射），但原版轉動中的樣子沒有截圖。
  - `AnimateText` 翻轉中的字也沒有原版可比。
- **推論與移植版的選擇**（harness README 逐項列了）：
  - 背面不畫，是推論：頂點交給 GPU 的那一段沒有找到。
  - 負倍率算正面，是移植版的選擇；原版推論會被剔除。
  - 點擊的投影方式，是移植版的選擇。
- **沒有涵蓋**：
  - 有深度的 alpha 裁切元件。
  - 有深度的父元件底下的 FLAT。
  - 剛好轉 90° 時四角共線的點擊。
- **環境**：無視窗的 GL 探針在新機器上第一次跑時，可能還沒有 Metal pipeline 快取；要先用有視窗的引擎跑一次。已寫在 harness README 開頭。
- **其他平台**：Windows、Linux 沒有建置。

審查摘要見 [review.md](review.md)。
