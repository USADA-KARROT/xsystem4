# 回傳三槽的 option 與 MainEXFile 的清單函式（戰鬥影格、成就與各清單沒有載入）

2026-10-08。程式 `3b92ad1`。兩個修正必須一起啟用。

## 根因

1. **清單函式的輸出寫不回去。** `MainEXFile.GetNodeNameList`、`GetEXNameList`、`GetFormatNameList` 把結果寫進「包著陣列的頁」的第 0 槽，但腳本傳入的是陣列自己（先清空的空陣列），所以什麼都沒寫，新配的陣列洩漏。`EXHelper::GetNodes` 因此永遠回傳空陣列：戰鬥動作的影格、成就、CG／音樂／回想模式的清單都沒有載入。
2. **回傳三槽 option 的函式被截成兩槽。** 13 個函式回傳「介面 wrap 的 option」（物件、vtable 偏移、判別）。`function_return` 只留兩槽，呼叫端取三槽，每呼叫一次堆疊少一格。

只修第 1 項時，啟動流程第一次真的對 65 個成就執行載入迴圈（`AchievementCollection@LoadAchievementsFromEx`），每個成就呼叫一次回傳三槽 option 的 `AchievementCollection@Create`，堆疊很快下溢，遊戲停在啟動時的等待迴圈。實機重現過。

## 原版依據（靜態反組譯）

| 項目 | 位址 | 內容 |
| --- | --- | --- |
| 輸出參數 | `0x65a620` → `0x67aba0` | 引數就是陣列自己的 heap slot，頁必須是陣列，否則視為沒有 |
| GetNodeNameList、GetEXNameList | `0x488550`、`0x4886e0` | 接在陣列後面：Realloc(目前大小 + 個數) 再逐一設字串；路徑找不到回 false |
| GetFormatNameList | `0x4b0fd0` | 取代陣列的內容 |
| RETURN | `0x66cb20` | 不處理值堆疊；回傳值有幾槽就是幾槽 |
| 槽數 | `0x653420` | option 是內層槽數加 1 |

## 修正

- `src/hll/MainEXFile.c`：三個函式就地填入傳入的陣列（前兩個接在後面，第三個取代）；傳入的不是陣列時不動並回 false。
- `src/vm.c`：回傳值的槽數對 option 取「內層加 1」；存放回傳值的緩衝放寬。

## 驗證

- 新模式 `ex-name-list`（9 案）：以遊戲自己的 `EXHelper::GetNodes` 讀真的 EX 資料（修正前 0 個節點）；三個函式對空陣列、已有內容的陣列、不是陣列的引數；回傳值；不洩漏。
- 新模式 `option-return`（9 案）：遊戲自己的成就載入函式（只有清單修正時被 ASan 攔下，重現實機的故障）；13 個函式的槽數；守衛。
- 正式 before-check：修前 `27726d9` 上 `ex-name-list` 8/9、`option-return` 6/9 失敗；修後 `3b92ad1` 全過；兩種字元規則結果相同，還原後 src／include 乾淨（[before／after](before-after.txt)）。
- 預設與 GBK 各 71 模式 VERDICT PASS、sanitizer 0（[預設](verify-default.txt)、[GBK](verify-gbk.txt)）；既有 `SJIS ` 輸出與基準逐位元組相同；既有探針的斷言沒有變動。
- GUI（[摘要](gui-summary.json)）：八條路線都以提交後建置的執行檔執行，沒有斷言、堆疊下溢或 VM 錯誤；七條既有路線的對白與點擊目標和前一組相同。

## 實機上的改變

- 第一場戰鬥的教學原本開到一半就停住（只有底圖，戰鬥畫面沒有縮進框）；現在完整顯示標題、縮小的戰鬥畫面、說明與「關閉」鈕。
- 關閉教學後戰鬥畫面恢復全尺寸，背景鋪滿。點一個啟用中的技能會被選取執行。
- 之後停在技能的演出：所有點擊被全畫面的輸入層擋住，回合沒有推進。角色與敵人仍然看不到。

## 獨立審查

一輪兩個面向（程式與原版語義、探針），另有對抗驗證。沒有 High。成立的兩點都不是程式錯誤：影格只載入一部分（見下，已寫明）；一條宣稱測了「已釋放的 slot」的探針案例其實沒有測到，已改寫並補上反向檢查。

## 限制

- **影格只載入前 9 個子參數。** `FrameInfo@GetParams` 以 19 個兩槽元素的陣列字面值列出子參數，`X_A_INIT` 把它配成 19 槽（日誌的 `X_ASSIGN 38 past end of page`），後 10 個讀不到；CG 圖層與特效都在後 10 個裡，所以戰鬥的角色與敵人還畫不出來，技能演出也走不完。每個影格另外留下沒有歸還的參照。這是下一組。
- 呼叫不能進行時推的預設回傳值，末槽是 0，會被當成「有值」；兩槽與三槽都是既有行為。
- 腳本每呼叫一次清單的包裝函式會留下一個小的 heap slot（既有行為，不會被回收）。
- `GetNodeName`／`GetEXName` 也有同樣的寫法問題，腳本沒有呼叫點，沒有動。
- 成就、CG／音樂／回想模式的清單第一次有內容，這些畫面沒有實測。
