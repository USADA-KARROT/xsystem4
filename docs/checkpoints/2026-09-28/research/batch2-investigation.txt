========================= 調查 =========================
Math 組已完成原版 EXE 反組譯確認，並給出 selector 和新 C 函式。結論：CN 走錯的 122 次（Abs#1 33、Min#1-#5 24、Max#1-#5 30、Clamp#1 35）全部可以只靠 math_select_function 依宣告形狀分流修好。int Clamp 與現行 Math_Clamp 對全部邊界值等價，不必改。Math 其餘 29 個宣告沒有同名多載，也沒有 float/int 原型錯配，掃描報告沒有漏列。另外發現一個語義差異，但在 CN 裡實際影響為 0：原版 Asin/Acos 回傳弧度，xsystem4（和 Rufim）回傳角度，不過只有沒被呼叫的 AFL_Asin/AFL_Acos（FUNC 6435/6436）會用到。

EXE 定位：名稱字串 "Math" 在 0x7cee14，名稱比較鏈 0x49478f（call 0x41bfa0，相等時 mov eax,0x4c6520）指向 dispatcher 0x4c6520。0x4c654c 做 cmp eax,0x26（39 格，剛好對上 39 個宣告），0x4c6555 跳到跳表 0x4c6ca0。各格的分支形狀（int 版用 0x659f20 取參數、float 版用 0x65a070 取參數；參數個數用 +0x28 步距判斷）和 libraries.txt 的 index 0..38 逐格吻合。證據檔：scratchpad/overload2/math/table.txt、disp.txt、helpers1.txt、helpers2.txt。

原版語義（最高權威）：
(1) Clamp(value, low, high)，參數順序就是 value、low、high。
  - int 版（0x4c6bee）：value<low 回 low；否則 value<high 回 value；否則回 high。low>high 時不交換，value<low 回 low，其餘回 high。
  - float 版（0x4c6c28，comiss 加 jbe/ja）：low>value 回 low；否則 high>value 回 value；否則回 high。所以 value 是 NaN 時回 high，high 是 NaN 時回 NaN。
(2) int 多參數 Min/Max 是 min_element/max_element 取值（0x4c687c、0x4c7170、0x4c6a85、0x4c71d0）。
(3) float Min/Max 呼叫 MSVC UCRT 的 fminf 0x769351 和 fmaxf 0x7692f5：有一邊是 NaN 就回另一邊；相等時 fminf 偏好 -0.0、fmaxf 偏好 +0.0。巢狀方式：
  - 3 參數：f(f(x,y),z)
  - 4 參數：f(f(x,y),f(z,w))
(4) Abs(int)（0x4c664a）是 cdq/xor/sub，所以 Abs(INT_MIN)=INT_MIN。Abs(float)（0x4a69a0）是 andps 0x7fffffff，-0.0 變 +0.0。

String 組已用原版 EXE 定案，C 實作與 selector 也寫好並測過。

**原版 EXE 位置**：名稱比較鏈 0x49472f，庫名字串 0x7cedb4 "String"。dispatcher 在 0x684120，跳表 0x684984，共 36 格，index 對應 AIN 的 String[0..35]。參數槽間距 0x28；0x65a5f0 取 self，0x659f20 取 int，0x65a1c0 取 string。

1. **GetPart[21]（16 處）**：語義是「從 index 取到字尾」，不是取單一字元。
   - 證據：[21] 從 0x6845f5 進 0x688290，它直接 `push 0x7fffffff` 再呼叫 [22] 的 0x6882c0，也就是 GetPart(i, INT_MAX)。
   - [22] 0x6882c0 的規則：begin<0 夾成 0（0x6882fe cmovs）；length<=0 回空字串（0x688309 cmovg）；begin 超出字尾回空字串；end 超出就取到字尾。
   - index/length 以「字元」計，不是位元組。原版判斷雙位元組的條件是首位元組在 0x81..0xFE（0x68832f/0x688334，另有一段 0xE0..0xEF 的條件被前者涵蓋）。這是 GBK 規則，不處理 GB18030 的 4 位元組字元。
   - xsystem4 目前的 String_GetPart（String.c:328）：
     - 字元規則用 sjis_index（SJIS_2BYTE）。
     - begin<0 時回空字串，原版是夾成 0。
   - String_GetPartChar（:317）是死碼，語義也不對。

2. **Match[17]（6 處）**：語義是 std::regex_match 全字串匹配，語法 ECMAScript。
   - 0x6878f0 先用 "CHS" locale（0x811eac）把 self 和 regex 轉成 wstring（0x685e20），再建 std::wregex（0x68afc0）。0x68d120 在 +0x40 存入 1，就是 ECMAScript 旗標。
   - 接著呼叫 0x68bda0，即 _Regex_match1：`push 1; push 0` 後呼叫 _Match(nullptr, full=1)，代表全字串匹配。
   - Search[14] 則是 0x686ff0 → 0x68bc20（_Regex_search2），會逐一換起點重試，屬於 regex_search。
   - regex 例外被 catch，錯誤訊息字串在 0x7e5e44。
   - 6 個呼叫點（lambda fno 37567/37569/37571/37573/37575/37577，ain_code L1717751–L1718071）的 regex 常值，已在 AIN 解壓後用位元組確認都是單一反斜線：
     - `Button\d`（L1120231）
     - `RivalShop\d`（L1216486）
     - `Skill\d`（L1313252）
     - `Bonus\d`（L1319245）
     - `Player\d`（L1319254）
     - `Button.*`（L1340079）
   - 全部是 ASCII 字面值加 `\d` 或 `.*`。
   - meson.build 是 `project('system4','c')`、c_std=c11，專案純 C。Windows 的靜態建置沒有 <regex.h>，glibc 的 ERE 也不支援 `\d`。所以我寫了一個不依賴外部函式庫的 ECMAScript 子集 NFA（Pike 模擬、無 capture、線性時間），同時支援 Search 與 Match。

3. **PadLeft/PadRight**（0x6883d0/0x688640，0 處呼叫）：
   - 1 參數版就是 paddingChar=0x20。
   - paddingChar 的高位元組不為 0 時，以 2 位元組字元（高位元組在前）重複 pad/2 次；pad 是奇數時結果少 1 位元組。
   - self 不會被修改。

4. **Trim 系列**（0x688f10/0x6890c0/0x689230，0 參數版傳入預設清單 `20 0c 0a 0d 09 0b 81 40`）：
   - charList 是 1 或 2 位元組字元的集合（0x6862a0 建立），空集合代表不修剪。
   - 回傳新字串，**不修改 self**。
   - 現行 do_trim（String.c:394-420）和原版有三處不同：
     - 會把結果寫回 self（13 處呼叫多半是 `ref string` lambda，例如 FrameInfoBgLighting.CustomColor L1068621，會連帶改到來源）；
     - 會修剪所有 <=0x20 的位元組；
     - 不會修剪 0x81 0x40。

- QuickSort#0 與 #1 是 0x646a00：以索引追蹤 pivot 的 Hoare 分割，I 掃描 less(a[i],a[p])、J 掃描 less(a[p],a[j])，遞迴左半、迴圈處理右半。
- 值比較器：INT/BOOL/ENUM 用有號 <；FLOAT 用 <（NaN 為 false）；STRING 用無號 strcmp<0；其他型別恆為 false。謂詞比較器是 func(arr[a],arr[b])。
- 以上全部和 Remain 一樣，回傳 self handle（值型別 0x50）並 ref+1。

GetStructPageList 的語義是回傳新的 int 陣列，內容為各元素的 page handle（iwrap 元素取第 0 槽，也就是 struct slot），但要補一句：原版消費者 DeserializeStruct 必然是透過 handle 就地載入。xsystem4 的 system_DeserializeStruct 必須跟著改成就地寫入 heap[values[i]].page，不能再取代 values[0]；否則這項修法只修好 Save，Load 仍然遺失資料，而且會洩漏。
