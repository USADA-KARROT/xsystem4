# 元素是 option 的陣列（春銷永遠不成交、進地城當機）

2026-10-08。程式 `884b638`。

## 症狀

- 春銷的四位顧客配對完，三家店的人數都不變，沒有結算畫面，金額停在 10,000。按不按「快進」都一樣。
- 第 2 天在地城選擇的確認框按「前往」，載入地圖時記憶體存取錯誤（`MapView@LoadNodes`）。
- 道具查詢一律回傳空清單（沒有在畫面上看到，由腳本與探針得知）。

## 根因

v14 的腳本以 `CALLHLL Array <方法> <型別參數>` 操作泛型陣列，第三個運算元說明元素的型別：

| 型別參數 | 元素 | 槽數 | 堆疊由下而上 |
| --- | --- | --- | --- |
| 1 | 數值 | 1 | 值 |
| 2、0x10002 | 物件（0x10002 是 wrap） | 1 | slot |
| 0x10003 | 介面的 wrap | 2 | 物件、vtable 偏移 |
| 0x20002、0x30002 | option（物件或其 wrap） | 2 | 值、判別 |
| 0x30003 | option（介面的 wrap） | 3 | 物件、vtable 偏移、判別 |

低 16 位是內層的種類，bit16 是 wrap，bit17 是 option。option 元素比內層多一槽，判別放在最後：0 是有值，1 以上是 none。

`src/ffi.c` 與 `src/hll/Array.c` 只看低 16 位，把 0x20002、0x30002、0x30003 都當成一槽的元素。

- **春銷**：`ArrayExtensions::Select`（收集三家店展示的人材）以 `PushBack 0x30002` 推入兩槽的 option。少取一槽之後，被當成陣列的是人材物件，真正的結果陣列留在堆疊上被丟掉。結果永遠是空陣列，配對函式回傳 -1，顧客不進任何一家店；`SceneWorkResult@Run` 在成交數為 0 時直接返回，所以沒有結算，金額也不會入帳。整個過程沒有任何警告。
- **地城**：`MapView` 的建構子以 `Alloc 0x30002` 配置節點陣列。舊程式把它配成一槽一個元素的頁，腳本以兩槽一個元素去讀寫，一半的索引落在頁外；`X_OP_SET` 寫入頁外時，頁在同一條指令裡被重新配置，接著讀到已釋放的記憶體。

腳本裡用到這三個型別參數的呼叫點有 27 個：春銷配對、道具庫、偷人材、地城地圖的節點與邊、各種清單（物品、徽章、隊伍道具、調教道具、戰鬥道具、成就、存讀檔縮圖），以及商店的按鈕（唯一的 0x30003）。

## 原版依據（靜態反組譯）

| 項目 | 位址 | 內容 |
| --- | --- | --- |
| CALLHLL 取參數 | `0x66d470` → `0x66a5e0` → `0x66a700` → `0x659970` | 第三運算元決定泛型參數從堆疊取幾槽；bit17 走 option 的路徑，依序取判別、第二槽、主值 |
| 陣列的步幅 | `0x653420`（存在陣列物件 +0x48） | 陣列自己帶元素型別與步幅；Alloc、Realloc、Numof、Erase、Insert 只看陣列，不看型別參數 |
| Alloc | `0x647470` → `0x67f4a0` | 先清空再配置；option 元素的初值是 none：(-1, 1)，三槽是 (-1, -1, 1)（`0x656a44`） |
| PushBack／Add | `0x6476b0`、`0x646d70` | 等於 Insert(Numof)；推入 none 時值槽不寫，有值時陣列多持一份參照 |
| At、First、Last | `0x6499e0`（option 分支 `0x649b0d`） | 對 option 元素回傳的是元素的位置（陣列頁、索引 × 步幅），越界回 (-1, 0) |
| 帶述詞的函式 | `0x6455d0` | 述詞收到整個 option |
| `X_REF`、`X_A_SIZE`、`X_OP_SET` | `0x66b5a0`、`0x66e860`、`0x66fcb0` | 扁平的槽索引；邏輯元素數；依運算元寫兩槽或三槽 |

型別參數的編碼另以腳本的呼叫點對照宣告型別與呼叫前後的堆疊平衡驗證，七種實際出現的值沒有反例。

## 修正

只在 v14 且型別參數為正數時生效（-1 的 bit17 也是 1，所以要先判正數）。

- `include/vm.h`、`src/ffi.c`：新增 `hll_generic_slots()` 與 `hll_generic_is_option()`，取泛型參數的三處改用它；三槽時多存一槽。
- `src/hll/Array.c`：步幅取元素的槽數；Alloc 與 Realloc 建立 option 元素（清空、配 n × 步幅、填 none）；PushBack 與 Insert 寫入 option 元素（none 的值槽不採用傳入的值）；At、First、Last 對 option 元素回傳位置；Where 與 First 把整個 option 傳給述詞。

沒有動 `vm.c`、`page.c`、`heap.c` 與存讀檔。

位置參照是「借用」：原版建立位置值時對陣列加參照，由函式頁在釋放型別 87 的變數時歸還；xsystem4 既不釋放這種變數、也不在呼叫時對這種引數加參照，所以這裡不加，否則每查一次節點就洩漏一份。腳本唯一的使用者（`MapView@GetNode`）拿到位置後立刻讀出元素。

## 驗證

- 新模式 `option-array` 17 案（[harness 說明](../../harness/README.md)）：真 ffi 的 PushBack（有值與 none）；遊戲自己的 `Select`（真位元組碼）；Where 與真述詞；Add 0x20002；Alloc、Count、`X_OP_SET`、Erase、再 Alloc；地圖節點陣列的存取形狀（配 ASan）；位置參照；真的 `MapView@GetNode`；Alloc「先換頁再釋放」；Realloc；另有守衛：一槽與既有兩槽介面的呼叫逐步比對、v13 與型別參數 -1、三槽的頁面佈局、未實作函式的路徑。
- **修正前的執行期證據**（同一份探針配修正前的程式）：遊戲自己的 `Select` 回傳空陣列、沒有任何警告；節點陣列的存取形狀被 ASan 以 heap-use-after-free 中止（`X_OP_SET` 讀到同一條指令稍早釋放的頁）。
- 正式 before-check：修前 `57e98af` 17 案中 14 案失敗（另外三案是守衛）；修後 `884b638` 17 案全過；兩種字元規則結果相同，兩次都還原 HEAD 且 src／include 乾淨（[before／after](before-after.txt)）。
- 反向檢查：暫時改壞實作的 31 處，30 處有案例失敗；沒有被抓到的一處（ffi 的釋放迴圈不跨過多出的槽）在這個腳本上沒有可觀察的行為，因為 14 個這類參數都是所屬宣告的最後一個，探針另外檢查這個前提。
- 預設與 GBK 各 68 模式 VERDICT PASS、sanitizer 0（[預設](verify-default.txt)、[GBK](verify-gbk.txt)）；既有 `SJIS ` 輸出與基準逐位元組相同；既有探針的斷言沒有變動。
- 存讀檔：一般存檔序列化的 9 個 struct，依成員宣告都到不了有 option 陣列成員的 struct；四個存檔模式的輸出與基準相同。中斷恢復用的 VM 映像沒有以執行驗證。
- GUI（[摘要](gui-summary.json)）：春銷成交路線 182.375 秒：顧客第一次成交，88 秒起出現結算畫面（收入 6,900、顧客 1 人），第 2 天據點的金額是 16,900。進地城路線 282.262 秒：按「前往」後進入地城地圖，點節點移動，再點有敵人的節點進入第一場戰鬥（TURN 01，技能選單與行動順序條），停在等待指令；對白到 681 行。正常速度 150.361 秒、MSG 88（與前組逐位元組相同）；春銷目標 85.278 秒；系統選單 30.337 秒；庫房 35.295 秒。都以提交後建置的執行檔執行，沒有斷言、VM 錯誤或堆疊溢位；四條回歸路線的點擊目標與前一組相同。

## 獨立審查

一輪三個面向（原版語義、程式正確性、探針），審查者之外另有對抗驗證者重新查證每個 High／Medium。

- 沒有 High。原版語義逐條以反組譯確認一致。
- Medium 一個，成立並已修正：第一版讓位置參照對陣列加了參照，卻沒有任何地方歸還，進地城後每查一次節點就多一份，地圖關閉後節點陣列不會釋放。改成上面說的借用，並加了執行真 `MapView@GetNode` 的案例（修正前節點陣列的參照由 2 一路增加到 5，釋放地圖後陣列仍然存在）。
- Low 已處理：帶述詞的 First 遇到步幅不對的頁時不再回傳一槽；守衛案例由人工比對改成逐步比對內建的期望值；三槽案例的輸入改成分得出槽位對調；補上「刪到空之後再推入」與「先換頁再釋放」；文件列出哪些真位元組碼路徑沒有被探針執行。

## 與原版的差異與限制

- **實機只看過到第一場戰鬥的指令選擇。** 道具庫、各清單、商店、戰鬥的後續都是第一次拿到正確的資料，沒有實測。
- **春銷只成交一位**（四位裡）。原版在同樣條件下成交幾位沒有對照。`Array.Shuffle` 以傳入的 -1 當固定種子，對手每輪展示的人材固定，可能有關；原版對 -1 的語義還沒有查。
- **位置參照是借用**（見上）。腳本若把位置存進會自動釋放的變數，會多放一份；這個腳本沒有這種用法。完整照原版要同時改型別 87 的變數釋放與引數的參照，另案。
- **三槽元素的第二槽**（vtable 偏移）：VM 的 `X_OP_SET` 與頁的拆除對每一槽都計參照，Array 這邊只計第一槽。商店現有的路徑（Alloc、`X_OP_SET`、頁釋放）是成對的；兩邊混用會差一份。這一組只保證三槽的頁面佈局與初值，商店沒有驗收。
- **回傳三槽 option 的函式**仍被截成兩槽（13 個，多在戰鬥）。
- **陣列字面值**的多槽元素仍配得太小（日誌的 `X_ASSIGN ... past end of page`）。
- **`X_OP_SET` 對值物件的 option**（例如 option 的字串）共享同一個值，原版是複製一份；字串元素的 PushBack 也是共享。
- `MapView@GetNode` 找不到節點時，原版是錯誤，這裡會讀成「有值、值為 -1」。
- 沒有呼叫點、這一組沒有實作的：option 元素的 EmplaceBack、三參數的 Realloc（加了限次警告）、Fill、Copy、Sort、帶述詞的 Count 等。型別參數 0x30001（原版三槽）這裡當兩槽，腳本沒有用到。
- `X_OP_SET` 寫到頁外時讀取已釋放記憶體的問題本身沒有修；修正後已知的位元組碼不再走到，另案加固。
