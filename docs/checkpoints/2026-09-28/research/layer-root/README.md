# 圖層的 ID、根元件與 delegate 呼叫的游標（春銷之後的對話沒有對話框）

2026-10-09。程式 `6dfbab6`（controller 的 ID）與 `43e5574`（根元件、delegate 的游標）。

## 症狀

- 春銷結算之後的對話（夜晚的街道、第 2 天的開場）沒有對話框的底，對話文字是小字擠在畫面左上角，一句接一句疊上去；名字牌孤零零留在左下。遊戲開頭的對話是好的。與快進無關。
- 從系統選單開「配置」或「劇情回顧」，程式以 `PE_AddController: index != -1 not supported` 結束。

## 根因

三件事疊在一起。

1. **controller 的 ID 被當成堆疊位置**。`PE_AddController` 只接受 -1。原版的引數是「插在這個 ID 的 controller 之後」，而且 ID 在下面的 controller 被移除後仍然有效。
2. **圖層沒有根元件**。腳本以「元件最上層父親的號碼」當它所屬圖層的 ID（`AFL_Parts_GetLayerIDByParts`）。原版每個 controller 擁有一個根元件，號碼就是 controller 的 ID。這裡頂層元件沒有父親，`CMessageWindow@OnErasingLayer` 永遠比對不到，腳本不 Release 訊息視窗；但引擎已經把那一層的元件全部釋放。之後腳本看到視窗「還存在」就不重建，對舊號碼寫字，引擎靜默建出空白的替代元件（沒有圖、文字區在 (0, 0)、字級 16）。
3. **delegate 呼叫中有項目把自己移掉時，下一項被跳過**。`CallErasingLayerEvent` 逐一通知訊息視窗；事件用的那個視窗處理完把自己從清單移掉，主要的那個就沒被通知到。

## 原版依據（靜態反組譯）

| 項目 | 位址 | 內容 |
| --- | --- | --- |
| AddController 等 | `0x58a6b0`、`0x53d480`、`0x53d3a0`、`0x53d500`、`0x53d870`、`0x53d800`、`0x53fe30`、`0x53d740` | 引數是 ID；找不到時插在作用中者之後；移除、設定作用中、查 ID 與位置、移動 |

| 掛父 | `0x53afb0`、`0x58f060` → `0x53ab60`、`0x534f00` | 掛到別層的元件底下就屬於那一層；`SetParent(0)` 掛回目前所在樹的根；根不能被掛到別的元件底下 |

| 新增 | `0x652210`；`DG_PLUSA` `0x652710` | 先移除相同的項目（只比物件與函式）再接尾端；上限不加 |
| 清空、指定 | `0x652620`、`0x6522a0` | 游標與上限歸零；指定先清空 |
| 物件解構 | `0x652970` | 它的項目經同一個移除函式移掉 |

## 修正

- `6dfbab6`：v14 的 controller 有獨立於位置的 ID；Add、Remove、SetActive、GetActive、GetControllerID、GetControllerIndex、MoveController 照原版；繪製順序依位置。v14 以外不變。
- `43e5574`：
  - 每個 controller 有根元件（不畫；號碼是 controller 的 ID，從 1000000000 起）；頂層元件的父親是所屬圖層的根；掛到別層的元件底下時子樹跟著換層；`SetParent(0)` 沿父鏈找根；根不能掛父；根隨 controller 釋放。
  - delegate 一次呼叫的游標與上限放在 delegate 頁自己身上，移除、新增、清空、指定、物件解構都照上表調整。v13 以前不變。
  - 存檔：v14 一律在檔尾寫 controller 的 ID，讀檔先讀它再載入元件。沒有這一段的舊檔仍讀得進來並印一次警告，但那份存檔裡腳本手上的圖層 ID 已經對不上。
  - 對「所屬圖層已釋放的 activity 元件」做操作時印限次的警告。

- 反向檢查：每個關鍵處暫時改壞都有案例失敗（最後一輪 23 處裡 1 處是等價改法）。

## 獨立審查

兩輪，各兩個面向，高與中等級的發現另有對抗驗證。

- 第一輪找到兩個 High，都已修掉：
  - 修正的第一版在圖層消除時順手把「元件全數不在」的 activity 從表中移除，改變了腳本找空名稱的結果，**春銷結算畫面的立繪因此錯位**（實機回歸）。已拿掉那個清理。
  - delegate 的游標第一版用一張以頁指標為鍵的全域表，讀檔、重新啟動、頁被搬移後會留下懸空的登記。已照原版改成放在 delegate 自己身上。
- 第一輪的 Medium（上限沒有實作、物件解構的路徑沒有調整游標、存檔分不出新舊、說明文件）也都處理了。
- 第二輪只審修正的增量：沒有 High 與 Medium，上一輪的問題確認修掉。留下的 Low 見下。

## 與原版的差異與限制

- **對話畫面還差**：右下的 NEXT 圖示（`SetKeyWaitCGName` 是空殼）；對話文字的顏色（原版淡黃，這裡白）與字型；地點標題在換場景後殘留；事件場景的名字牌沒有牌底。
- **劇情回顧沒有字**：回顧的文字是以構築命令 23（把文字以 alpha 混合畫上去）畫在全透明的底上；原版的 23 會把表面的 alpha 提高到文字的 alpha（`0x494420`），這裡當成一般畫字，字畫了但看不見。靜態讀出，還沒有以修正驗證。
- **設定畫面**：滑桿沒有把手、核取方塊與按鈕文字沒有（函式庫空殼）、背景沒有變暗模糊。
- **讀檔沒有實機驗證**：存檔格式與「讀檔後進行中的 delegate 呼叫結束」只有探針與讀程式的依據。
- 第二輪審查留下、還沒處理的 Low：
  - 重複新增同一個處理函式時，舊的閉包環境在頁還要繼續用的中途被釋放；若釋放連鎖回頭改到同一個 delegate，可能用到過期的頁指標（條件很窄，沒有實測，腳本裡沒有找到這種寫法）。
  - 重複新增會以新的閉包環境取代舊的（與原版一致，但行為和修改前不同：`SceneWorkerOperation@ExecuteEvent`）。
  - 探針沒有涵蓋：呼叫中重複新增尚未呼叫的既有項目、v13 下經指令的呼叫、Delegate 函式庫、讀檔往返、跨層掛父後存讀檔。
  - 讀檔會把存檔裡的 activity 元件誤報成「已釋放」並用掉警告的次數。
- system overlay 沒有根（原版有）；根元件的狀態不存檔；ID 從 1000000000 起（原版 1000010000）。
- activity 表上限 128，滿了沒有警告；長時間遊玩會不會滿沒有驗證。
- 戰鬥結束到結果畫面之間有一幀是黑畫面加一個黃點（修改前那一幀閃現地圖）；原因沒查。
