# 陣列字面值的多槽元素（戰鬥看不到角色、技能演出走不完）

2026-10-08。程式 `e3417c2`。

## 根因

`X_A_INIT` 把「立即數 + 1」當成泛型元素的槽數。元素是兩槽或三槽（介面的 wrap、option）的陣列字面值因此配得太小，後面的 `X_ASSIGN` 被截短（日誌的 `X_ASSIGN n past end of page`）。`FrameInfo@GetParams` 就是這樣列出一個影格的 19 個子參數：只有前 9 個被載入，CG 圖層與特效在後 10 個裡，所以戰鬥的角色與敵人畫不出來，技能的演出也走不完，每個影格還留下沒有歸還的參照。

## 原版依據（靜態反組譯）

| 項目 | 位址 | 內容 |
| --- | --- | --- |
| X_A_INIT | `0x66e420` | 元素的槽數取自宣告的元素型別（`0x679432` → `0x653420`，存在頁 +0x48），與大小、立即數無關 |
| 頁的大小 | `0x67fee0` | 元素數 × 槽數 × 4 |
| 立即數 | `0x66e697` → `0x67f4a0` | 只決定元素要不要預設初始化；option 的預設是 none（`0x656a44`） |

## 修正

- 陣列頁記住每個元素的槽數（新欄位）。具大小的泛型頁由宣告取得；多槽元素的伴隨槽（vtable 偏移、判別）在頁的拆除、複製與指派時不當成參照。
- Array 函式庫在設定步幅的地方同步記下佈局。
- 中斷恢復用的映像保存這個佈局（rsave 放在 rank 欄位的高半部，JSON 多一個鍵）；舊映像照舊規則讀。一般存檔的內容不變。
- 立即數不是 0 時，option 元素預設為 none。
- 空頁仍用「立即數 + 1」，由 Array 函式庫在存入第一個多槽元素時給佈局。

腳本裡具大小的多槽 `X_A_INIT` 有 35 處：32 處是字面值，另外 3 處是預設初始化（`MatchingInfo@2`、`AdvTransition@2` 的兩個成員）。

既有探針 `working-cards` 的 WC6 原本釘著舊行為（一個介面元素配成一槽；預設初始化的 option 是 (−1, −1)），兩段都依原版改了。

## 驗證

- 新模式 `array-literal` 12 案（[harness 說明](../../harness/README.md)）：遊戲自己的 `FrameInfo@GetParams`；從真的 EX 資料載入一個影格（19 個子參數都載入、釋放後的殘留有數量斷言）；使用者元件的字面值；三槽的字面值；`AdvTransition@2` 與 `MatchingInfo@2`；Array 函式庫給佈局與保留佈局；映像的兩種格式來回；守衛（一槽字面值、v13、struct 索引 2 與 3 不被誤判、一槽泛型元素）。
- 正式 before-check：修前 `c27fc93` 12 案中 9 案失敗；修後 `e3417c2` 全過；兩種字元規則結果相同，還原後 src／include 乾淨（[before／after](before-after.txt)）。
- 反向檢查：兩輪共 22 處，全部有案例失敗。
- 預設與 GBK 各 72 模式 VERDICT PASS、sanitizer 0（[預設](verify-default.txt)、[GBK](verify-gbk.txt)）；既有 `SJIS ` 輸出與基準逐位元組相同。
- GUI（[摘要](gui-summary.json)）：八條路線都以提交後建置的執行檔執行，沒有斷言、堆疊下溢或 VM 錯誤；`past end of page` 警告在每一條路線都是 0（修正前 22 到 520 筆）；七條既有路線的對白與點擊目標和前一組相同；峰值記憶體沒有增加。

## 實機上的改變

- 戰鬥教學的框裡看得到敵人。
- 選取技能後演出會播完：我方四人、技能名稱與使用者、特效、敵人受擊，並顯示傷害合計；之後回到技能選單，輪到下一位行動。

## 獨立審查

一輪兩個面向，另有對抗驗證。沒有 High；原版的流程、槽數表、新欄位在各處的設定與保留、參照計數都確認一致。成立的一點是文件說得太滿：原本寫「具大小的多槽 `X_A_INIT` 全是字面值」，實際有上面那 3 處；已更正，補上真位元組碼的案例，並照原版做了 option 的預設值。

## 限制

- 預設初始化的介面元素這裡是 (−1, −1)，原版是 (−1, 0)；目前受影響的兩個陣列在建構後立刻被逐一寫入。
- Array 函式庫有幾個函式（Alloc 的非 option 分支縮小時、Realloc、ShallowCopy、Duplicate、Remain）還不照新的佈局計參照；腳本不以多槽元素呼叫它們。
- 每個 CG 圖層物件多留一個參照，是既有的雙重參照（腳本的 A_REF 加上 Array.Insert），這次因為圖層第一次載入才看得到。
- **戰鬥還打不完**：演出結束後，演出時加的一層畫面沒有被移除，蓋住技能按鈕（函式呼叫時對 delegate 引數多留一個參照，環境頁不釋放）；我方在畫面最上緣、敵人在最底部，鏡頭的位置不對。兩者都是下一步。
