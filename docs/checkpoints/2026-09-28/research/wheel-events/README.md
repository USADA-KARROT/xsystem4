## 修正目的與版本界線

這組修改補上 v14 的雙向滾輪計數、Whole／元件事件，以及元件自身 wheel flag 的載入與保存。滾輪事件要送到符合資格的元件，不能以 hover 或 click 的目標代替，也不能把兩方向計數先相減後丟掉資訊。

新邏輯使用既有 v14 分流；v13 以下保留原本的最後整數方向與輸入流程。`Parts_SetWheelable` 僅在已確認的 `void(int, bool)` 宣告形狀下安裝，未知形狀保留舊綁定。pactex 僅補已驗證的中文版鍵，不猜測或新增 SJIS 鍵名；這不等於已驗收所有 SJIS 遊戲。

### 必須保留的更正：owner 不等於視覺父層

第一版把 `0x5350c0` 使用的內部 owner 直接映射成移植版 `parts->parent`。這是已確認的高風險語義錯誤，初審沒有辨識出來；先前探針也沿用同一錯誤前提，因此原本的 PASS 不能證明這項映射正確。

補查建立與重掛鏈後，確認原版 owner 位於 `+0x7c`，一般具名 parts 的建立路徑會將它設為空；複合元件的內部建立才傳入 owner。`SetParent` 在 `0x53b098` 改的是另一個欄位 `+0x13c`。兩者不能互換。重要建立鏈為 `0x578cb0 → 0x4f3c20 → 0x533da0`，複合內部建立另見 `0x4f2e20`。

更正版不沿視覺父層推導 wheel 資格，也沒有補上向父層多送事件的通用冒泡。原版基本元件的父通知槽 `0x4d9c90` 不支持「父腳本必然再收到 wheel」這項假設。

移植版目前以一個 parts 表示一個輸入元件，尚未重建原版複合元件的內部 owner 與完整內部焦點模型。更正的意義是移除錯誤映射，並非宣稱原版沒有 owner 繼承，或所有複合元件已完全等價。

## 移植策略與維護理由

**首次 GetCount 快照是移植策略。** SDL 可能在腳本輸入週期中途抽取事件，因此首次 GetCount（包括第一次讀到零）固定本輪值，直到 ClearCount；之後收到的事件留待下一輪。Clear 結束快照而不吞掉 pending 或小數餘數。這與原版純讀 getter 的內部行為不同，必須以呼叫順序與消費結果驗證適配。

AIN 靜態呼叫鏈指出文字等待 callback 可以先輪詢 wheel，再做 View 更新；View 尾端才依序 Clear、Peek、UpdateMessage。因此不能假設所有消費者都先更新 Parts、再讀計數。小數 SDL delta、自然捲動方向轉換及極大計數飽和也是移植端決策，不能寫成原版觀察。

元件事件使用獨立的 wheel 候選走訪；Whole 與 local 都保留兩個計數。腳本有只看方向的消費者，也有按計數大小移動的消費者，所以 producer 不統一改成「每格一筆」，亦不把兩方向合併成一個 signed 值。AIN 清點得到 3 個 HLL 宣告、6 個直接 HLL 呼叫、59 個名稱相符的直接函式呼叫、23 個 Whole 註冊／解除，以及 86 個已辨識的虛擬槽呼叫形狀。這些集合重疊，不能加總，也不代表所有動態呼叫均已解析。

### XPE 12 的可選 PWHE 區段

這是移植版保存格式的選擇，不是原版存檔格式。既有 XPE 12 parts record 不變；各區段存在時依序為 **PCDF → PWHE → PCID**，PCID 保持在尾端。PWHE 僅保存自身 flag 為 true 的 ID，不保存型別、焦點或 owner 所導出的有效資格；沒有任何 true flag 時不寫該區段。

一般 parts 沿用既有保存與隱藏篩選，controller root 的自身 flag 另行保留。讀入時驗證區段長度，只更新已存在的 parts；可從既有 controller stack 重建 root，但區段內的任意 ID 不得建立新 parts。沒有 PWHE 的舊資料維持自身 flag 為 false。

更正版已另行重跑真正的 `d9d13e8` 舊 reader，完成 4 類合成案例、16 個 probe process，全部 rc 0 且有 PASS 標記；沒有沿用第一版結果。案例涵蓋多 controller 模式中的單一與多個 controller、單 controller 模式，以及只有 root 的保存內容。每案皆核對 controller／PCDF 斷言、PWHE 區段位置，以及移除 PWHE 後與未設 flag 的保存內容逐位元組相同；舊 reader 分別讀入含 PWHE 與移除 PWHE 的內容後，重新保存的結果也逐位元組相同。

新 reader 的 7 個已修改 engine 原始檔雜湊均與 `owner-correction-v2` 相符，執行紀錄亦綁定各自的 binary 雜湊。這組跨 reader 測試使用預設字元設定與獨立的合成探針，不是 GBK 跨 reader 測試。舊 reader 不會恢復新 flag，測試目的是既有內容與區段定位相容，不是讓舊版取得新功能，也不是原版遊戲存檔相容驗證。

## 選項涵蓋範圍

標準函式庫 `CMenuView` 的輪詢流程已做靜態盤點，但尚未找到本作正常路線的可重播入口；完整名稱、直接呼叫及已知動態入口的查核也不足以證明它絕對不可達。因此明列「正常路線可達性及實機結果未驗證」，不宣稱所有 ADV 分歧通過。
