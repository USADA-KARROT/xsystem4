## 缺陷（修前，parent `42aa793`）

- **兩個比率被丟掉**【讀】【量】。`PE_v14_UpdateComponent` 第一行就把最後兩個參數（亮度、不透明度）丟掉，可重入的那條路也一樣。設定第 3 頁把兩條橫桿拉低，值會改、會存，但預覽與對白的訊息框都不變：父版本的建置在實機上拉低兩條之後，預覽區 0 個像素不同，回到對白，訊息框只差鍵待標記動畫的 501 個像素（〈實機〉）。
- **預覽沒有樣本文字**【讀】【量】。訊息框的 pactex 載入（`pactex_apply_message_window`）讀ＣＧ名、文本エリア、文本位置、字型、間隔、字速度與鍵待標記，沒有讀「文本」，所以預覽是空框。
- **字型快取**【讀】。`text_style_font_size()` 只要樣式裡有快取的字型尺寸就直接回傳，不比對 face 與 size；`PE_SetFont`、`PE_SetPartsFontType`、`PE_SetPartsFontSize`、`PE_SetMessageWindowTextFont` 改字型或字級之後都不清它，所以排過一次字的樣式改字之後仍用第一次查到的尺寸（探針 FN1–FN4：改成 40 號之後字寬仍是 20 號的）。FNL 字型的尺寸查詢回「最接近的一級」，所以不能只比快取的 size。遊戲裡會不會在排字之後改字型，沒有證實（〈原版依據〉的腳本端）。

**吃比率的地方之一：訊息框的背景**

- 視窗物件的 vtable `0x80f164` 偏移 `+0x14`（從 0 起算的第 5 格）是 `0x4f25e0`，它呼叫 `0x4f2660`（上下文）。`0x4f2660` 在上下文的可見旗標 `+0xa0` 為真時，只改視窗的私有背景（視窗 `+0xa0`，建構在 `0x4f1d30`）：
  - **背景乘色**：每個分量由基底色往目標色內插，係數是 1 減亮度；反組譯讀到的式子是 trunc((目標 − 基底) × (1 − 亮度) + 基底)，單精度、乘和加各一次捨入，`cvttss2si` 截斷，`0x550ce0` 夾在 0..255。基底在視窗是作用中（`+0xbc`）時是白，否則是 pactex 的「非アクティブ時の乗算カラー」；目標是建構時（`0x4f1e06`..`0x4f1e31`）由 `0x4f1c90` 讀 EX「Ｅ＿信息窗口.明るさ乗算色」的三項，找不到時是 0。
  - **背景 alpha**：不透明度乘 255.0 後截斷（`0x81333c` 是 255.0），夾在 0..255（`0x4f2755`..`0x4f2768` 的條件搬移，不經 `0x550ce0`），寫到背景的 `+0xb0`（`0x4f2773`）。
  - 文字（`+0xa4`）與鍵待標記（`+0xa8`）的顏色與 alpha 不動。`0x4f2660` 最後呼叫的 `0x4f2790`（`0x4f277b`）只擺背景、文字、標記三者的位置。`0x4f2790` 是 `0x4f2660` 的最後一步，不是整個更新的最後一步：`0x4f25e0` 之後還呼叫 `0x4f32c0`、`0x4f38e0`、`0x50d400`。
- 背景再和視窗本身的 alpha 與乘色合成：`0x4f32c0` → `0x535260` → `0x579bb0`，整數相乘、乘 1/255（常數 `0x813054`）、截斷。視窗的子 parts 和視窗的上下文合成，那裡沒有比率。
- `cvttss2si` 遇到 NaN 或超出 int 範圍時得 `0x80000000`，夾值後是 0。

**吃比率的地方之二：MessageWindowEffectLink**

### 腳本端【AIN】

- **兩個值的來源**：`g_AFConfig`（`CASConfigData`）的**成員 14 是亮度**（`ConfigMessageWindowMulColorRate`），**成員 15 是不透明度**（`ConfigMessageWindowAlphaRate`）。`parts::detail::Update` 呼叫 `UpdateComponent` 時，第 4 個參數是成員 14、第 5 個是成員 15。10/19 的盤點紀錄把這兩個欄位的順序寫反了（寫成「欄位 15／14」對第 4、5 個參數），以這裡為準。
- 讀寫這兩格的只有四個函式（兩個 Get、兩個 Set）；Set 先夾到 0..1 再存；初值、Reset 與 EX 沒有對應鍵時都是 1.0。設定頁橫桿的兩個 `AFL_Config_Set…` 在 AIN 裡沒有直接呼叫，也沒有以函式號推入的地方，推論是設定頁的資料綁定以名字呼叫【推】。
- **UpdateMatrix**：`parts::detail::UpdateMatrix` 同樣把三個值給它；唯一的呼叫者 `AFL_Parts_Update` 有 8 個呼叫點，所在的函式屬於測試選單、模型檢視器（兩處；另一處是只出現在模型檢視器成員裡的 `parts::detail::CPartsTimeLine`）、舞台編輯器與聲音濾波器編輯器（三處）。看名字都是測試與編輯工具【推】。
- **EffectLink**：`SetComponentMessageWindowEffectLink` 只出現在一個沒有呼叫者的包裝函式與各 parts 類別的 `MessageWindowEffectLink` 屬性函式；以方法呼叫的呼叫者找不到，經介面的呼叫靜態數不到。
- **非作用中的乘色**：`SetMessageWindowInactiveMultipleColor` 唯一的腳本入口是訊息框 parts 的屬性函式，找得到的使用者只有 activity 編輯器【推：經介面的使用數不到】。
- **改字型的地方**：`Parts_SetFont` 兩個呼叫點，一個是沒有呼叫者的包裝函式，一個經介面（文字 parts 的 `Font` 屬性）；`Parts_SetPartsFontType`、`Parts_SetPartsFontSize` 各只有一個沒有呼叫者的包裝函式；`SetMessageWindowTextFont` 經訊息框 parts 的 `TextFont` 屬性（經介面）。所以遊戲在排字之後改不改字型，靜態數不到；沒有加計數去量。
- `SetMessageWindowActive` 的呼叫者是 ADV 的 `message::detail::CMessageWindow@UpdateActiveState`（〈範圍外的發現〉）。

### 遊戲資料的量測【量】

- pactex 裡型別是「信息窗口」的元件只有 5 個（ADV 的四個，加設定第 3 頁的預覽），五個都是「アクティブ」0、「非アクティブ時の乗算カラー」白。所以這個遊戲的基底色一定是白。
- 這一版的 EX：`Ｅ＿信息窗口` 只有 `Ｚ値`，沒有「明るさ乗算色」，所以目標色是黑。英文版的 EX 沒有查。
- 所以在這個遊戲裡：背景乘色的位元組隨亮度從 255（亮度 1）降到 0（亮度 0），背景 alpha 的位元組是不透明度乘 255 截斷。0.30083567（實機把把手拖到的值）時兩個位元組都是 76。
- pactex 的「信息窗口視覚效果連動」2706 處、「信息窗口表示連動」2706 處，全部是 0。
- 預覽（第 3 頁）的 pactex：有「文本」（三行，以換行分隔）、字速度 23、信息番號 0、已讀判定 0、フォントサイズ 25、[拡大縮小] 0.66。ADV 的四個訊息框的 pactex 也都有「文本」。
- 存出的設定裡兩個值的位置：只拉亮度的那一趟只有亮度那一格變，兩條都拉的兩趟逐位元組相同、兩格都是 0.30083567。
- 沒有綁定的建置（G8b 的提交後，`42aa793` 的程式）跑的九條路線、片頭第二、三趟，以及這一組在父版本建置上走過設定第 3 頁的實機那一趟，引擎日誌都沒有那三個 HLL 的 `UNIMPL HLL`；移植版對沒有綁定的 HLL 每個函式前 5 次都會印。這一組的建置已經綁定，不會再印，所以這一組的日誌證明不了它們沒被呼叫。

## 做法

### 主線的決定

1. **EffectLink 與 UpdateMatrix 的綁定**：接受。照原版語義補齊這個遊戲沒有用到的 HLL，是移植策略；綁了以後這個遊戲的行為不變（沒有呼叫者、pactex 的連動旗標全為 0），又不再印警告、回預設值。只在 v14、宣告形狀相符時綁。
2. **字型快取只對 v14**：接受。交接規則是「v14 之前不變」，上游 `5fb3c49` 不分版本；FN7 釘住 v13 照舊沿用第一次查到的尺寸。
3. **註解與探針檔頭裡的算式**：沿用捲軸把手、限速兩個探針的前例保留短式子，但用文字說明它描述的是什麼（「反組譯讀到的背景乘色」），不寫成轉型的程式片段；超過三行的改成文字。
4. **提交說明查證時另做的兩份註解修改**都套用，讓公開註解、探針檔頭與提交說明一致（`0x4f2790` 擺三者的位置、get-or-create 的完整鏈、原版不夾值、Not covered 的 flat）。
5. **補 WR15、WR16**：審查找到的兩個缺口（show 為假時的比率、亮度不動加算色）能直接寫子案，就補案，不只列進 Not covered。
6. **原版不同值的補拍**：這一輪不拍（使用者不在、螢幕鎖著）。文件與提交說明寫「沒有原版畫面，期望值來自反組譯」，HANDOFF 的待辦列補拍的步驟。
7. **範圍外的發現**（`SetMessageWindowActive(false)` 會把視窗藏起來、載入時無條件設 ShowLink）：這一組不修，列進 HANDOFF 的待辦（2026-11-08 補記（G13，程式 `4b681b2`）：兩條都修了，見〈範圍外的發現〉的更新）。

### 實作【讀】【移】

- **比率的存放**（`src/parts/parts.c`）：`parts_message_window_mul_rate`、`parts_message_window_alpha_rate`，初值 1.0，由 `parts_set_message_window_rates()` 寫入。`PE_v14_UpdateComponent` 在判斷重入**之前**呼叫它（所以重入的呼叫也存，不論 show），新綁的 `UpdateMatrix` 也呼叫。不存檔：原版每次更新都重寫。比率改變時，重新合成每個連動的 parts。
- **背景**（`src/parts/message_window.c` 的 `parts_message_window_background()`，在 `src/parts/render.c` 的 `parts_render_cg` 畫訊息框自己的 CG 時呼叫）：照 `0x4f2660` 算乘色與 alpha 的位元組，乘色分兩句寫，對應原版乘和加的兩次捨入；轉整數用 `parts_rate_byte()`（照 `cvttss2si`：NaN 或超出範圍得最小的 int，再夾成 0..255）。結果**乘在**視窗自己的 alpha 與乘色上（不是取代）。基底白、目標黑是常數。版本低於 14 時不套用。
- **EffectLink**：parts 加一個旗標（不存檔）；在算合成值的三處（`parts_update_global_alpha`、`parts_update_global_multiply_color`、`parts_combine_params`）把連動 parts 自己的值乘上比率、截斷後再合成；沒有連動時是同一條式子。旗標改變時重新合成那個 parts 與它的子樹。
- **三個 HLL**（`src/hll/PartsEngine.c`）：`SetComponentMessageWindowEffectLink`（號碼 0 以下什麼都不做）、`IsComponentMessageWindowEffectLink`（號碼 0 以下回假，其他取得或建立）、`UpdateMatrix`（存 show 與比率）。在 v14 的註冊批次裡、空殼之前註冊，條件是宣告的形狀相符；形狀不同的保留原綁定。
- **樣本文字**（`src/hll/pe_v14_activity.c`）：訊息框的鍵表加「テキスト」／「文本」；只讀型別資訊的直接葉，值是字串時以 `PE_SetMessageWindowText(no, text, -1, NULL, 0, 0)` 設成視窗的文字（號碼 −1、沒有函式名，所以不查已讀表）。兩種拼法不分字集都認，和同一張鍵表的其他鍵一樣。
- **字型快取**（`src/text.c` 的 `text_style_font_size()`）：v14 每次以樣式的 face 與 size 重查並存回。FreeType 與 FNL 對同一組 face／size 回同一個尺寸，所以字形快取不丟（FN5）；每次多一次不超過 64 項的線性查找。v13 以下照舊。FreeType 每個字型的尺寸表固定 64 項，填滿是錯誤；改字級之後新的尺寸會真的被查出來，理論上用到的尺寸數會變多，路線上沒有出現這個錯誤。

### 適用範圍

- 只有 AIN 版本 14 以上用到新程式：背景只在版本 14 以上吃比率；比率只由 v14 的 `UpdateComponent` 與 `UpdateMatrix` 寫入；三個 HLL 只從 v14 的宣告註冊；連動旗標只能經它們設、沒設時照舊合成；字型重查以版本 14 為閘；pactex 載入器本身只用在 v14。
- v14 之前：WR8（v14 設過比率之後，v13 的 `PE_Update` 照 CG 畫）、FN6、FN7 守住。
- 不讀文字規則：鍵的兩種拼法在兩種規則下都認；預設（SJIS 規則）與 GBK 兩組修前修後失敗、通過的案相同，每個案的檢查數相同，每個突變在兩組失敗的案也相同【量】。SJIS 的 v14 遊戲沒有實測。

## 和原版仍不同的地方

都寫在原始碼的註解、探針檔頭與提交說明。

1. **基底色與目標色是常數**【移】：白與黑。「アクティブ」、「非アクティブ時の乗算カラー」與 EX 的「明るさ乗算色」都沒讀。這是這個遊戲五個訊息框與這一版 EX 的值【量】；執行中非作用中的乘色一直是白，靠的是 AIN 裡唯一的設定入口只有編輯器在用【推】；移植版的 `SetMessageWindowInactiveMultipleColor` 是空殼。英文版的 EX 沒有讀。
2. **和視窗 alpha、乘色的合成用浮點**【移】：原版 `0x579bb0` 整數相乘再截斷，移植版把位元組換成係數、以浮點相乘，所以視窗本身的 alpha 或乘色低於 255（例如淡入淡出中）時，推論兩邊最多差一級。WR12 接受 63 與 64（原版的整數乘積是 63；移植版的實際值探針沒有印）。
3. **比率全域只有一份**【移】：原版每次更新各自帶一份；`UpdateMatrix` 在原版只更新一個管理者的各層，移植版存下的比率到下一次 `UpdateComponent` 之前對所有 parts 生效。AIN 裡兩者傳的是同一份設定值。
4. **預覽的信息番號是 −1**【移】：預覽 pactex 寫的是 0，已讀判定也沒讀。差別只在之後用同一段文字、號碼 0 再設一次時會不會被當成一樣【推】，畫面看不出來。
5. **EffectLink**【移】：pactex 的鍵沒有讀、存讀檔不帶旗標；乘積超出 0..255 時移植版夾值，原版原樣往下傳。腳本的比率在 0..1 之內。這個遊戲走不到。
6. **UpdateMatrix**【移】：只存 show 與比率，原版那次更新的其餘部分（時間 0 的各 parts 更新）沒做。這個遊戲走不到。
7. **字型重查只在 v14**【移】：v13 以下照舊（FN7）；上游的修正不分版本。
8. **字形**：預覽的三行用移植版的預設字型（VL Gothic）。預覽縮放 0.66、字級 25 時，第 3 行一個字的上方細橫筆很淡；用 25 px 的字形加 0.66 倍的雙線性縮小可以重現，推論是縮小時細橫筆被取樣掉【推】。原版縮小時是否一樣，沒有看到。

另外，範圍外的兩點（下面〈範圍外的發現〉）也和原版不同，這一組沒有動。

### 實機：設定第 3 頁與對白【量】

做法：私人路線開新遊戲，點到開場第一句有框的對白，從選單開設定、切到第 3 頁，把「不透明度」的把手往左拖、再把「亮度」的把手往左拖到同一個位置，然後「返回遊戲」回到同一句對白；固定種子、不移動桌面游標，引擎每秒自己截一張圖。存下的兩個值都是 0.30083567（把手拖到的位置），依上面的式子兩個位元組都是 76。三趟：父版本的建置（G8b 的提交後，`42aa793` 的程式；只執行）、這一組的建置、這一組的建置只拉亮度。三趟都退出 0、桌面游標前後不變、結束後沒有殘留的行程。

| | 父版本 | 這一組 | 這一組，只拉亮度 |
|---|---|---|---|
| 預覽區（640×180）在第 3 頁剛打開時 | 平均色 (112.65, 98.84, 61.84) | (118.11, 104.52, 67.25) | 同左（逐位元相同） |
| 只拉不透明度之後 | 不變 | (152.40, 128.85, 97.49) | — |
| 兩條都拉（或只拉亮度）之後 | 不變；和剛打開時 **0 個像素**不同 | (148.12, 124.07, 96.54)；62115 個像素不同 | (103.83, 88.48, 64.08)；60948 個像素不同 |
| 回到對白的訊息框區 | (58.87, 54.85, 40.39) → (58.99, 54.79, 40.32)：只差鍵待標記動畫的 501 個像素 | (58.87, 54.85, 40.39) → **(133.43, 121.58, 93.29)** | (58.87, 54.85, 40.39) → (46.86, 42.92, 34.20) |

- **修前**：拉低兩條之後預覽區逐位元不變，回到對白訊息框也沒有變，和盤點時的結論一致。
- **修後**：不透明度拉低，背景（框與暗底）變淡、後面的場景透出來；再拉亮度，框的顏色變暗。回到同一句對白，訊息框的框與暗底幾乎看不見，場景透出來；頭像、對白文字、鍵待標記不變（只有背景吃比率）。只拉亮度時框變成暗的顏色、暗底更暗，文字與標記不變。
- **框的像素對式子**：取預覽裡不透明的框色像素 8933 個（剛打開時兩趟同色、拉了之後有變的）。
  - 只拉亮度：每個像素的原色乘 76／255 四捨五入後，三個分量都吻合的有 **8531** 個，乘 77／255 的只有 29 個，75 與 74 都是 0；G 分量比值的中位數 0.29804 就是 76／255。這直接量到亮度 → 乘色位元組 76。不吻合的多半在框的反鋸齒邊上（背景透出來），沒有逐點證明【推】。
  - 兩條都拉：從「只拉不透明度」到「兩條都拉」的進一步變化，是亮度經由背景的 alpha 造成的。G 分量是 255 的 8494 個框像素平均變化 53.30 級；代入上面量到的乘色 76，alpha 位元組 75、76、77 的預測是 52.65、53.35、54.05，所以資料把 alpha 定在 76（推算依賴乘色 76）。
- **預設值不變**：設定之前（兩條都是 1.0）的對白畫面，三趟逐位元相同；第 3 頁剛打開時，這一組和父版本的整張畫面只在樣本文字那一塊不同（5876 個像素，就是三行字與字的暗邊）。

## 提交說明的讀法

`c3e7649` 的提交說明在提交前逐句查證過（每一句都找得到證據，推論寫成推論），沒有和量測相反的句子。下面幾處以這裡為準；程式不 amend，改寫會換掉雜湊與執行檔裡的版本字串，提交後驗收的執行檔就對不上 commit。

1. 「nine automated routes keep … their click positions」：一般開場用固定間隔的自動點擊、沒有開點擊追蹤，沒有可比的點擊位置（[routes.tsv](routes.tsv)），所以對一般開場是空檢查；比過點擊位置的是開了追蹤的八條（和 [layer-switch](../layer-switch/README.md)〈提交說明的讀法〉同一點）。
2. 「Measured on a build of this code … (only comments and the harness have changed since)」那一段的路線、片頭（「mean +5.3 ms」）、存檔與截圖，以及設定第 3 頁的實機與並排，都是提交前那支建置的數字。提交的建置上：片頭組平均 −2.6 毫秒，戰鬥同樣落在 B 群（上面〈提交後驗收〉）。
3. 「they were not compared between runs of one build」：提交後驗收比了提交前與提交的兩支建置（程式只差註解與行號），那幾個檔在兩支之間也不同；同一支執行檔的重跑仍然沒有比。
4. 程式註解（提交前的核對找到、不擋提交；不是提交說明）：`src/parts/message_window.c` 背景那段寫背景 alpha「clamped the same way」，但原版的 alpha 是在 `0x4f2755`..`0x4f2768` 以條件搬移夾值，不經乘色用的 `0x550ce0`；範圍相同，所以不算錯，探針檔頭寫的「clamped to 0..255」比較精確。排給下一次動這個檔的程式提交（HANDOFF 的待辦）。

## 範圍外的發現

這一組沒有修，列進 HANDOFF 的待辦。

1. **`SetMessageWindowActive(false)` 會把視窗藏起來**：移植版的 `PE_v14_SetMessageWindowActive` 把 active 交給 `PE_SetShow`；原版 `0x5950d0` 只寫 `+0xbc` 並標已改，非作用中的視窗照畫，只是基底色改用「非アクティブ時の乗算カラー」（這個遊戲是白，畫面和作用中一樣）。呼叫者是 ADV 的 `message::detail::CMessageWindow@UpdateActiveState`，多個視窗的場景可能走得到；G8b 的路線裡追蹤到的前 12 次都是 active 1，傳假的情形沒有量。這一組沒有讓它變差。建議另開一組：先量遊戲會不會傳假，再保持顯示、把作用中旗標與非作用中的乘色接進背景的基底。
