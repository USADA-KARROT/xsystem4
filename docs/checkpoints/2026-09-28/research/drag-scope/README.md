# 拖放與滑動的範圍：哪些畫面要拖、有沒有替代（G12 之前的唯讀研究）

2026-11-02。唯讀研究：沒有改程式、沒有跑 GUI、Wine 或遊戲。另一個代理換一套方法試著推翻結論，沒有推翻，判定成立；他補的幾點也收在下面。研究時讀的移植版是 `3228ba8`（含 G8 的程式 `2d76d52`，在 G8b 之前）；G8b（`d698d6a`）改變的那一點另外註明（〈和原版仍不同〉第 3 條），G9（`c3e7649`）沒有碰拖放。這份研究隨 G9 的文件提交公開，取代 HANDOFF 先前排的「G12 拖放與滑動」的範圍（drop 目標的選取、Dropped、Dragged、swipe）。

標記：【AIN】從 AIN 傾印（腳本的反組譯）直接讀到的；【讀碼】讀移植版的原始碼；【推論】由前兩者推的，沒有實機、沒有原版畫面。公開檔不寫腳本字串、函式內容與角色名；類別名、函式名與 pactex 的鍵名照既有慣例。

> **2026-11-10 更新（G12a）**：以下保留 2026-11-02 的唯讀研究。G12a 的整合程式 `fd5c23a` 與 `drag-flag` DG1–DG9 已完成提交後驗收（兩組 141 模式、九條路線、三趟片頭）；提交前首輪片頭第三趟的有效失敗與原因未知仍保留，最新結果見 [拖曳旗標研究](../drag-flag/README.md)。原文「沒有實機」「旗標沒讀」「換位應該可用」只描述當時狀態，不能當成現況。
>
> 【量測】編隊與人材清單在 G12a 修前就能換位，修後結果相同；本次只補載入旗標。客人總覽的受影響判定元件在已測畫面隱藏，戰鬥拖曳範圍未測，因此可見修正效果只有合成探針支持。原版只取得靜態清單並排，沒有拖曳中畫面。
>
> 【量測】DG8 驗到切層期間保留拖曳狀態、回舊層後歸位；這是 G8b 的既有行為。【推論】原版切走期間應保留同類狀態，未有畫面；刪層是否送 DragEnd 仍未知。「元件刪除、不留狀態」僅能支持畫面不留元件，不能擴大為腳本提供者一定清除拖曳狀態。DG9 支持停在目標後放開的結果，快速移到新目標並立刻放開尚未覆蓋。

> G12a 推送後的順序改以 [HANDOFF](../../HANDOFF.md) 最新節為準：11/09 三個戰鬥問題 → G10b → 每層取樣／取消 → G12b → 第 8 天後試玩。下方原訂實機清單保留為計畫，不代表各項均已完成。

## 結論

1. **沒有任何畫面「沒有替代、又是必經」。拖放與滑動不會擋住遊玩。**
2. **遊戲本體只用左鍵拖曳的 7（DragBegin）、8（Draging）、10（DragEnd）**【AIN】。
   - 放下系列 11–14（DropEnter、DropOn、Dropped、DropLeave）、右鍵與中鍵的拖曳處理函式，遊戲本體都沒有註冊。放下系列只出現在 parts 框架給編輯器用的樹狀元件，那個元件只由 activity 編輯器與舞台編輯器建立；右鍵、中鍵的拖曳只出現在特效編輯器（`elkeditor`）。
   - 訊息派送（`parts::detail::CPartsMessageManager@CallDelegate`）的分支裡**沒有 9**（先前文件寫的 Dragged），所以就算送了也會被丟掉。
   - 遊戲的結構裡沒有放下或滑動的委派成員；pactex 只有屬性欄位，沒有事件綁定欄位。
   - DragEnd 的 mode 沒有任何遊戲的消費者區分 0（Dropped）和 1（NoTarget）；小地圖與立繪檢視只看是不是 3（OutOfScreen）。
   - 所以「放下目標的選取」、Dropped 與 Dragged 補了，對這個遊戲沒有可見的效果。
3. **放下之後的位置由腳本自己算**【AIN】：共用的 `PartsStateEventProvider` 在 DragEnd 時把元件歸位、送出拖曳的位移；編隊與人材清單的訂閱者再用每輪輪詢游標的 `InsertPositionView` 決定插入或交換的位置。不靠放下訊息。
4. **G8 之後這些拖曳應該已經可以用**【讀碼＋推論，未實機】：
   - G8 送 7、8、10：左鍵按在目標上、移動超過門檻（10）就開始，不論元件可不可拖都送，只有可拖的元件跟著游標移動。按下那一輪，元件的按鍵表先送 KeyDown（16），腳本在那裡記下起點；放開那一輪先送 DragEnd、再由焦點送 MouseClick，所以腳本用來吞掉「拖曳之後那一下點擊」的旗標來得及。
   - 所以下面這些應該走得通：編隊換位；人材清單換位（營業前的客人清單也一樣）；小地圖平移；戰鬥面板左右拖換角色；立繪檢視上下拖曳捲動。
   - 10/19 盤點寫的「腳本收不到開始、結束，放開後不會歸位或交換」是 G8 之前的狀態，已經過時。盤點擔心的「每幀 BeginInput 會打斷拖曳」前提不成立：這類畫面的迴圈（`CActivity@UpdateActivity`）整段執行只 BeginInput、EndInput 各一次【AIN】。（盤點紀錄不公開。）
5. **滑動只影響有滾輪的清單**：滑動 27–29 移植版不送，`Parts_SetSwipeType`、`Parts_GetSwipeType`、`Parts_StopSwipe` 是空殼【讀碼】。用到滑動的是 9 種用 `ScrollBase` 的清單與劇情回顧，全部有滾輪（G5 做了），除了一種以外也都有捲軸【AIN】。

## 補充的幾點

- **編隊換位的成敗只看輪詢**【AIN】：放下時，結果只看 `InsertPositionView` 每輪用游標位置與元件判定得到的插入或交換位置；有值就播 Click 的系統音效並換順序，兩個都沒有就播 Cancel、把順序還原。所以就算哪一環在移植版出錯，結果也是「每次放下都取消」，不會卡住、不擋遊玩。移植版用到的函式（游標判定、元件左上位置與大小、拖曳時把 Z 拉到最上層）都有實作【讀碼】。但這條鏈從來沒有在實機跑過，讀程式分不出「真的能換位」和「每次都取消」，所以 G12a 要用探針或實機記下放下時出現的是 Click 還是 Cancel。
- **可拖的元件要有人歸位**【讀碼＋AIN】：移植版放開時從不還原來源的座標；任何可拖、卻沒有負責歸位的 DragEnd 處理的元件，拖過之後會停在放開的地方。全部 pactex 裡 `[ドラッグ]` 是 1 的只有兩處（立繪元件的按鈕、戰鬥行動面板的拖曳範圍），兩處的腳本都會歸位；pactex 的屬性在載入時套用一次，比腳本把人材卡設成不可拖還早，不會蓋掉腳本的設定。G12a 讀 `[ドラッグ]` 時要守這一條。
- **戰鬥面板的外觀**【AIN＋推論】：拖曳範圍的 Z 比按鈕高，原版拖曳時它跟著游標走、蓋住游標下的按鈕，所以推論原版拖曳中按鈕不會變成滑過的樣子，移植版會。純外觀。
- **「拖一下變成點擊」**【讀碼＋推論】：清單項目按住拖一段、在同一項上放開，移植版會當成點那個項目；原版開始滑動之後會不會取消這次點擊，沒有查。讀檔與商店購買都還有一步確認框，所以就算誤觸也不會直接造成不可逆的結果【AIN】。
- **營業中的道具清單只剩滾輪**【AIN】：它沒有捲軸、滑動又是空殼，項目多於四、五個時下面的只能用滾輪捲到。滾輪和 G5 實機驗過的清單是同一套程式，但這一個清單沒有直接驗過。

## 和原版仍不同

1. **pactex 的 `[ドラッグ]` 沒讀**：戰鬥面板的拖曳範圍、客人的立繪拖曳時不跟著游標走。外觀差異。
   > 2026-11-10：此項由 G12a 補讀；原版與實機宣稱限制見頁首更新與[新研究](../drag-flag/README.md)。
2. **滑動 27–29 不送**，三個 HLL 是空殼。有替代（上表）。
3. **拖曳途中作用中的層被換掉**：研究時（G8）移植版會清掉槽、不送 DragEnd，腳本端留在「拖曳中」：被拖的卡停在游標最後的位置與最上層、插入的標記留著；再拖同一張卡一次會重新開始並正常結束【AIN＋推論】。原版每一層各自保留槽，回到那一層後拖曳繼續。**G8b 起**移植版也每層保留槽，在別層放開的拖曳在舊層再跑時送 DragEnd（[layer-switch](../layer-switch/README.md) 的 KE94）；舊層不再跑（例如被拿掉）時的情形這次沒有重查。要碰到這個情況，得在拖曳中開出新的層，編隊與人材畫面找不到會這樣做的路徑；拖曳中按結束鍵會結束整個畫面、元件跟著刪除，不留狀態【AIN】。
4. **放下目標與 Dropped、Dragged、DragEnd 的 mode 0、右鍵與中鍵拖曳**：不做，這個遊戲沒有消費者（上面第 2 條）。放下目標在滑過時被略過的外觀差異，等原版畫面再決定。

## 範圍：G12 縮成兩半

原本的 G12（drop 目標的選取、Dropped、Dragged、swipe）縮小並往後排（HANDOFF〈接下來依序做〉：G10 → U2 → G1c → G12a → 每層取樣與取消旗標 → G12b → 試玩）。

- **G12a（小）**：
  1. pactex 讀 `[ドラッグ]`，是 1 時呼叫 `PE_SetDrag`（取捨和 `點擊許可` 一致）；守上面「可拖的元件要有人歸位」那一條。
  2. 探針：用原版 AIN 的 `PartsStateEventProvider` 流程驗 16 → 7 → 8 → 10 → MouseClick 的順序、拖曳之後那一下點擊被吞掉、起點是按下時的位置；`InsertPositionView` 的插入或交換在放下之前有值。可以加一案：拖曳中切換作用中的層再切回，記下卡片的位置與 Z（上面第 3 條，G8b 之後要重看）。
  3. 實機：編隊（插入、交換、拖到空處取消、拖曳中按右鍵）與人材清單換位，和原版並排；記下放下時出現的是 Click 還是 Cancel 的系統音效，才分得出「真的能換位」和「每次都取消」。
- **G12b（之後）**：滑動。動手前先反組譯滑動用滑鼠怎麼觸發、門檻與慣性、和點擊的互斥（開始滑動後會不會取消點擊）。驗收：9 種清單與劇情回顧，順便用滾輪捲到營業中道具清單的最後一項。
- **從範圍刪掉**：放下目標的選取、Dropped、Dragged、DragEnd 的 mode 0、右鍵與中鍵的拖曳。

## 方法

- **介面的槽位**【AIN】：腳本多半透過 parts 介面的方法註冊事件，很少直接呼叫函式名，所以先從按鈕 parts 類別建立的 vtable 解出每個槽是什麼（拖曳、放下、滑動的 add／remove，Draggable、SwipeType、Clickable、Transparent 的 set）。反駁的一方改從基底 parts 類別的 vtable 重新解，槽位一致。
- **掃描**【AIN】：掃所有函式裡對上面這些槽的介面呼叫、以函式號做的方法呼叫、名稱帶 Drag／Drop／Swipe 的直接呼叫與 HLL；lambda 歸到外層函式；排除各編輯器、parts 框架本身與 `AFL_Parts_*` 包裝。遊戲本體的註冊點：拖曳只有左鍵三種，在 `PartsStateEventProvider`、小地圖、戰鬥行動面板、立繪檢視四處；滑動只有三種，在 `ScrollBase`、劇情回顧、問卷三處。直接呼叫的拖放包裝函式都沒有呼叫者；停止滑動的包裝有 6 個呼叫者，都是滾輪或滑動的處理函式。
- **訊息派送**【AIN】：派送的分支依型別呼叫處理函式；7、8、10 再依按鍵分給左、右、中的處理函式；DragEnd 的 mode 是 0 Dropped、1 NoTarget、2 Canceled、3 OutOfScreen。
- **移植版**【讀碼】：v14 的輸入（`src/parts/input.c`）、pactex 載入（`src/hll/pe_v14_activity.c`）、`PE_SetDrag` 與空殼的列表。
- **pactex**：全部 pactex 的文字傾印裡 `[ドラッグ]` 是 1 的兩處、`[スワイプ]` 是 1 的一處（劇情回顧的滑動範圍）。

## 沒做與限制

- 沒有實機、沒有原版畫面；各畫面「移植版（G8 之後）」那一欄都是讀碼推論。拖放的原版補拍沒有做。
- 沒有反組譯原版用滑鼠怎麼觸發滑動、門檻與慣性、開始滑動之後會不會取消點擊。
- 「沒有給建立函式的 activity 用名稱對應的預設建立函式」只從註冊的寫法推出來，沒有逐步追過（影響客人清單與客人立繪兩列）。
- 隊伍順序對戰鬥的實際影響（前衛格數、傷害）沒有查，只確認出戰成員依順序排。
- 人材順序是否影響任何數值：只看到顯示與瀏覽的用途（卡片位置、人材操作畫面的前後切換、事件提示的排序），不能排除沒搜到的間接用法。
- 原版會不會把「不可點擊、但不穿透游標」的元件當成按下的目標（客人立繪能不能拖）沒有確認。
- 只看了中文版的 AIN 傾印；日文版、英文版的腳本若不同，不在範圍內。
