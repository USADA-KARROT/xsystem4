# 確認框、`system.Exit`、關閉視窗

2026-10-12。基底 `c87e265`。同一天依審查做了一輪修正，內容已併入下面各節（「審查後的修正」一節列出改了什麼）。

這一步讓設定頁的「返回標題畫面」「結束遊戲」照原版先問再做，讓 `system.Exit` 真的結束程式，並讓關閉視窗（關閉鈕、Cmd+Q）在「結束遊戲時進行確認」開著的時候先問。

## 症狀

修改前：

- `system.MsgBoxOkCancel` 印一行警告後固定回 1。「返回標題畫面」按一下就重置，沒有存檔的進度直接丟掉；設定頁「輸入」分頁的兩個確認開關沒有作用。
- `system.Exit` 是空殼。「結束遊戲」的腳本在呼叫之後是一個只呼叫 `system.Peek` 的迴圈，沒有離開條件：按下去畫面就停住。
- 關閉視窗直接結束，不問。

## 原版依據（靜態反組譯）

只來自多娜多娜這一支執行檔與它的 AIN；沒有執行。標「偽代碼」的只看了反編譯的偽代碼，其餘讀過反組譯。標「Windows 的一般行為」的不是從這支執行檔看到的，也沒有實機。

## 做法

- **確認框**（`src/vm.c` 的 `vm_ask`、`src/hll/system.c`）：模態的兩鈕對話框，掛在遊戲視窗上，標題是遊戲名稱，內文由遊戲編碼轉成 UTF-8。舊 VM 的系統呼叫 `SYS_MSGBOX_OK_CANCEL` 原有的那一段抽成共用函式，它自己傳的內容不變。按鈕文字（確定／取消、是／否）依系統語言，有英、日、繁中、簡中。
- **不問的情況**：`XSYS4_AUTO_MSGBOX` 是 `ok` 或 `cancel` 時就是那個答案（空字串等於沒有設定）；畫面上沒有視窗時（探針）答案是「確定」。兩種情況都只記一行、不跳對話框。`run-gui-bounded.py` 的 `RUN_AUTO_MSGBOX` 預設 `ok`，`ask` 才跳真的對話框。
- **對話框顯示不出來**（SDL 回報失敗）：不是回答，由呼叫的一方決定。腳本的確認框當作「取消」（和原版相同：`MessageBoxA` 失敗回 0；問不出來就不做會丟進度的事），關閉視窗那一問當作「是」（否則視窗關不掉）；不做輸入重設，記錄寫明是顯示失敗並附上 SDL 的錯誤。舊 VM 的 `SYS_MSGBOX_OK_CANCEL` 失敗時結果仍是 0。
- **對話框之後的輸入**（`src/input.c` 的 `input_modal_closed`）：對話框開著的時候鍵盤與滑鼠是它的。關掉之後把所有按鍵與滑鼠鍵當成放開，丟掉那段時間排進來的鍵盤與滑鼠鍵事件。
- **`system.Exit`**：設一個旗標，`CALLHLL` 的處理在函式庫呼叫返回之後先清掉旗標、再以狀態 0 結束程式，和 `system.Reset` 同一個位置；重新啟動也會清掉它。參數不用。已讀表在結束時由 MsgSkip 的收尾寫出（既有）。
- **關閉視窗**（`src/input.c` 的 `close_requested`）：`SDL_QUIT` 到的時候，「結束遊戲時進行確認」開著而且不是訊號造成的，才先問「是／否」，答「否」程式繼續。這個開關只有 v14 的視窗設定會打開（`SystemService` 載入與改變第 4 型時通知輸入層），v14 之前照舊直接結束。SIGINT 與 SIGTERM 經 SDL 也會變成 `SDL_QUIT`：在 SDL 的處理函式上面包一層記下來，訊號照舊直接結束（對話框開著時來的訊號也一樣，答「否」仍然結束）；包裝在第一次處理事件時裝，那時還沒有處理函式可包就下一次再試。答「否」之後，還排著的 `SDL_QUIT` 一併丟掉，不再問一次。跳出對話框之前先把已讀表寫出：對話框開著時行程若被強制終止，走不到結束時的收尾。Android 上不問、照舊直接結束（SDL 在 Activity 銷毀時送出 `SDL_QUIT` 並在 UI 執行緒等這一邊結束，而訊息框要靠 UI 執行緒顯示；依 SDL 2.32 的 `SDLActivity.java`，沒有實測）。
- **按鈕與問句的語言**：依 SDL 回報的第一個偏好語言。中文先看文字（`Hant`／`Hans`），沒有才看地區；SDL 2.32 在 macOS 上把「zh-Hant-TW」切成語言 `zh-Hant`、地區 `TW`，把「zh-Hant」切成語言 `zh`、地區 `Hant`（實測），兩種都判成繁中。
- **兩個確認開關**不必另外做：腳本讀的是 [config-widgets](../config-widgets/README.md) 那一步已經照原版實作的視窗設定第 3、4 型。

## 與原版還不同的地方

- **對話框的樣子**：原版是 Windows 的訊息框（有標題列，確定在左、取消在右）。這裡是 SDL 在各平台的訊息框；macOS 上是掛在視窗上的警示框，遊戲名稱是粗體的第一行，預設按鈕在右。原版的是／否框帶問號圖示、確定／取消框沒有圖示；這裡兩種框是同一種（SDL 的「資訊」類）。
- **是／否框的 Esc**：這裡 Esc 等於「否」。原版的是／否框沒有取消鈕，Esc 關不掉（Windows 的一般行為，沒有實機）。確定／取消框的 Esc 等於取消，兩邊相同。
- **關閉視窗問的那一句**：原版固定是執行檔裡的那一句，不隨系統語言，而且和「結束遊戲」鈕問的是同一句。這裡是另外寫的四句（英、日、繁中、簡中），跟系統語言走，所以系統語言和遊戲語言不同時，「結束遊戲」鈕與關閉視窗問的是兩種語言的句子。四句都刻意不用腳本原句的句式（對過的原句：中文版執行檔與腳本的那一句、英文版腳本的英文句與它留著沒有翻的日文句；簡中的一句是繁中那一句的轉寫，沒有簡中版可以對）。
- **對話框關掉之後的按鍵**：這裡把所有按鍵當成放開、丟掉那段時間的鍵盤滑鼠事件。原版每次查詢都讀系統當下的鍵狀態，沒有這一步。看得出來的差別：(1) 腳本在取消之後等 Enter 與 Esc 放開的那個函式，原版會等到真的放開，這裡立刻通過；按住 Esc 或 Enter 超過系統的重複延遲來關掉對話框時，之後的重複事件會被當成一次新的按下。(2) 按著 Ctrl 快進時被問（例如 Cmd+Q 答否），原版關掉對話框後仍在快進，這裡要放開重按。(3) 左鍵按著時跳出對話框，關掉之後元件層會把它當成一次放開。其中 (1) 以合成的重複按鍵試過 Esc 按住約 1.3 秒：設定頁沒有被關掉、沒有再跳對話框；實體鍵盤與 (2)(3) 沒有試過。
- **對話框顯示不出來**時，關閉視窗那一問這裡當作「是」、照常關閉，原版（`MessageBoxA` 回 0）是不關；腳本的確認框兩邊都是取消。
- **關閉 hook 沒有做**：`SetHookCloseApp` 仍是空殼，系統訊息佇列永遠是空的，`PopSystemMessage`／`PopSystemMessageString` 的宣告形狀沒有動。一般遊戲不會打開 hook，只有開發用的編輯器會。
- **結束時不備份存檔**：`SystemService.AddBackupSaveFileName`／`BackupSaveFile` 本來就是空殼（返回標題時腳本自己呼叫的那一次也沒有做）。
- **結束時寫的檔案**：原版在視窗關閉時一次寫四個檔（視窗設定、滑鼠游標設定、`CommonSystemData`、已讀表）。這裡視窗設定與 `CommonSystemData` 在值改變時就寫，已讀表在結束時（以及關閉視窗的對話框跳出之前）寫，**滑鼠游標設定不存檔**（既有的差異，見 `src/hll/SystemService.c` 的註解）；視窗位置不記。
- **沒有視窗選單**（原版有「系統」「幫助」，其中「返回標題」讀視窗設定第 3 型）。
- **對話框開著的時候訊號結束不了程式**：模態迴圈裡不處理事件，要等對話框關掉（那時不論回答是什麼都結束）。等不到而被強制終止時，關閉視窗的那一問之前已經寫過已讀表；腳本自己的兩個確認框開著時被強制終止，已讀表不會寫。
- **訊號的分辨只在 POSIX 上有**：Windows 上沒有包裝，主控台的 Ctrl+C 若經 SDL 變成 `SDL_QUIT`，會和關閉鈕一樣被問（沒有建置、沒有實測）。Android 上關閉視窗不問。
- **啟動的頭幾毫秒**（函式庫還沒啟動）與 v14 之前，關閉視窗不問。
- 系統關機或登出時 macOS 也會送出結束的要求，這裡同樣會問；原版在 Windows 上那是另一個訊息，不經過這一段。

## 審查後的修正

同一天的獨立審查沒有找到會當機、卡死或丟資料的問題，留下的小修正如下（都已在上面各節裡）：

- 對話框顯示失敗原本一律被當成「取消／否」（關閉鈕因此關不掉、記錄看起來像使用者按了取消）。改成：關閉視窗那一問當作「是」，腳本的確認框仍是取消；都不做輸入重設，記錄寫明是顯示失敗。
- Android 上關閉視窗不問。
- `system.Exit` 的旗標在結束之前先清掉，重新啟動也清掉。
- 關閉視窗答「否」之後，還排著的 `SDL_QUIT` 丟掉，不再問一次。
- 訊號的包裝至少包到一個處理函式才算裝好，否則下一次處理事件時再試。
- 語言判定補上 SDL 把文字切到地區那一欄的情形，而且文字先於地區。
- 關閉視窗的四句都換了句式（原先繁中與簡中的第一行是原句前面加兩個字，日文的第一行和日文原句相同，英文的第一行只差一個動詞）。
- 跳出關閉視窗的對話框之前先寫已讀表。
- 關於原版的說法補正：VM +0x18 的身分由推論改成事實；視窗關閉時寫的是四個檔；按鍵查詢是即時的；關閉視窗的問句不隨系統語言；是／否框的 Esc 與圖示。
- 探針加了 CE8–CE12；引擎多了一個只給探針用的替身（`src/vm.c` 的 `vm_ask_test`，平常是空的）。

另外（不是審查提的）：舊 VM 的系統呼叫 `SYS_EXIT` 恢復成上游的行為，見「適用範圍」。

審查留下、這一輪沒有做的：左鍵按著時跳出對話框、長按 Esc／Enter 關掉對話框、按著 Ctrl 快進時被問這三種操作的後果（先用真實鍵盤滑鼠看過再決定）；關閉視窗的問句改成跟遊戲語言。

## 適用範圍

- `system.Exit` 與 `system.MsgBoxOkCancel` 在 `system` 函式庫（v14）裡的行為對所有用這個函式庫的遊戲都變了；依據只有這一支執行檔。
- 關閉視窗的確認跟著 v14 的視窗設定表走，那張表也只從這一支執行檔讀出。
- 舊 VM 的系統呼叫：`SYS_MSGBOX_OK_CANCEL` 等價。**`SYS_EXIT` 恢復成上游的行為**（以參數為結束碼直接結束）：這個分支在移入 v14 的 VM 核心時（`14c2618`）把它改成只印一行警告、不結束，v14 之前的遊戲因此結束不了。多娜多娜的腳本沒有任何舊式的系統呼叫（`CALLSYS` 0 處），所以這個恢復對它沒有作用；沒有用任何一款舊遊戲實跑過。
