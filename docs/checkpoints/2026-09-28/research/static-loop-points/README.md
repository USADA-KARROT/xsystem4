# G1c：v14 靜態通道的迴圈範圍與串流最後一圈

2026-11-10。提交前以 `672f0d0` 加修改量測，兩項最小註解修正後，預設／GBK 各 138 模式 PASS、sanitizer 0；九條主路線與三趟片頭個別及組層級通過。語義、證據雙審完成，已在原基底提交 `4ae99ed`；libsys4 固定 `247f544`。已接到父提交 `76a6f71`，整合提交為 `65ab81b`；整合修前對照、預設／GBK 各 140 模式、九條主路線及三趟片頭個別／組層級驗收均完成。提交後證據覆核通過；最終公開覆核 PASS，新增 H0／M0／L0，程式推送已完成，三方一致為 `65ab81b`。

本組修正兩項聲音群組模式的行為：靜態通道不採用 timemap 迴圈點，循環時重播整檔；採用 timemap 迴圈點的串流通道，有限次數的最後一圈到迴圈終點就停止。靜態通道仍依 timemap 決定群組與增益。

遊戲資料與腳本的靜態交叉量測顯示，本遊戲可到達的靜態循環路徑受影響 **0 列**。修正的正面證據來自合成探針；實機路線、追蹤與錄音只能作回歸驗證，不能據此宣稱聽感改善。串流最後一圈是另一項變更，不能由「靜態受影響 0 列」推出完全沒有差異。

## 原版依據

以下來自本遊戲原版執行檔的有界靜態分析；沒有把合成探針的結果當成原版的動態量測。

| 項目 | 位址 | 靜態分析讀到的行為 |
|---|---|---|
| Prepare 與載入後設定 | `0x4a3430`、`0x4a3460` | 先依 ID 取得或建立通道，再載入聲音；群組設定與交付迴圈點是兩個動作。Begin、End 都非負才呼叫緩衝區的 SetLoop |
| 緩衝區種類 | `0x700270` | 種類參數為 0 建立靜態緩衝區，非 0 建立串流緩衝區；其 vtable 分別為 `0x8128d8`、`0x812820` |
| 靜態 SetLoop | `0x49c5c0` | 直接回假，不儲存起點或終點 |
| 串流 SetLoop | `0x6f7ed0` | 儲存兩個端點並回真 |
| 靜態有限次數 | `0x6fc540`、`0x6fc760` | 每圈結束後累加圈數；未達設定次數時，呼叫裝置緩衝區的停止、設位置 0、播放槽位；達到次數時結束 |
| 靜態無限循環 | `0x6fc4a0`、`0x6fc5a0` | 次數 0 使用裝置緩衝區的循環播放旗標 |
| 串流最後一圈 | `0x6f8af0` | 到終點時，有限圈數若已用完，就把剩餘輸出填零並返回；否則跳回起點。終點不包含 |
| 串流未設定有效點 | `0x6f7a20` | 開檔時先把迴圈範圍設為整檔 |
| 載入後預設次數 | `0x4a4e3f`–`0x4a4e48` | 靜態為 1，串流為 0；這項差異本組未修正 |
| 同 ID 的種類 | `0x49a130`、`0x4a2aa0` | 已有 ID 時返回原通道；只有第一次建立才決定種類。SetLoopCount 可以在第一次 Prepare 之前建立串流通道 |

**推論界線**：裝置呼叫與循環旗標依 IDirectSoundBuffer 的標準 vtable 與旗標解讀，沒有追進 DirectSound；靜態緩衝區裝著整個檔案，是由其用法推論。串流端點換算（`0x6f8220`、`0x6f8270`）所取的解碼器欄位讀成位元深度、聲道數，以及解碼器位置讀成位元組位置，也包含推論。

## 移植版的變更與範圍

群組模式仍要求 AIN 恰好是 v14、使用 GBK 字元規則、有 MainEXFile 函式庫，而且主 EX 的群組表形狀有效。v13 以下、v15、SJIS、只有 GB18030 旗標、缺表或異形表仍走原本混音器；本組不改舊的重填函式。

| 通道來源與種類 | 迴圈範圍 | 有限次數的最後一圈 | 群組 |
|---|---|---|---|
| sound／voice，bStreaming＝0 | 整檔 | 到檔尾 | 照 timemap；缺列或群組不合法時用既有後備群組 |
| sound／voice，bStreaming 非 0，有有效 timemap 點 | 第一圈從 frame 0 到 End，後續圈從 Begin 到 End | 到 End，不讀其後尾段 | 照 timemap |
| sound／voice，bStreaming 非 0，沒有有效點 | 整檔 | 到檔尾 | 沿用既有規則 |
| BGM 封裝 | 沿用 BGI | 沿用播到檔尾的既有行為 | 沿用既有規則 |

實作在開通道時記錄 bStreaming，只有 sound／voice 的串流通道套用有效 timemap 點時，才標記最後一圈停在該終點。這兩個旗標在 Play 前設定，音訊 callback 只讀。PlaySe、引擎自己的聲音及檔案／記憶體入口維持靜態預設。BGM 封裝不會取得這個 timemap 標記。

這次不改自然播完後倒回 frame 0 的既有處理。串流通道到 End 結束後也倒回 0；這是既有移植策略，詳見[聲音倒帶研究](../sound-rewind/README.md)。HLL 的改動只有註解；沒有新增模式，也沒有修改模式登記、標頭、submodule 或建置設定。

### 保留的移植策略與主要差異

- **種類依每次 Prepare**：移植版每次 Prepare 重開通道，種類依當次參數；原版由 ID 第一次建立決定。不能把原版簡化成「第一次 Prepare」，因為 SetLoopCount 可能先建立 ID。原版 Unprepare 是否移除 ID 物件尚未查明。
- **端點修整**：只採用非負、Begin 小於 End 且 Begin 在檔內的範圍，End 夾到檔長；其他情況整檔循環。原版對有效端點的終點不包含已有靜態依據，但無效或越檔尾端點的實際輸出仍未追清。
- **BGM 封裝**：兩種 bStreaming 都保留 BGI 點與最後一圈到檔尾的舊行為。這是相容性防守，並非本組證實的原版語義。
- **預設次數**：移植版 sound／voice 在 Prepare 後一律為 1，原版串流預設為 0。未呼叫 SetLoopCount 的串流因此仍與原版不同；本遊戲的串流播放包裝會先設定次數。
- **播放用掉次數**：移植版每圈遞減次數，GetLoopCount 與播完後再次 Play 的圈數仍可能與原版不同；本組不處理。
- **重播與位置**：串流自然結束後倒回 0、播放中再次 Play 不中斷，以及解碼位置式 GetPos，仍保留既有差異。不能把 SR9 通過解讀為原版串流重播行為已完整重建。

## 資料與腳本量測

唯讀重算共 23,462 列 timemap；按移植版的端點修整規則，有 316 列不是整檔範圍，其中靜態來源的候選為 251 列。交叉檢查腳本呼叫後，這些靜態通道不會取得無限或多於一次的播放次數，所以本遊戲靜態循環實際受影響 0 列。這是資料與腳本的靜態量測，不是完整動態路線覆蓋證明。

串流最後一圈的變更另行計算：資料中修整後的 End 比檔尾最多少 3 個 frame，約 0.07 ms。腳本存在串流只播一次的路徑，但本次九條追蹤沒有觀察到有限次數串流播放或其差異末圈到達終點。上述資料上限不是路線實際效果，也不代表已做原版錄音或聽覺比較。

## 合成探針

沿用 `sound-groups` 與 `sound-rewind`，資料全部自行合成，經正式 HLL 與混音 callback 取樣。斜坡 PCM 讓每個樣本指出來源 frame；期望序列獨立寫出，不讀通道內部欄位當答案。有限圈數逐格核對後面的靜音，無限循環至少跨過兩圈。

| 案例 | 檢查內容 |
|---|---|
| SG7 | 串流的迴圈點、邊界、短迴圈、聲道與取樣率；靜態播一次的子案嚴格要求整檔 |
| SG13、SG14 | 靜態無限與有限次數都重播整檔，涵蓋單／立體聲、語音、22.05 kHz 與端點形狀 |
| SG15 | 靜態通道仍取得 timemap 的群組及群組鏈增益 |
| SG16、SG17 | 同一 ID 以不同 bStreaming 重新 Prepare，守住種類依當次參數的移植策略 |
| SG18 | PlaySe 與引擎自己的聲音維持整檔一次 |
| SG19 | 串流次數 1–3 的最後一圈停在 End |
| SG20 | 群組模式的 BGM 封裝沿用 BGI，兩種 bStreaming 的最後一圈都維持到檔尾；另守無效 BGI 與後備群組 |
| SR2、SR9 | SR2 靜態嚴格播完整檔；SR9 串流嚴格到 End，結束後讀位置及再次 Play 都從 0 開始 |
| SG10、SR7 | 既有版本、字集、缺表與 BGI／WAI 舊路防守 |

`sound-groups` 現為 21 案（SG0–SG20），`sound-rewind` 為 10 案（SR0–SR9）。防守中的 BGM 封裝及重新 Prepare 種類規則屬移植策略，不應統稱為原版相容性量測。

## 未驗證與後續

- 解碼器在宣告長度或迴圈終點前提早結束；現有合成 WAV 沒有觸發該分支。
- 原版靜態緩衝區確實裝著整檔，以及 DirectSound 的實際輸出；目前仍含上述推論。
- 無效、倒置、零或越檔尾端點在原版解碼器中的完整行為。
- 負次數、GetLoopCount、SetLoopCount 先於 Prepare、Unprepare 的 ID 生命週期，以及原版串流再次 Play 的圈數重設與實際輸出。
- Prepare 後不設定次數的串流預設差異，及既有位置／播放中再次 Play 的差異。
- 原版 BGM 封裝語義、所有版本與入口的完整交叉矩陣，以及真實音訊裝置的聽測。
- 錄音整段事件對齊電平、精確雙時鐘映射、少數過渡窗及數值警告原因；已有局部支持不擴張為整段相同。
- Windows、Linux 及其他遊戲未做本組實機驗收。完整套件 PASS 不代替這些驗證。
