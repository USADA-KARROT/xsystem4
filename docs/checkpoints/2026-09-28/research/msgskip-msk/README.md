# 已讀表（MsgSkip）照原版的檔案讀寫並存到磁碟

2026-10-11。程式 `4f2220e`（基底 `c40182c`；一起推送的四個 commit 的第二個，推送後的 HEAD 是 `4682a89`）。

這一步只處理已讀表與它的檔案。**對話文字的已讀顏色還沒有接上**（訊息視窗的已讀判定與取色是後面的兩步），所以畫面沒有變化，也沒有可以和原版並排的東西。

## 症狀

- 已讀表從來沒有寫到磁碟：每次啟動都是全部未讀，「跳過已讀」沒有跨次執行的紀錄，之後要做的已讀字色也沒有資料來源。
- 讀不了原版引擎寫的已讀檔。
- `MsgSkip.SetAdvFlag`／`GetAdvFlag` 沒有連結，呼叫時回 0。

## 根因

1. 寫檔靠 `MsgSkip_Init` 註冊的 `atexit` handler。這棵樹的 `sys_exit` 是 `_exit`，handler 從不執行；不論怎麼結束都不寫。
2. 它要寫的也不是原版的檔：xsystem4 自己的格式是 `MsgSkip.asd`（4 bytes 訊息數加位元表）；原版 v14 是 `SaveData/MsgSkip.msk`，位元的排列相同，多了標頭與 ADV 表。
3. v14 的 MsgSkip 庫沒有 `Init`（表由引擎自己建立），另有兩個 ADV 函式；移植版沒有對應的實作。

## 原版依據（靜態反組譯）

只來自多娜多娜這一支執行檔；其他 v14 遊戲沒有驗證。

| 項目 | 位址 | 內容 |
| --- | --- | --- |
| 函式庫分派 | `0x4c7230`（跳表 `0x4c738c`） | 四個函式：`SetFlag(int)`、`GetFlag(int)`、`SetAdvFlag(string, int, int)`、`GetAdvFlag(string, int, int)`；引數依序是名稱、版本、步數 |
| `SetFlag`／`GetFlag` | `0x4c8700`／`0x4c7700` | 已啟用、表非空、`0 <= n < 訊息數` 才動作；第 n 句是位元組 `n>>3` 的 `0x80 >> (n&7)`；`SetFlag` 不寫檔 |
| `SetAdvFlag` | `0x4c7760` | 找不到就新增（版本、步數）；版本不同兩者都覆寫；版本相同取較大的步數 |
| `GetAdvFlag` | `0x4c8750` | 已啟用、找得到、版本相同時回「記錄的步數 >= 步數」 |
| 建立 | `0x4c7650`，唯一的呼叫點 `0x4b5112` | 訊息數取自 AIN，檔名前綴取自遊戲的 EX 資料（這個遊戲是空字串）；位元表是 `(訊息數+7)/8` 個 0；讀檔；之後啟用，不看讀檔成敗 |
| 讀檔 | `0x4c7b50`；讀字串 `0x72c8b0`、讀整數 `0x72c6e0`／`0x72c730`、讀位元組 `0x72caa0` | 見下一節的規則 |
| 寫檔 | `0x4c7840`，唯一的入口 `0x4c1b60`（`0x4c1b77`）；檔案 `0x6dbb70`、`0x6dc100` | 表非空就整份重寫，不看有沒有變動；建立檔案後一次寫入，就地覆寫 |
| 視窗關閉 | `0x4be9b0`（`0x4bea04`） | 呼叫寫檔的入口 |
| Reset | `0x4b5b9a`–`0x4b5c20`：`0x4b5bc3` → `0x4c12e0` → 寫檔，之後 `0x4b30f0`（全部釋放）、`0x4b4bf0`（重新初始化） | 寫檔是 Reset 的第一步，早於釋放；只寫，不清表 |
| 腳本的 Reset | `0x4b5f00` | 只設旗標，VM 迴圈回到開頭才真的做（「`system.Reset` 這個函式會走到這裡」是推論，沒有追） |
| 訊息視窗查已讀 | `0x4eeada` | 直接呼叫 `0x4c7700`（之後接已讀字色時用） |

腳本只有四個呼叫：每顯示一句呼叫一次 `GetFlag`；一頁被清掉時才對那一頁的每一句呼叫 `SetFlag`（`EraseMessageNumber`），所以結束時還在畫面上的那一句不算已讀。`GetFlag` 的結果只寫進一個全域變數，讀它的地方都只和「跳過模式」有關；按住 Ctrl 的強制跳過不讀它。

## 檔案格式

小端。

| 內容 | 說明 |
| --- | --- |
| `"MSK\0"` | 魔數，以 0 結尾的字串；整串相等才接受 |
| int32 `0` | 版本；不是 0 就放棄 |
| 字串與結尾的 0 | 第二個字串；讀到什麼就寫回什麼（新檔是空字串，1 byte） |
| int32 訊息數 | 寫出的是 AIN 的訊息數 |
| int32 位元組數 | `(訊息數+7)/8` |
| 位元表 | 第 n 句 = `byte[n>>3] & (0x80 >> (n&7))` |
| int32 ADV 項目數 | 正常遊戲不會產生 ADV 項目，這裡是 0 |
| 每項：名稱與結尾的 0、int32 版本、int32 步數 | |

這個遊戲的 AIN 有 57532 句訊息，所以新檔是 17 + 7192 + 4 = 7213 bytes。

讀檔的規則（照 `0x4c7b50`）：檔案不存在就什麼都不做；魔數、版本、第二個字串、訊息數、位元組數依序讀，任何一項讀不到或不合就放棄，但第二個字串一讀到就留下，之後失敗也不還原；位元組數是 0 就放棄；位元表讀不滿就放棄。要載入的位元組數是 `(min(檔案訊息數, AIN 訊息數)+7)/8`：它比自己的表大、或比檔案的位元組數小，都放棄。所以檔案的訊息數較少時載入前段（整個位元組照抄），訊息數較多但位元組數相同時仍載入。ADV 表讀到哪裡算哪裡，同名取第一個。讀檔失敗一樣啟用，結束時把目前的表（可能是空的）寫回去。

## 存檔時機

原版只在視窗關閉與 Reset 時寫；`SetFlag` 時不寫，存檔時不寫，沒有定時寫。

移植版把寫檔放在函式庫的 `_ModuleFini`：`vm_exit` 與 `vm_reset` 都經過它（`vm_free` → `exit_libraries`）。`system.Reset` 在這棵樹仍是空殼、不會走到 `vm_reset`，所以另外讓它先做原版 Reset 的第一步：只寫檔，表不動（`msgskip_flush`）。

**實機上會寫的時機只有兩個：關視窗（`SDL_QUIT` → `vm_exit`），以及腳本呼叫 `system.Reset`（回標題、讀檔、Game Over）。** 不會寫的：設定畫面與標題畫面的「結束遊戲」（`system.Exit` 被既有程式壓掉，行程不會結束，要再關視窗才寫）、VM 錯誤、當掉、強制結束。原版 `system.Exit` 寫不寫沒有依據，沒有動它。

## 修正

- `src/hll/MsgSkip.c`：函式庫沒有 `Init` 而且 AIN 是 v14 以上時，以原版的格式建立、讀入、寫出（`0x4c7650`、`0x4c7b50`、`0x4c7840`）。寫檔先在記憶體組好整份，寫到同一個資料夾的暫存檔再更名（原版是就地覆寫）；失敗只留警告，舊檔不動。`_ModuleFini` 寫檔並釋放；Reset 之後重新初始化時從檔案讀回。
- `SetAdvFlag`／`GetAdvFlag`：只在原版格式啟用、而且 AIN 的宣告正好是 `(string, int, int)`、回傳 `void`／`int` 時才綁定；其他形狀維持未連結。
- `include/msgskip.h`（新檔）：`msgskip_get_flag`、`msgskip_get_adv_flag`（給之後的訊息視窗用，目前沒有呼叫者）、`msgskip_flush`。
- `src/hll/system.c`：`system.Reset` 的空殼先呼叫 `msgskip_flush()`；其餘不變，`system.Exit` 沒有動。
- 舊格式（v13 以前，或宣告了 `Init` 的遊戲）：檔名、格式、讀檔都不變；`_ModuleFini` 也以舊格式寫一次，表留在記憶體。這只接回關視窗這一條（上游靠 `atexit` 存檔）；上游的 `atexit` 另外涵蓋的 VM 錯誤、`ERROR()`、`main` 返回在這棵樹仍然不寫，`vmMsgSkip` 沒有涵蓋；經過 `vm_reset` 時也會寫一次，上游不寫。**沒有舊遊戲可以實機驗證。**
- 存檔的元件格式（XPE）與這一步無關，沒有動。

從這一步起，每次實機執行結束都會在存檔資料夾留下 `MsgSkip.msk`。拿舊的存檔資料夾當種子比較基準時，先看裡面有沒有這個檔。

## 驗證

- 新模式 `msgskip-msk`（14 案），每案在 fork 的子行程、私人的暫存存檔夾裡跑真 AIN、真 ffi；檔案內容全部是合成的，期望的位元組由探針自己算。各案內容見 [harness](../../harness/README.md)。
- 正式 before-check（[before／after](before-after.txt)）：`c40182c` 的 src／include 上 14 案全部失敗（沒有寫出檔案、讀不了 `.msk`、ADV 函式未連結、舊格式也不寫、`system.Reset` 不寫）；修正後全過；兩種字元規則結果相同，sanitizer 0。
- 反向檢查：31 個刻意改壞的地方，每一個都有案例失敗，都是探針自己的斷言或 sanitizer。這是實作時在最終的原始碼上做的；整合到主線時這一步的 src／include 與那一版相同。沒有對應突變的三段守衛：連續兩次 `_ModuleFini`、舊格式再啟動與經過 `vm_reset`、函式庫沒有啟動完成時的 `vm_exit`。
- 預設與 GBK 各 92 模式 VERDICT PASS、sanitizer 0（[預設](verify-default.txt)、[GBK](verify-gbk.txt)，四個 commit 之後的 HEAD）。模式數由 91 變 92；既有模式的斷言沒有改。
- **原版的已讀檔**：以它的複本驗過，讀入之後重存的檔與複本逐位元組相同（選用模式 `msgskip-msk-file`，不在例行的模式清單裡；另有一次實機以複本當種子，結束時寫回的檔也逐位元組相同）。原版的存檔資料夾只讀不寫，前後的雜湊與修改時間相同。反方向（原版讀這裡寫的檔）沒有辦法實測，依據只有格式逐位元組相同。
- GUI（[摘要](gui-summary.json)，`RUN_RANDOM_SEED=20261008`，四個 commit 之後）：十條路線都從空的存檔夾開始，沒有斷言或 VM 錯誤，對白的行數與雜湊和先前各組的紀錄相同；每條結束時寫出一個 7213 bytes 的 `MsgSkip.msk`，沒有殘留的暫存檔，檔裡的已讀集合就是該次顯示過的對白。只有不快進的 `noskip` 少一句：結束時還在畫面上的最後一句。
- 提交前在同一份修改上另外做的實機（不在摘要裡）：同一條路線連跑兩次，第二次啟動時讀回第一次的 88 句，寫回的檔與種子逐位元組相同；從設定畫面點「返回標題畫面」，紀錄依序是點擊命中、已讀檔寫出、`system.Reset` 的空殼警告。帶已讀種子的執行（上面的第二次，以及以原版檔的複本當種子的那一次）都是只按住 Return 的開場，每個時間點累積的對白行數與沒有種子時相同。

## 獨立審查

一輪兩個面向（檔案格式與解析、寫檔時機與舊遊戲），中等級以上的發現另有對抗驗證。審查者以反組譯獨立核對格式、讀寫規則、四個函式的語義與寫檔時機，並另寫程式重組原版的檔，與原檔逐位元組相同。

- 沒有 High，也沒有成立的 Medium。
- 一件 Medium 在對抗驗證降為 Low：實機上已讀只在關視窗時落盤，原版最常寫的時機是 Reset。它不是這一步引入的（修正前完全不存），但照建議補上了 `system.Reset` 先寫檔與案例 M14。
- 其餘 Low 都處理了：探針補「字串沒有結尾」的兩種檔與對應的突變；ADV 表是線性查找（刻意做大的檔載入是平方時間；項目數預期是 0，只加註解）；「v14 就用 `.msk`」的依據只有這一支執行檔（寫進檔頭註解）；兩處註解的位址與歸類；一個突變原本是被實作自己的 assert 攔下而不是探針（改寫後重跑）；探針補三段生命週期的守衛。
- 舊格式的遊戲在 `_ModuleFini` 寫檔：審查建議保留。

## 與原版的差異與限制

- **已讀字色沒有做**：訊息視窗還不查已讀表，文字永遠是白的。「跳過已讀」現在有跨次執行的紀錄，但畫面上真的開跳過模式的行為沒有驗證；帶已讀種子、按住 Ctrl 或以點擊前進的路線也沒有實測，「不受影響」的依據是腳本。已讀表開始有內容之後，任何誤開跳過模式的殘留問題會從看不出來變成對白被快進。
- **寫檔的時機比原版少**：`system.Reset` 仍是空殼，這裡只做了它的第一步；Reset 之後腳本停在沒有離開條件的等待迴圈（既有狀況）。三個呼叫 `system.Reset` 的地方只實機走過「返回標題」，讀檔與 Game Over 沒有。「結束遊戲」不寫。腳本的 `main` 自己返回時不寫（這個遊戲的 `main` 不會返回）。
- 寫檔經暫存檔再更名，原版就地覆寫；寫檔的瞬間存檔資料夾多一個暫存檔。Windows 的分支是直接覆寫，沒有建置過；Android 的分支也沒有建置過。
- `system.Reset` 寫檔的時刻：原版在 VM 迴圈回到開頭時，這裡在函式被呼叫的當下；腳本在那之後不會再標記已讀，檔案內容相同。
- 檔案比需要的短時，原版讀超出緩衝區，這裡缺的補 0；位元組數大到配置不了時，原版是配置失敗，這裡是放棄。讀檔、寫檔失敗是警告，不是訊息框。
- ADV 項目寫出的順序是讀入與加入的順序（原版是雜湊表的順序）；讀回來的語義相同。含 ADV 項目的原版檔沒有樣本，這一段只有反組譯與合成資料。
- 檔名前綴沒有實作（這個遊戲是空字串）。名稱含 0 的字串當成 C 字串。
- 修正前這棵樹對 v14 會讀存檔夾裡的 `MsgSkip.asd`（從不寫回）；現在完全不看它，沒有做遷移。
- 別的 v14 遊戲若原版的 `.msk` 版本或欄位不同，會被判定讀不了，結束時以空表覆寫（原版對版本不符也是這樣）。
- 探針沒有守著的：Reset 之後真的回到 VM 入口重跑函式庫初始化（探針是自己重跑 `_PreLink`）；舊格式經真的 `vm_exit`；`rename` 失敗與磁碟滿（寫檔失敗只測了存檔夾唯讀）。兩個行程同時用同一個存檔夾不處理，原版也不處理。
