## 症狀

G3（[滑過事件](../hover-events/README.md)）留下兩個差異，都出在子畫面開著的時候，例如據點的存檔確認框：

審查者另外讀出、這一組沒有重讀的兩點：

- `0x53c5b0` 收集清單之後呼叫的 `0x53c830` 是排序（超過 32 個元素時分割遞迴，否則小區段排序），比較清單紀錄的三個整數；三個鍵各是什麼欄位沒追。原版收集後會再排序，審查者認為這支持移植版沿用排序過的順序（z 順序），但沒有證實排的就是 z（語義審查 A6）。
- 左鍵按下時命中的元素放進另一個槽（+0x218），一般點擊在放開的那一次更新就清掉；只有元素的 +0x1c0 旗標成立時（由 `0x577fa0` 設定，審查者推定是手勢開始）才保留到之後，這時框的 BeginInput 會靜默重設它，關框後原版也會重送 MouseEnter。移植版沒有實作手勢，所以下面「不再送 MouseEnter」限於一般點擊（語義審查 A5）。

### 腳本端【AIN】

每個場景，包括確認框，都由 `SceneContext@0` 經 `AFL_Parts_AddLayer(-1)` 開一層；場景的 `WaitForClick` 在迴圈前後呼叫 BeginInput／EndInput；關閉時 `SceneContext@1` 經 `AFL_Parts_EraseLayer` 收層。設定、回顧等另由 `CASPartsLayer` 開層並切換作用中層。輸入總開關的包裝 `AFL_Parts_SetEnableInput` 沒有任何腳本呼叫。

### 推論【推】

照上面的讀法，「存檔鈕 → 確認框 → 取消」時，底下的存檔鈕：

- 開框時不離開、沒有訊息，狀態與「已進入」不變，時間停住。唯一收到的是框的 BeginInput 送的 LostFocus。
- 框開著時游標移開，也不送 MouseLeave，仍是滑過狀態，所以被背板變暗成暗黃。
- 框關掉後，游標還在鈕上：只照常送 OnCursor，不再送 MouseEnter。游標已經移開：這時才送 MouseLeave。

G3 時對原因有兩種推論：原版只走目前範圍的元件，或原版框的背板不擋游標。上面的反組譯支持前者，範圍的單位是層。實機的對照見〈和原版對照〉：現有的原版截圖排除了修前的行為，也和「背板不擋游標」不符。

## 做法

- 每次 v14 的輸入更新，先取這次的作用中層：`PE_get_active_controller()`，選法和 `0x53e690` 相同（有指定回指定的層、指定 overlay 回 overlay、沒有指定回最上面那層）。之後只讀這一層的 parts：
  - 按下目標；
  - 游標走訪；
  - 滾輪的候選與 fallback 焦點；
  - 經過時間的累加。
- 不在這一層的 parts：不進入、不離開、沒有訊息，狀態與「已進入」不變，時間停住。
- 層的歸屬沿用 `layer-root` 的 `controller_no`（隨父鏈換層），等同原版「根元件底下的整棵樹」。
- 左鍵槽與從它開始的拖曳：槽裡的 parts 不在這一層時靜默清空（`0x547c00` → `0x548530`）。
- `GetActiveParts` 只回報屬於作用中層的焦點，否則 0。
- 追蹤：`XSYS4_STAGE2_TRACE` 時，作用中層一換就記一行 `S2 input-scope`，最多 2000 行。
- **適用範圍**：只有 v14 的多層模式。單層模式（AIN 沒有 AddController）所有 parts 都在範圍裡，結果和修前相同；v14 之前的遊戲走舊的 `parts_update_mouse`，不動。規則只看「多層模式、v14」，所以會套到任何 v14、會開層的遊戲；依據只有多娜多娜這一支執行檔，別的遊戲沒有實測（語義審查 A7）。

### 移植策略（不是原版行為）【移】

- 移植版只有一套輸入狀態與一個焦點；原版每層一套管理器，焦點是每個元素自己的旗標。原版每次 BeginInput／EndInput 都重設所有層，所以只差在「範圍內換層、兩次 Begin／End 之間」。
- 按下時舊焦點若在別層，移植版仍在按下時送它 LostFocus；原版在清單裡找不到它（`0x545c70`），要到下一次 BeginInput 才送。修後的示範裡，放開存檔鈕後約 40 ms 作用中層就換成框那一層【量】；框的 BeginInput 由框的 `WaitForClick` 呼叫（見〈腳本端〉），推定在開框動畫之後。所以開框動畫期間（框的 BeginInput 之前）若在框裡按下，移植版在按下時就送原鈕 LostFocus，原版到框的 BeginInput 才送；開框動畫中沒有按下時兩邊相同【推】（開框發生在哪一層範圍深度裡沒有追，見探針審查 F4）。
- `GetActiveParts` 的時間點仍是移植版的「立刻」，原版要等下一次元件更新。
- 沒有做：`SetEnableInputProcess`（+0x90）與 `SetEnableInput`（+0xb4）仍是空殼；清單順序沿用 z 順序；別層正在拖曳的捲軸把手仍跟著游標；右鍵、中鍵與其他四個槽本來就沒有；手勢。

### `controller-id` 的 CI12：期望值更正

- 原本的 CI12 寫的是「搬層後點擊落在畫面最上面那層的元件」：把層 A 搬到最上面後，作用中仍是 B，卻期待點到 A；在最底下插入新層 C 後，也期待點到 A。
- 這是「走全部層」的結果，和原版衝突：`0x53e690` 只把輸入給作用中層，搬層（`0x53d740`）不改作用中層，`AddController`（`0x53d3a0`）指定新插入的層【反】。所以搬層後應點到 B，插入 C 後應點到 C。
- 更正後的 CI12：搬層後點到 B；明確指定 A 後點到 A（保留「跟著堆疊」的原意）；插入 C 後點到 C；兩處另外確認繪製順序仍依堆疊。
- 修前只有 CI12 失敗（15 案中 1 案）：搬層後與插入後都點到 A，原因正確。`d7c0d27` 上兩種字集相同，最終 parent `cdff563` 上（預設字集）也一樣。這是 oracle 的更正，不是回歸；其餘 14 案修前修後都通過。

- **探針少一案**：換層（BeginInput）後的第一次更新就在舊層的鈕上按下，舊層的鈕不拿焦點、不被點擊。審查者的暫存案證實修後通過、修前失敗，還沒寫進 `layer-input`；寫進去時把「按下目標用上一次更新的層」加進突變（語義審查 A2；審查者的突變 V3 存活）。
- **讀檔之後的點擊沒有實機走過**：G3b 之後，作用中層與 parts 的層號直接決定按鈕點不點得到。探針 CI11 驗了讀檔後的作用中層與 owner，但九條路線與示範都沒有「讀檔進去之後再點」；舊格式存檔（沒有 ID 區段）讀進來時 owner 換成位置的 ID，也可能讓按鈕落在非作用中層（語義審查 A4）。
- **戰鬥剪影的機制**：要確認的話，在修前的建置上對技能演出那幾秒加 `SceneBattle@HighlightTarget` 的呼叫追蹤。
- **戰鬥的切入子層作用時點技能列**：照原版規則這時只有那一層收輸入，所以在切入動畫中途點技能列不會有反應。原版是不是也這樣，沒有實機對照。
- **例行路線沒有走到的子畫面**：
  - 教學層開著時點底下的據點鈕；
  - 商店購買確認、細節頁、ADV 的按鈕選單；
  - ADV 訊息框的按鈕（AUTO 等）。normal150 只按住 Return、沒有點擊；`GetActiveParts` 的使用者有一個在 ADV（`CMessageKeyControl@CheckKeyClick`），路線的對白逐位元組相同，沒有看到影響。
- **移植策略的界線**（〈做法〉）：
  - 每層各自的輸入管理器：範圍內新增一層時，原版新層前兩次更新會送全畫面 MouseMove，移植版游標沒動就不送；推定遊戲裡只有除錯工具掛全畫面 MouseMove，所以實際流程看不出差別【推】（登記 MouseMove 的腳本呼叫點沒有逐一查）。不經 BeginInput 回到舊層時，原版可能送出舊層留下的點擊，移植版重現不了，LI12 只比新層作用的期間。
  - 左鍵按住時收掉新層，舊層的按下外觀（複審存活的突變 R3）；焦點跨層的 LostFocus 時機（開框動畫期間在框裡按下時兩邊不同，見〈移植策略〉）；`SetEnableInputProcess`、`SetEnableInput`；清單順序；別層正在拖曳的捲軸把手；手勢。
- **片頭判準與追蹤行**：`S2 input-scope` 印在同一次更新的 hover 行之前。若某條路線在片頭載入的那一格才換作用中層，它會先於錨點的 hover 行，新判準會回「無法判定」。這次四趟都沒有發生（語義審查 A3；推送前的證據覆核也確認程式沒改、隱患還在）。要根治，把這一行移到 hover 追蹤之後（程式修改，要重跑 verify 與片頭），或讓判準略過它。
- **提交後沒有重跑示範、沒有重比截圖**：提交後驗收是 before-check、兩組 120 模式、九條路線與片頭三趟；示範、滑過追蹤與截圖比對只在提交前的建置上做過（`src/parts/input.c` 相同）。戰鬥剪影在提交後的 binary 只做了像素掃描與幾張目視。
- **截圖的雜訊對照**：八條例行路線的舊雜訊組已轉成縮圖，改成逐張打開看差最多的幾張。
- **G7 一節排給程式提交的兩項這次也沒做**：命令 1 的程式註解（`PACTEX_CP_CREATE_PIXEL_ONLY` 一段）改成推論、89 的位址寫法統一；這一組只動輸入，移到下一個程式提交。
- **其他遊戲與平台**：別的 v14、會開層的遊戲沒有實測；Windows、Linux 沒有建置。
