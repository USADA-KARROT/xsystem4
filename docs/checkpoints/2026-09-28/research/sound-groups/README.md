# G1：v14 聲音群組、檔案的群組與迴圈點、音量存檔

2026-10-24。程式 `e69dfa3`（`e69dfa34a52613145238d6b66da96f8a4487757d`），基準 `7143b27`（前一組程式 `f693086`），libsys4 固定 `247f544`。提交前、後的預設與 GBK 各 116 個模式 PASS。程式已推送，推送後本機、ls-remote 與 GitHub branches API 三方的雜湊一致。

UI 盤點的 G1 組（盤點項目 S1–S8、S10、S14）。內部音量與片頭聲音的路由（G2）、系統音效的通道池（G11）不在這一組。

## 症狀

使用者 10/19 實玩回報「調整聲音怪怪的」（指的是哪個情境還沒有確認）。之後的盤點在移植版上量到（錄音、畫面與追蹤）：

- 移植版只有三個固定的混音器（Music、Sound、Master），遊戲腳本用的是主 EX 定義的 9 個聲音群組（0 總控、1 BGM、2 音效、3 語音、5 背景語音、6–8 三個語音子群組）。總控與它的靜音沒有作用；BGM 與音效兩條橫桿都控制全部的聲音；語音那條每幀被拉回 0；下面三條顯示 0、拉了沒用，重開又回 0。
- 預設音量一律 100（原版的 EX 是 80，語音 100）；「初始化」寫進 99；音量讀回少 1（53 讀回 52），設定頁每幀讀寫一次，把手就往回退。
- 沒讀聲音封裝裡的 timemap，`GetGroupNumFromFile` 一律回 0，有語音的路線裡 BGM 從來沒有被腳本壓低。
- 設定第 4 頁（聲音）開頁時的把手位置和原版截圖不同。

當時判斷「很可能」、沒有實測的：BGM 每一圈都從 0 秒重播前奏（原版把 LoopBeginSample／LoopEndSample 交給 backend，推定從 Begin 接回；backend 沒追，見下面〈沒追到的〉）；音量與靜音不存檔（原版有 `Volume.sav`），重開回 100；「非作用中時靜音」用的 `SetGlobalFocus` 是空函式；第 7 頁的事件語音靜音（`SetMute(3)`）因為群組 3 不存在而失敗。

### 量測（遊戲資料，只讀）

- 主 EX 的群組表「Ｅ＿聲音群組設定」有 3 欄（群組編號、対応語音群組編號、默認ボリューム）、9 列：預設 80／80／80／100／80／80／80／80／80，對應欄全是 −1，所以 6–8 掛在 3 底下。
- timemap（每個封裝一個 `SoundInfo` 表：Name、Group、LoopBeginSample、LoopEndSample）：音效封裝 1035 列、語音封裝 22427 列，每個封裝檔都對得到一列。依檔名查：音效封裝群組 1 有 44 個、2 有 991 個；語音封裝 6／7／8 各 4081／14568／3778 個；沒有落到 fallback 的檔。兩份都沒有同名列、負群組、9 以上的群組或 End ≤ Begin 的迴圈點；量過的幾首 BGM 都是 End＝總 frame 數−1（舊盤點寫的是「多數」）。
- AIN 的 6 處 `Prepare` 呼叫：只有 BGM 管理器（`sound::detail::CASBGM`）傳 bStreaming＝1，其他 5 處傳 0。
- 腳本啟動時以 `g_AFConfig` 第 18 欄呼叫 `SetGlobalFocus`；設定頁「非作用中時靜音」不勾時這一欄為真，所以平常不會靜音。
- 英文原版在私人前綴裡寫出的 Volume.sav（29 位元組；母片沒有這個檔）和移植版以預設值寫出的逐位元組相同。那一次是正常結束寫出的，屬推論。

### 推論

- 腳本的 `SetMixerVolume` 等是最後一層覆寫：由「Volume.sav 在所有引擎初始化之前讀」推出。
- `+0x31` 是視窗作用中：寫入點 `0x4bdc14`、`0x4be5e7` 有 WM_ACTIVATE 參數的形狀。
- 迴圈點以來源檔的 frame 計，不換算輸出取樣率：backend 候選類別的 getter（`0x6f8020` 一帶、`0x6f8270`）把 sample 換成位元組。
- 重啟後原版會重建聲音引擎、再讀一次 Volume.sav：寫的那一半有反組譯，讀回沒追。
- 只要「播語音時壓低 BGM」有勾，語音音量是 0 時 BGM 照樣被壓低：這是腳本依檔案的群組決定的，原版用同一份腳本，推定相同，原版沒有實測。

## 做法

- **啟用條件**：AIN 恰好是 v14、有 GBK 字元規則（`game_charset_is_gbk()`）、AIN 有 MainEXFile 函式庫、主 EX 有形狀正確的群組表（表名與三個欄名以 GBK 位元組比對，欄與每一列的型別都要對）。其他情況——v13 以下、v15、SJIS、只有 GB18030 旗標、沒有表或表的形狀不對——整段走原本的三個混音器，程式與行為不變。
- **群組圖**：群組 0 是總控，其他群組的串流播在父群組的混音器裡，鏈的乘積由混音器本身完成，通道上不再乘一次。圖在開音訊裝置、解除暫停之前建好，之後不改；重啟保留。
- **整數的音量**：預設值與目前值分開、都是整數，讀回不經 float（53 讀回 53）；SetMixerVolume 夾在 0..100，範圍外照原版回 false；改音量會傳到正在播的聲音。
- **檔案的群組與迴圈點**：音效與語音封裝的 timemap 讀成依名稱的表（名稱照 `0x4195b0` 折疊）。通道依檔名掛群組；沒有列或群組不合法時，`Prepare` 照 bStreaming 掛 1 或 2，其他入口（`PlaySe`、引擎自己的點擊音等）掛 2。BGM 從 LoopBeginSample 起播、在 LoopEndSample 接回。群組通道用新寫的 refill：一個 chunk 可以跨任意次迴圈點、立體聲以 sample 前進、檔尾那個 chunk 照樣播出。舊路的 `cb_read_frames` 不動。
- **焦點**：`SetGlobalFocus` 存旗標，`src/input.c` 把視窗焦點的變化通知混音器；旗標為假且視窗非作用中時整個輸出靜音。
- **Volume.sav**：EX 預設之後、開裝置之前讀；KiwiSoundEngine 新的 `_ModuleFini`（正常結束與 `system.Reset` 都會跑，只存檔、不釋放）寫，格式照原版。沒有存檔資料夾時不讀不寫。
- **v14 的宣告形狀**：SetGlobalFocus、Prepare、GetGroupNum、GetGroupNumFromFile、GetGroupVolume、GetMixerDefaultVolume、GetMixerName 七個經宣告形狀的掛鉤（`hll_shape_select`）換綁定，只認確切的形狀；沒有群組時一律呼叫原本的函式，未知形狀保留原綁定。GetMixerVolume、SetMixerVolume 等仍是原本的函式，差別在混音器層。
- **主 EX 只讀一次**：聲音引擎（初始化較早）和 MainEXFile 共用同一份；`MainEXFile: loaded …` 改在 KiwiSoundEngine 初始化時印出。v14、GBK、有 MainEXFile 但沒有群組表的遊戲只是提早載入，混音器不變。
- **語音時壓低 BGM、背景音效清單**：不另寫自動壓低，靠群組查詢接回遊戲腳本既有的處理（`sound::detail::IsExistSoundList` 依群組過濾清單）。
- **片頭聲音**：路由沒改（G2），影片的串流仍播在 master 上；群組模式下 master 就是群組 0，所以片頭聲音現在跟著總控（預設 0.8）與焦點靜音。
- 沒有新增 VM_ERROR，沒有改全域的預設音量，沒有改 meson 或 libsys4。

### 移植策略（不是原版行為）

- **迴圈**：終點不包含（原版 `0x6f8683` 的位置換算把 End 和 Begin 當同一點，只算弱支持）；只在 `0 ≤ Begin < End` 而且 Begin 在檔內時用，End 夾到檔長；End＝0、End ≤ Begin、任一端為負都整檔循環（原版未知）；最後一圈播到檔尾。
- **timemap**：同名的兩列留先出現的（實際資料沒有同名）；形狀不對的 timemap 整份不用，那個封裝的檔都當作沒有列。
- **Volume.sav**：內容和讀到的或上次寫的相同就不寫；先寫暫存檔、fsync、再改名（原版每次原地寫）；重啟只寫、不重讀（記憶體裡的值就是剛寫的值）。截斷時「這組不套、前面照套」照審查者重讀屬原版行為（上表），程式註解仍寫成移植策略，探針對被截斷的那一組也接受較寬的結果。
- **焦點**：在輸出端把整個輸出清零（原版把各通道增益與 GetGroupVolume 設 0，影片聲音怎麼走沒追）；腳本第一次呼叫 SetGlobalFocus 之前旗標為假、視窗當作作用中。
- **其他**：增益變更從下一個 chunk 生效；表外群組的 GetGroupVolume 只乘根（審查者重讀 `0x4a5e70`：原版 n > 5 時經 `0x4a1e50` 走到群組 3；腳本傳的群組都在 0..8，走不到）；timemap 列的群組為負時 GetGroupNumFromFile 回原值（原版回 2；實際資料沒有負群組）；啟用的表至少要有 3 個群組、每個父群組最多 16 個子群組。

- **舊路的既有問題（不修）**：舊路 `cb_read_frames` 在迴圈點讀完前半之後，讓立體聲緩衝以 frame 而不是 sample 前進，迴圈點所在的 1024-frame chunk 後半被覆蓋、迴圈點前的 frame 數是奇數時左右聲道對調、尾端留下靜音。戰國蘭斯的錄音在本組與基準都和「照原樣重播這段程式」逐 sample 相同。這行從上游 `f58c1b4`（2022-04-15）就在；推測 v13 以下的遊戲每圈有一次爆音（依波形，沒有用耳朵聽）。照規則舊路行為不變，要修另開一組，並重跑 v13 以下的冒煙。
- **其他沒涵蓋的**：第 7 頁的事件語音靜音只在探針驗過群組 3 靜音；BGM 封裝加 BGI 的群組模式路徑（這個遊戲沒有）；多個封裝之間 timemap 的先後；`Fade` 的類型；Rance 9 的 `Sound_Seek`（這份 AIN 沒有宣告）；使用者說的「調整聲音怪怪的」是哪個情境還沒問。G1 之後使用者可能從「拉了沒反應」變成聽到「BGM 太大聲」，G2 應該緊接著做。
- **其他遊戲與平台**：SJIS（包括 v14 英文版）與 v13 以下的遊戲走舊路，沒有群組；Windows、Linux 沒有建置。
