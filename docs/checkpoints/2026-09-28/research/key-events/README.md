## 症狀

修前（parent `3f20f3e`），都只說 v14：

- **右鍵與中鍵對元件輸入沒有作用**：按下不換焦點，放開不送全畫面與焦點元件的 MouseClick（鍵碼 2、4）【量：`input-model` IM4 在修前失敗在「非左鍵的按下沒有選焦點」】。這是 [input-model](../input-model/README.md) 那一組刻意留下的現況。腳本用全畫面右鍵掛的回呼（場景的取消、戰鬥的返回技能選擇）【AIN】因此收不到訊息【推】；修前在這些畫面按右鍵的實機沒有另外量。
- **按鍵事件 15–18 完全不送**：KeyTrigger、KeyDown、KeyPress、KeyUp，全畫面與焦點元件都沒有【量：`key-events` 修前 80 案中 78 案失敗】。頁尾鈕這類按鈕的按下位移是腳本收到鍵碼 1 的 KeyDown／KeyUp 才做的【AIN】，所以修前不會動【推】。
- **拖曳通知（7、8、10）不送**，拖曳中按另一顆鍵也不取消；訊息佇列的變數只有 4 格，放不下 Draging 的五個整數【量：探針；讀程式】。
- **橫桿的軌道**：內部元素的按鍵事件與點擊不轉給外層的捲軸元件【量：`key-scrollbar` 修前 8 案全部失敗】。
- **SDL 鍵盤**：左右兩顆 Shift、Ctrl 共用一個鍵狀態，放開其中一顆就算放開；數字鍵盤 Enter 在父版本沒有對應到任何 VK（所以 v14 也不是 Return）【量：探針；讀程式】；v14 的滑鼠鍵取樣不看失焦與最小化（讀程式）。

## 原版依據

### 反組譯看到的【反】

位址都是中文版解殼檔。Codex 的補查是主要來源，Claude 收尾時重讀了下面標「重讀」的段落。

**按鍵表與事件 15–18**

- 固定 80 個 VK 的表（在 `0x575060`–`0x57521f` 建立，同一段也清空 80 個舊的狀態位元組）：左右中滑鼠鍵、Backspace、Tab、Enter、Shift、Control、Esc、空白、翻頁與方向等導覽鍵、Insert、Delete、數字、A–Z、數字鍵盤與 F1–F9；沒有 Alt 與 F10 以上。取樣用 `GetKeyState` 的最高位元（`0x574ded`–`0x574dfa`）。表裡的 Shift、Control、Enter 用的是通用的 VK（`0x10`、`0x11`、`0x0d`），沒有分左右的 Shift、Control。通用的 Shift、Control 涵蓋左右兩顆，主鍵盤與數字鍵盤的 Enter 同為 `0x0d`：這兩點是 Windows VK 的慣例，不是反組譯讀到的。
- 同一輪先收集，再整批依序送 Trigger(15) → Down(16) → Press(17) → Up(18)（`0x574d50`；焦點元件由 `0x578580` 分派，全畫面由 `0x547940`）。第一次按下的那一輪同時有 15、16、17。
- 一份鍵表共用一個重複時鐘：初次 500 ms、之後 80 ms，判斷是嚴格大於；有新鍵或全部放開時回到 500；一次大的時間跳躍只送一輪（`0x574d53`–`0x574d7f`、`0x574f12`–`0x574fc1`）。
- 全畫面的四批在游標、滾輪與點擊之前（`0x547e16`）；焦點元件的放開先送 MouseClick 再送 KeyUp（`0x5788d0` 末段）。
- 焦點元件的鍵表是元素自己的（`0x578580`、`0x574d50` 用元素 `[edi+8]` 的表，80 個一位元組的鍵旗標在元素的 `+0xc`–`+0x5b`）。更新裡沒有任何元素是焦點時，`0x545c70` 回傳管理器的根元素，`0x54836a` 對它跑 `0x578580`（見〈推論〉）。

**滑鼠三鍵、焦點與全畫面放開**

- 按下時先清三個來源槽，有目標時依左 → 中 → 右的優先只設一個槽（左 `+0x1ec`、中 `+0x200`、右 `+0x208`；`0x546926`–`0x546aa2`）；任何一顆鍵的新按下都可以換焦點（焦點是元素的 `+0x1b4`）。
- 每次放開先送全畫面 MouseClick，順序是左 1、右 2、中 4，只在取得得到游標位置時（`0x548024`–`0x548133`）。
- 元件的右／中鍵 MouseClick：可點擊、游標在它上面（`+0x1ac`）、位置有效時才送，鍵碼 2 或 4；不播點擊音、不寫 `+5`，所以不設 `GetClickNumber`（`0x578917`–`0x578a52`，右／中鍵的分支 `0x5789e8`–`0x578a34`；左鍵在 `0x5789a0`–`0x5789bc` 播音）。
- 換焦點時先更新新焦點，再把舊焦點的鍵表整份放掉，走完整的放開（`0x54836f` → `0x578810` → `0x574fd0`；`0x548367`–`0x54837c`）。
- 左鍵 Trigger 在焦點、entered、可點擊時設按下標記 `+4` 與按下外觀（`0x578650`–`0x578675`）；左鍵 Up 清它，entered 且位置有效時回滑過、沒有 entered 時回普通（`0x578944`、`0x578997`、`0x5789dd`）。走訪每次依 `+4` 設按下外觀（`0x577b90` 的 `0x577c28`–`0x577c38`，重讀）。
- 滑鼠三鍵的取樣也經啟用閘門：每顆鍵先問 `0x496670` 與 `[0x87f8a0]+0x1c`，都為真才 `GetKeyState`，否則取樣成放開（`0x547e88`–`0x547f2d`；放開邊緣與全畫面點擊 `0x547f81`–`0x548133`；重讀）。BeginInput 取樣三顆鍵時也經同一個閘門（`0x546100`–`0x54618c`，中鍵 `0x546175`–`0x54618c`；重讀）。按下的判斷是管理器上次取樣的 `+0x40` 為放開、這次按住（`0x547f2d`–`0x547f4a`），取樣寫回 `+0x40`–`+0x42`（`0x547fbd`–`0x547fc5`）。

**管理器、作用中的層與槽**

- 只有作用中那一層的管理器在跑（`0x53e690` 選層，`0x53c5b0` 收集清單），它每次更新清掉元素不在本層清單裡的槽（`0x547c90` 對五個槽呼叫 `0x547c00`，不在就 `0x548530`）。槽存的是元素本身（`0x5462bc`），所以同一個號碼放掉又重建的元件不是原本的來源。
- `SetActiveLayer` 只依 ID 找到 controller、寫作用中層（`0x57ba47`–`0x57ba60` 呼叫 `0x53d870`，再寫作用中層的欄位），不 begin 被指定的管理器；`AddLayer` 會（`0x53d3a0` → `0x546030`）（重讀）。

**拖曳通知與五個整數**

- 一般移動時，左鍵跨過門檻（預設 10，曼哈頓距離）才開始；可移動旗標（`+0x1a6`）只管座標更新，事件照送；中右鍵沒有門檻（`0x546c02`–`0x546d90`）。門檻由設定讀，非正值時用 10（`0x545a3f`）。
- 左鍵拖曳只有在游標這一次有移動時才寫來源的位置：`0x547e5f`–`0x547e84` 算出移動旗標，由 `0x5482c6` 當最後一個參數傳進 `0x546890`，在 `0x546c41`–`0x546c56` 閘住位置寫入（重讀；呼叫端推了 15 個 dword，最後推的是隱藏的回傳指標，移動旗標正好落在被呼叫端的 `[ebp+0x40]`）。
- 一般放開只對「這顆鍵的拖曳開始過」的來源送 DragEnd（`+0x1e0`–`+0x1e2`，在 `0x5474c3`、`0x54753e`、`0x5475ae` 測）。左來源沒有 drop 目標時 mode 1、有的時候 0（`0x5474d4`–`0x5474e6`），中右都是 0（`0x547460`、`0x547530`、`0x5475a0`）；移植版不建 drop 目標，所以左鍵一直是 1。
- Draging(8) 有五個 int（起點 x、y，目前 x、y，鍵），DragEnd(10) 兩個 int（鍵、mode）（`0x5781b0`；mode 的序列化 `0x577660`）。AIN 的 type 8 宣告也是五個 int【AIN】。

**交叉按鍵取消**

- 右或中鍵新按下而左槽有來源 → `0x5462b0`；左或右新按下而中槽有來源 → `0x5463c0`；左或中新按下而右槽有來源 → `0x546470`。條件只要槽不空，不要求已移動或可拖（`0x548153`–`0x5481b0`）。
- 取消一定送 7（還沒開始時）、8、10，起點與終點都用按下時的位置；別顆鍵按下是 mode 2，沒有位置的放開是 mode 3。只有可拖（`+0x1a6`）的左來源還原座標（`0x5462cf`–`0x5462ec`）；右／中的取消不寫位置。
- 取消後設 `+0x1fc`，三顆鍵全放開才清（`0x548206`–`0x548218`，在 `0x548278` 讀它之前）。期間略過換焦點與游標走訪，但全畫面放開、滾輪與焦點的鍵表照常（`0x548278`、`0x548343`–`0x54837c`）。所以取消的那次按下不換焦點。
- 取消用 `0x548530` 清槽：和一個空的暫存交換、再遞減舊的參照計數，不寫元素的焦點、entered、按下標記或鍵表（左槽 `0x54636e`–`0x546378`；重讀）。左取消另外清已開始拖曳的旗標、離開 drop 目標（`0x5784b0`）。
- 沒有位置時，每顆鍵的放開只取消自己的槽（`0x5481bb`–`0x548201`）；沒有位置而左來源是焦點時，離開它（`0x548311`–`0x548339` → `0x5476b0` → `0x577cf0`，`0x5476dc`–`0x5476ec`；`0x577cf0` 在 `+0x1e3` 為 0 時清 `+0x1ac`，`0x577cf6`–`0x577cfd`、`0x577d91`）。同一段的 `0x548324` → `0x547740` 也離開滑過中的 drop 目標（移植版不建 drop 目標）。

**輸入範圍的開始與結束**

- 範圍結束（`0x5461a0`）先清全畫面鍵表（`0x547ad0`），再對五個槽（`+0x1ec`、`+0x200`、`+0x208`、`+0x210`、`+0x218`）的元素各呼叫一次 `0x577af0`，然後清空五個槽（重讀）。`0x577af0` 清的欄位包含 `+4`、`+0xc`–`+0x5b` 的 80 個一位元組的鍵旗標、`+0x1ac`、`+0x1b0`、`+0x1b4`、`+0x1b8`／`+0x1bc` 等，不送 Up。不在槽裡的元素不碰。`0x53e8b0` 對每個 controller 的管理器都跑 `0x5461a0`；開始時 `0x53e830` 對每個還沒 begin 的管理器跑 `0x546030`（重讀）。
- 開始（`0x538060`；`0x564cc0` 以 false 呼叫）只對還是焦點的元素送 LostFocus、清 `+0x1b4`（重讀）。

**橫桿的軌道與把手**

- 軌道明確設成可點擊（`0x574648`），把手初值不可點擊（`0x550a2f`）；子元素繼承外層的穿透游標、不繼承可點擊（`0x573b20`、`0x573baa`）。走訪先把手後軌道（`0x4f3370`、`0x5471d0`），所以不穿透游標的把手擋住軌道。
- 捲軸把內部元素的 15–18 與 type 4 原樣轉給外層元件的 provider（`0x572ba0` 的 default）；左鍵的 Trigger／Down／Up 另由 `0x572c30`／`0x572e00`／`0x572f50` 處理，`0x572e00` 不看取消旗標。放開讀內部元素快取的 entered（`0x5788d0` 讀 `+0x1ac`，不重做命中測試）。

**鍵盤的啟用閘門**

- WM_ACTIVATE 的快取：啟用且未最小化才為真；每次變成啟用時先 `SetKeyboardState` 全清（`0x4bdaf0`–`0x4bdb28`），WM_SETFOCUS 也清（`0x4bcb8c`–`0x4bcbaf`）。閘門為假時鍵表照樣取樣成「放開」，所以按著的鍵會送 Up。

### 腳本端【AIN】

- 場景的全畫面右鍵回呼：場景是作用中的那一層、沒有在轉場、RClickEvent 不是空的時候，先播取消音再呼叫它（`SceneContext`）。戰鬥另有自己的訂閱：作用中而且不在換人時呼叫 `BattleActionPanel@BackToSkill`（`SceneBattle`）。兩者都是全畫面右鍵的獨立訂閱；沒有看到跨場景或整幀的去重旗標，所以「同一次右鍵只關一層」不是靜態能證明的，要實機看。
- 頁尾鈕這類按鈕的 provider 只處理鍵碼 1 的 KeyDown／KeyUp，按下位移由腳本的狀態 3 驅動，位移量是腳本自己的。
- 訊息的分派把 type 15、16、17、18 依序對到 KeyTrigger、KeyDown、KeyPress、KeyUp 的回呼；每則只讀一個 int 鍵碼，讀完再 Pop，之後才呼叫回呼，回呼另補元件號碼。type 4 讀 x、y、鍵碼，鍵碼 1、2、4 分到左、右、中的回呼。
- 對話中右鍵隱藏信息窗口、中鍵已讀跳過走的是腳本自己輪詢（`CASClick`、`AFL_IsKeyDown`），不靠佇列訊息（見 [key-map](../key-map/README.md)），所以這一組不改它們的路徑。

### 推論【推】

- 腳本端只確定了消費的方式（上一節）；原版什麼時候產生 15–18、重複的節奏、拖曳取消時有幾則訊息，AIN 決定不了，全部依上面的反組譯。探針 `key-consumer` 用原版的 AIN 分派程式碼驗消費端的讀法（Pop 之前讀完、收件者正確），不驗原版的產生端。
- 焦點元件的鍵表與滑鼠鍵用的是不是同一個啟用閘門物件，沒有逐一對照。
- 取消之後左鍵仍按著時，原版的捲軸把手仍跟著游標走（由 `0x572e00` 不看取消旗標推得）。
- 被取消的左來源跨過 EndInput 之後的外觀：見〈和原版仍不同的地方〉第 1 條。
- **切換作用中層**（由上面〈管理器、作用中的層與槽〉推得，沒有原版畫面或動態量測）：按住左鍵時用 `SetActiveLayer` 切到別層，舊層的管理器不跑、保留它取樣的按鍵、它的槽與元素的焦點旗標；所以在別層放開之後，舊層再跑時會再送一次全畫面 KeyUp＋Click，焦點元素自己的 KeyUp 與 Click 也在那時送。焦點被另一層的按下移走時，`0x545c70` 只在那一層的清單裡找，舊元素的 `+0x1b4` 留著，它那層再跑時照樣送 KeyUp 與 Click。另一層的 BeginInput 經 `0x5461a0` → `0x577af0` 靜默清掉舊層槽裡元素的鍵表。被指定的那一層沒有 begin，拿上次取樣的「放開」來比，按住的鍵在那裡算新的按下（焦點、Trigger，在那裡放開時被按的元素的 Click）。
- **沒有焦點時的根元素**：`0x545c70` 找不到焦點時回根、`0x54836a` 對它跑 `0x578580`，推論原版的根元素會收到自己的按鍵事件（`+0x1ac` 允許時還有 MouseClick）；腳本讀不讀根的訊息沒有追。

## 做法

所有新邏輯的閘門都是 `ain->version == 14`（恰好 v14，不分字集；SJIS 的 v14 遊戲也走新路徑，沒有實測）。版本 15 以上沿用 G8 之前的輸入路徑，只有兩處小改：`S2 input-scope` 追蹤行移到 hover 追蹤之後（下面〈追蹤〉），訊息佇列的變數由 4 格改成 5 格、變數數為負時夾成 0（下面〈拖曳〉；讀程式：五個整數只有 v14 的 Draging 會送，沒有呼叫者傳負數，所以行為不變）。v13 以下的輸入路徑、`input_is_active()` 對非 v14 回傳原本的 `keyboard_focus`，探針的 v13 守衛照舊通過【量】。

- **三個來源槽**：左、中、右各一個，和焦點元件的鍵表分開；按下時依左 → 中 → 右只設一個；任何一顆鍵的新按下都可以換焦點，`GetActiveParts` 跟著三顆鍵。槽記的是元件本身，元件被釋放時清掉它的槽。
- **全畫面放開**：左 1、右 2、中 4 的順序，各送一筆 MouseClick，位置無效時不送。
- **鍵表**：全畫面一份、每個元件一份（`struct parts` 多一個 `v14_keys`，80 格加時鐘與門檻，不存檔），表序照原版；每次輸入更新先送全畫面的四批，再處理游標、滾輪與點擊，最後更新焦點的鍵表、再 flush 換掉的舊焦點。焦點的放開先送 MouseClick 再送 KeyUp；右／中鍵的元件點擊不播音、不設 `GetClickNumber`。
- **拖曳**：DragBegin(7)、Draging(8)、DragEnd(10)；左鍵門檻 10、中右沒有門檻；可拖的左來源照位移更新座標，只在游標有移動的那一格寫。訊息佇列的變數由 4 格改成 5 格（`src/hll/pe_v14_message.c`），變數數為負時夾成 0；這兩點不看版本，版本 15 以上也生效。
- **交叉取消**：在換焦點與走訪之前處理；mode 2／3；只有可拖的左來源還原座標；取消後到三顆鍵都放開之前略過換焦點與走訪，全畫面放開、滾輪與焦點鍵表照常。左取消時若有 drop 目標，送 DropLeave(14) 並離開它（v14 現在不建立 drop 目標，這個分支走不到）。
- **輸入範圍的結束**（審查後修正）：v14 只重設三個來源槽裡的元件，被取消的來源因為已經不在槽裡，保留焦點、entered 與鍵表，下一次 BeginInput 送它 LostFocus（`0x5461a0`、`0x548530`、`0x538060`）。修正前也重設「按下中的元件」，取消後按著鍵結束輸入時會靜默清掉它的焦點；版本 15 以上保留原本的做法。
- **切換作用中層**【移】：作用中的層一換就清三個槽與取消抑制；焦點與焦點自己的鍵表保留，別層作用期間不取樣、不 flush。所以在別層放開的左鍵，焦點要到自己那層再跑的第一格才收到 KeyUp 與（entered 時）MouseClick，`GetClickNumber` 是它，沒有第二次全畫面 Click（取樣的按鍵是共用的）；切回後才放開則在放開時照常。別層不把按住的鍵當按下。探針 KE79、KE80 釘的是這個移植版行為。
  > 2026-11-02 更新（G8b，程式 `d698d6a`）：換層不再清三個槽：每層保留自己的槽、左鍵按下標記與焦點，舊層的焦點在別層的按下時不再收到 LostFocus，BeginInput 與 EndInput 靜默重設每一層槽裡的元件；取樣的按鍵與取消抑制仍共用，所以「別層不把按住的鍵當按下」與「沒有第二次全畫面 Click」照舊，KE79、KE80 的期望不變、只改註解。見 [layer-switch](../layer-switch/README.md)。
- **橫桿**：每個元件多兩個暫態欄位（軌道是不是焦點的內部元素、軌道是不是 entered），v14 的點擊改看焦點的內部種類，不再只看外層的可點擊與滑過；15–18 與軌道的點擊轉給外層元件。
- **SDL 鍵盤**（`src/input.c`）：左右 Shift、左右 Ctrl、Return 與數字鍵盤 Enter 各記自己的狀態，VK 取 OR；v14 的數字鍵盤 Enter 當 Return（只取上游 `6d05546` 的這一半，NumLock 關閉時轉方向鍵的那一半沒有搬：macOS 的 SDL 起始時沒有 NumLock 狀態，照搬會讓數字鍵盤預設變成方向鍵）；FOCUS_GAINED／LOST 加 MINIMIZED、RESTORED、MAXIMIZED 近似原版的閘門，變成可用（或在作用中再收到 FOCUS_GAINED）時清鍵盤。
- **追蹤**（`XSYS4_STAGE2_TRACE`，不影響行為）：提交後修正輪起，範圍內每次左鍵放開至少一行 `S2 click`，沒有元件接下時 `target=0`（和 G8 之前相同）。不是在左鍵放開那次更新送出的元件點擊，行尾加 `(late)`：換焦點時被 flush 的舊焦點、跨層保留的焦點在自己那層再跑時才放開、元素重新成為焦點時自己的表還有左鍵。一次放開可能有兩行（`target=0` 與之後的 `(late)`），所以行數不一定等於點擊數。另外（不是修正輪改的，本機第一次提交裡就有）：作用中層一換就記的 `S2 input-scope` 行從同一次更新的 hover 追蹤之前移到之後（G3b 語義審查 A3 的建議，程式註解寫明保留第一行 hover 當路線開頭的錨點）：片頭層在載入那一格才成為作用中層時，它不會再排在片頭判準的錨點之前。版本 14 以上的多層模式都走這一段；提交後的 verify 與片頭三趟都在這個順序下跑過，三趟的錨點都是片頭元件的滑過行【量】。
- 順手改寫 `src/parts/input.c` 檔頭移植策略的兩句註解（G3b 推送前公開內容覆核 P-M1、P-L1 排給下一個碰這個檔的提交）：確認框那一句改成「輸入範圍內新建的 controller 在明確的 BeginInput 之前就可能收到按下」，接著寫開框動畫期間、框的 BeginInput 之前在框裡按下時，原鈕的 LostFocus 移植版在按下時送、原版到框的 BeginInput 才送（標成推論）；`0x53c830` 那一句改成「`0x53c830` 會再排序清單（鍵沒追）；移植版用 z 順序（畫的順序）」。
  > 2026-11-02 更新（G8b，程式 `d698d6a`）：確認框那一句又改寫了：開框的按鈕仍是舊層的焦點，到框的 BeginInput 才收到 LostFocus，和原版推論相同（行為跟著改了）。見 [layer-switch](../layer-switch/README.md)〈做法〉。
- 「沒有位置時離開左來源」那一段的註解帶原版位址：`0x548311`–`0x548339` → `0x5476b0`（`0x5476dc`–`0x5476ec` 呼叫 `0x577cf0`），`0x548324` → `0x547740` 也離開滑過中的 drop 目標（移植版不建），放開時 `0x5462b0` 已先清掉槽（`0x5481cb`），`0x577cf0` 再讀位置、沒有位置時是 (0, 0)（區域變數先清，`0x577d1d`；失敗時寫什麼沒有追）。

### 移植策略（不是原版行為）【移】

- **單一管理器、單一焦點**：原版每個 controller 一份管理器、焦點與五個槽，複合元件有多個內部元素；移植版只有一份，捲軸的內部元素只用兩個暫態欄位表示，沒有各自的鍵表。外層捲軸的滑過穿透沒有做。換到別層時清槽、丟掉上一層的取消抑制，回到原層也不恢復（原版各層的管理器各自保留）；焦點與焦點的鍵表跨過切換保留（上一節）。
  > 2026-11-02 更新（G8b，程式 `d698d6a`）：槽、左鍵按下標記與焦點改成每層一份（換到別層不再清槽，回到原層時取回）；取樣的按鍵、全畫面鍵表、儲存的位置與取消抑制仍只有一份，換到別層時丟掉上一層的取消抑制、回到原層不恢復照舊；捲軸內部元素的表示不變。見 [layer-switch](../layer-switch/README.md)。
- **拖曳門檻**只取預設 10，沒有接原版從設定讀值的來源。
- **SDL 的閘門與聚合**：不是原版 OS 訊息逐條等價；子視窗、模態對話框等情境沒有比對。回焦時實體鍵仍按著：原版清掉之後靠 `GetKeyState` 重新取樣【反】，移植版要等下一個 SDL 按鍵事件才會再變成按下【推，沒有實機】。啟用清鍵盤只在事件之後是作用中時做。
- **停用的按鈕**擋右／中鍵的元件點擊，和左鍵一樣是移植版的權宜（原版輸入更新沒有對應：`0x528690` 只清音效名、每幀把內部元件設成可點擊）。
- **沒有做的原版行為**：一般的 drop 目標選取、Dropped(13)、Dragged(9)、swipe、雙擊（G12 的範圍）。
  > 2026-11-02 更新（拖放範圍的唯讀研究，隨 G9 的文件公開）：遊戲本體只用左鍵拖曳的 7、8、10；drop 目標的選取、Dropped(13)、Dragged(9)（派送的分支裡沒有 9）與右／中鍵拖曳在這個遊戲沒有消費者，從 G12 的範圍刪掉；G12 縮成 G12a（讀 `[ドラッグ]`、驗消費端、編隊與人材清單並排）與 G12b（滑動）。雙擊不在那份研究的範圍。見 [drag-scope](../drag-scope/README.md)。

## 和原版仍不同的地方

1. **被取消的左來源跨過 EndInput 的按下外觀**【推】：原版的 `+4` 只由左鍵 Trigger 設，左取消與範圍結束（只動槽）都不清，走訪每次依 `+4` 設按下外觀；所以 End 與 Begin 之後，這個元素只要還是 entered，原版顯示按下，要等它再成為焦點、處理到左鍵 Up 才改回。移植版只有一個「按下中的元件」，每次範圍結束都清，Begin 後馬上是滑過【量：探針印出的狀態】。沒有原版畫面。
2. **停用按鈕的右／中鍵**（上一節）。
3. **SDL 的閘門與聚合、回焦時仍按著的鍵**（上一節）。
4. **單一管理器、單一焦點，捲軸內部元素的表示**（上一節；2026-11-02 起槽與焦點每層一份，取樣、全畫面鍵表與取消抑制仍共用，見 [layer-switch](../layer-switch/README.md)）。
5. **拖曳門檻**只取預設值。
6. **drop、Dropped、Dragged、swipe、雙擊**沒有做。
   > 2026-11-02 更新（拖放範圍的唯讀研究，隨 G9 的文件公開）：drop、Dropped、Dragged 在這個遊戲沒有消費者，不做；swipe 排進 G12b。見 [drag-scope](../drag-scope/README.md)。
7. **對話右鍵隱藏時留下的按鈕與說話標記**：原版一起隱藏，移植版仍留著。既有差異（[key-map](../key-map/README.md) 就記過），不是 G8 造成的，也不在 G8 範圍。
8. **切換作用中層時保留的焦點**【推】：移植版只在焦點那層再跑時送延遲的 KeyUp 與 Click（KE79），推論的原版另有四點（〈推論〉）：在另一層放開之後，舊層的管理器再送一次全畫面 KeyUp＋Click；焦點被另一層的按下移走時，元素的焦點旗標留著，它那層再跑時送 KeyUp 與 Click；另一層的 BeginInput 靜默清掉舊層槽裡元素的鍵表；被指定的那一層把按住的鍵當新的按下。移植版四點都沒有做，也都沒有和原版對照。
   > 2026-11-02 更新（G8b，程式 `d698d6a`）：四點中的第二點（焦點被另一層的按下移走時保留焦點旗標，它那層再跑時送 KeyUp 與 Click）與第三點（另一層的 BeginInput 靜默清掉舊層槽裡元素的鍵表）照原版推論做了；第一點（舊層的管理器再送一次全畫面 KeyUp＋Click）與第四點（按住的鍵在被指定的那一層算新的按下）仍不同，排進「每層取樣與取消旗標」一組。見 [layer-switch](../layer-switch/README.md)。
9. **殘留的左鍵位元**【量：審查者的隔離診斷案；讀程式】：G8 帶進來的錯誤（父版本沒有元件鍵表）。上一條保留的鍵表只在那個元素一直是唯一的焦點、而且沒有 BeginInput 清掉焦點時才有效；焦點被另一層的按下移走，或被那裡的 BeginInput 清掉時，左鍵位元留在那個元素的表裡（它的槽在切換時已清，所以範圍結束的重設也碰不到它）。之後右鍵或中鍵讓它成為焦點，它收到左鍵的 KeyUp 與 MouseClick（`GetClickNumber` 是它，追蹤行是 `(late)`）；左鍵讓它成為焦點，則沒有左鍵 Trigger 與第一個 Press。觸發要「按住時用 `SetActiveLayer` 切層（不經 Begin／End）→ 在別層放開 → 焦點被移走或 BeginInput → 切回 → 再按同一個元素」；自動關閉的子層走 EndInput，會清表。推論的原版在兩半不同（BeginInput 那一半靜默清表；焦點被移走那一半在切回時送延遲的 KeyUp 與 Click），要照原版分兩半做，排成下一組 G8b。右鍵的情形由審查者的診斷案量過，中鍵是讀程式推論。
   > 2026-11-02 更新（G8b，程式 `d698d6a`）：已修。焦點被另一層的按下移走那一半，舊層保留焦點、切回時送延遲的 KeyUp 與 Click；BeginInput／EndInput 那一半，仍在舊層槽裡的元件被靜默重設（右鍵、中鍵槽與鍵盤鍵一起）。見 [layer-switch](../layer-switch/README.md)。
10. **沒有焦點時根元素的按鍵表**【推】：推論原版會對管理器的根元素跑它自己的鍵表，移植版那時只跑全畫面的表。

## 驗證

### 探針

說明與各案內容見 [harness](../../harness/README.md) 的三節。資料全部合成，不用遊戲資產；正式的 `PE_UpdateInputState`、`PE_UpdateComponent`、BeginInput／EndInput 與 v14 訊息佇列，SDL 的部分送真的 SDL 事件。

- `key-events`（80 案）：鍵事件與點擊的完整多重集合與順序、80 鍵表、重複時鐘、換焦點與 flush、取消的各種組合（左右、左中、中左、中右、右中、優先序、抑制、視窗外 mode 3、已移動與未移動、不可拖）、拖曳門檻、範圍的開始與結束、啟用閘門、圖層、SDL 的聚合與啟用（移植策略）。KE8 是 v13 守衛。KE47–KE78 是收尾時補的子案（多數為存活突變而補，也含守收尾時的引擎修正與審查發現的子案），期望值來自上面的反組譯（KE57、KE58、KE70 守的是 SDL 的移植策略），時點離界線至少一格。KE79、KE80 是提交後修正輪補的（切換作用中層時保留的焦點；每格比整格的事件總數），期望值是移植版現行的行為：「別層不把按住的鍵當按下」與「不再送第二次全畫面 Click」也在期望值裡，推論的原版在這幾格不同（〈和原版仍不同〉第 8 條）。
- `key-scrollbar`（8 案）：軌道與把手的 15–18 轉送、軌道的點擊、把手擋住軌道與穿透、左鍵按著時按右鍵後把手仍收到 KeyDown。
- `key-consumer`（2 案，守衛）：原版 AIN 的分派與回呼程式碼怎麼讀佇列（Pop 之前讀完、恰好一次 Pop、收件者、非滑鼠鍵不當成點擊），以及 provider 的按下狀態（左鍵 Down 進狀態 3，右／中鍵不擾動，放開回 1 或 2，停用時不反應）。只控制五個訊息來源的 HLL，不替換任何指令。
- 既有模式：`input-model` IM4 與 `auto-input` AU6 的期望改成原版的右／中鍵行為；`base-ui-review`、`config-widgets`、`hover-events`、`scrollbar-knob` 的讀取函式在 v14 略過 15–18 與拖曳通知（各自只驗原本的訊息家族，新的家族由 `key-events` 讀未過濾的佇列驗）。
- 追蹤行（`S2 click`）沒有探針斷言；它的語意由路線的逐下對齊與探針裡印出的行（KE79 一次放開印 `target=0` 與之後的 `(late)` 兩行）檢查。

3. 沒有位置時離開左來源、焦點是捲軸軌道（`0x548311`–`0x548339` → `0x5476b0` → `0x577cf0`，在內部元素的 `+0x1e3` 為 0 時清它的 `+0x1ac`）：之後在別顆鍵的取消抑制中放開左鍵不得點擊軌道；要穿透游標的把手、一格無位置與那次被抑制的放開。
4. 停用按鈕擋右／中鍵元件點擊的移植策略（左鍵那條是 `input-model` 的案）。
5. 放開時讀捲軸內部元素快取的 entered（`0x5788d0` 讀 `+0x1ac`，不重做命中測試）：移植版沒有會重算它的分支，`key-scrollbar` 守「必須是 entered」。
6. 舊焦點的捲軸角色存在各自的元件上，被 flush 時還按著滑鼠鍵（一顆鍵從 Begin 按著、另一顆按下換焦點）。
7. 右／中鍵放開不播點擊音（`0x5789e8`–`0x578a34` 只送 Click；左鍵在 `0x5789a0`–`0x5789bc` 播），這個模式沒有音效計數器。
8. SDL 的啟用清鍵盤只在事件之後是作用中時做（`0x4bdaf0` 的移植策略）：非作用中時別的視窗事件清不清，只有腳本自己在非作用中讀鍵盤狀態看得出來。
9. 沒有焦點時管理器根元素的按鍵表（`0x545c70` 找不到焦點時回根，`0x54836a` 對它跑 `0x578580`）：推論原版的根會收到自己的按鍵事件，移植版只跑全畫面的表；腳本讀不讀根的訊息沒有追。
10. 切層時保留的焦點在另一層被移走或被 BeginInput 清掉之後，元素鍵表殘留的左鍵（上面〈和原版仍不同〉第 9 條）。刻意不寫子案：釘移植版的行為等於把錯誤寫成期望值，釘推論的原版又沒有原版的量測；由 G8b 處理。
    > 2026-11-02 更新（G8b，程式 `d698d6a`）：已處理（KE81–KE123）。檔頭的第 10 條改寫成每層管理器移植版沒有照做的部分，另加兩條（按住跨過切回時游標的位置、被拿掉的層留下的表項），共 12 條；見 [layer-switch](../layer-switch/README.md)〈Not covered〉。

另外：`key_cancel_fixture.inc` 不涵蓋 drop 目標的離開（14）；`key-scrollbar` 不涵蓋左鍵按下／放開的幾何時序、內部元素的鍵盤焦點變化、外部 listener、drop-hover 與 swipe 的例外；`key-consumer` 驗的是消費端的讀法，不是原版的產生與時序，槽註冊的涵蓋仍開著。

## 沒做與沒驗證

- **錄音**：右／中鍵放開不播點擊音（反組譯讀到原版也不播，`0x5789e8`–`0x578a34`；這是沒有驗證的相同點，不算差異）、道具頁右鍵的取消音（場景的右鍵回呼會播）都沒有錄音比對。
- **SDL 鍵盤聚合、最小化與回焦**：只有探針；例行路線與戰國蘭斯的自動輸入不經 SDL 鍵盤事件（排程的 `key` 步驟直接寫引擎的鍵狀態）。

- **拖曳中右鍵後在對話上放開左鍵、對白推進一頁**：原版沒有量。
- **實測示範**都在提交後修正輪之前的建置上做，修正輪之後沒有重跑。
- SJIS 的 v14 遊戲、其他平台（Windows、Linux）沒有跑。
- 突變：加一行敘述型的突變（例如讓右／中鍵放開也播音）沒有列舉；runner 不解析的模式（例如 `hover-events`）沒有跑突變；提交後修正輪的必殺突變只在 `key-events` 跑。
