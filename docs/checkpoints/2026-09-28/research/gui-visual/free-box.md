# 自由盒的原點偏移與 user component 的原點傳遞（庫房資訊面板）

2026-10-07。程式 `b05ff2d`。

## 症狀

庫房畫面右上角的資訊面板（TP、房間、人材、庫房的數字）在 xsystem4 落在畫面外，只在右上角露出一小塊洋紅色；原版完整顯示。

## 根因

面板是一個 user component，原點模式 3（右上），座標 (1258,19)。原版把 user component 的原點模式交給它的內容根，內容根是自由排版的盒（レイアウトボックス 類型 0），自由盒再依自己的原點模式把子元件整體位移：原點在右上，內容就向左延伸。xsystem4 兩件事都沒有做，內容一律從座標向右下延伸。

這是前幾組之前就有的缺陷；[layout-box](layout-box.md) 那一組把它列為未實作。

## 原版依據（靜態反組譯）

| 項目 | 位址 | 內容 |
| --- | --- | --- |
| user component 的更新 | vtable `0x80f0b4` +0x14 = `0x4e57d0` | 取第一個子元件，把自己的原點模式（+0xa8）寫給它，沒有其他條件（`0x4e5815`）。尺寸取第一個子元件的（`0x4e5880`），自己不在游標下 |
| 自由盒排版 | `0x5499e0` | 以 GetSize(1) 取得 W、H，依盒自己的原點模式算偏移（表 `0x549ba4`：0、−W/2、−W；`0x549bbc`：0、−H/2、−H；半值朝零截斷；範圍外的模式為 0），寫進每個直接子元件的 +0x238、+0x23c（`0x549b28`、`0x549b37`），隱藏的子元件也寫 |
| 自由盒尺寸 | `0x54a9f0` → `0x54aaf0` | 顯示中的子元件最大的右緣與下緣；只讀子元件的座標（+0x94／+0x98），不含偏移；寬或高不為正時是 0x0 |
| 位置的讀取 | `0x5377e0`、`0x537870` | 四個呼叫點（`0x53567a`、`0x535659`、`0x537b2f`、`0x537b4f`）都把 +0x238／+0x23c 加到座標上。偏移因此與座標在同一個空間：受盒與祖先的倍率、翻轉影響，子孫跟著移動 |
| 時機 | `0x549970` | 盒顯示時每幀排版。主 update 期間盒尺寸用快取（`0x54a9f0`，旗標由 `0x54b510` 設），對自身可見的盒等於每幀重算。`Parts_SetLockUpdate` 鎖定的子樹不更新（`0x535295`） |
| 其他寫入者 | `0x533ec8`、`0x4da23f` | 建立時為 0；另一個寫入者是 フォーム widget（類型 15），pactex 沒有這種元件。沒有任何程式在子元件離開盒時清掉偏移；存檔不保存 |

垂直與水平的盒不寫這個偏移。

## 修正

- `src/parts/parts_internal.h`：部件多一個排版偏移（原版 +0x238／+0x23c）。
- `src/parts/parts.c`：計算畫面位置的四處（全域位置、元件更新、命中方框、左上角）改用「座標加偏移」。會改變 user component 內容根的操作（原點模式改變、子元件掛上、脫離、釋放、讀檔時掛上父元件、型別變成 user component）把它標成待更新。
- `src/parts/layoutbox.c`：user component 把原點模式傳給第一個子元件；自由盒依原點模式與尺寸設定直接子元件的偏移。原點模式是 1 的自由盒不量尺寸、不會被標記，位置完全不變。原點模式不是 1 的自由盒，在尺寸的來源改變時重排。
- `src/parts/debug.c`：傾印在偏移不為 0 時列出它。

只限 v14。XPE 存檔格式不變：偏移不存，讀檔後由排版重算。

## 獨立審查

一輪，四個面向（原版語義、程式正確性、探針品質、資料與回歸），審查者之外另有對抗驗證者重新查證每個 High／Medium。

- 沒有 High。兩個 Medium 經驗證都降為 Low：
  - 「原點模式 1 的 240 個 user component 不受影響」原本的理由不完整（有 55 個的內容是腳本建立的部件，不是 pactex 根）。驗證者逐一查了腳本設原點的 93 處呼叫與 32 種沒有同名 pactex 的類別，結論成立。
  - 影響表漏了春銷結算的客人檢視（腳本直接對內容根設原點模式 4）。已補上；方向與原版一致，修正前它的底緣超出畫面。
- 原版語義逐條以反組譯確認一致，並補查到盒尺寸的快取與 `Parts_SetLockUpdate`。
- Low 已處理：註解、`SetLayoutBoxLayoutType` 改變類型時通知外層的自由盒、除錯輸出、探針補案例（尺寸改變穿過中間層、Y 方向與上下翻轉）。

## 與原版的差異與限制

- **除了庫房以外的畫面都沒有實測**（見上表）。自由盒的尺寸沿用版面盒那一組的量法，文字行高還不是原版的公式，所以含文字的面板尺寸可能有偏差；庫房面板的尺寸只由 CG 決定。
- **重排是標記式**：原版在盒顯示時每幀重排，這裡在排版讀到的東西改變時才重排，隱藏的盒與 `Parts_SetLockUpdate` 鎖定的子樹也照樣更新。沒有涵蓋的輸入：`PE_SetComponentType` 改變某個狀態的類型、影片部件第一次取得尺寸。遊戲受影響的元件上沒有找到會走到的路徑。
- 原版盒尺寸的快取、連動條件與訊息視窗連動沒有重現。
- 離開了原點不是 1 的自由盒、成為頂層而保留偏移的部件，存讀檔後繪製位置與命中方框會不一致，直到下次設定座標；原版讀檔後偏移是 0。沒有找到遊戲會這樣做的地方。
- 同時是 user component 又帶有盒狀態的部件（原版是換掉整個 widget），排版把它當 user component，尺寸與命中仍把它當盒。
- 效能沒有量測。
