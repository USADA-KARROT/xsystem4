## 症狀與原因（修前，parent `814a83c`）

### 1. 多行文字讀檔後變成一行

- 【讀】`save_parts_text` 把文字狀態一行存成一個字串，不含換行。`load_parts_text` 修前把讀出的各行一個接一個 append，行與行之間沒有換行，所以多行文字讀回之後擠成一行；每一行讀出的字串（`iarray_read_string` 每次都新做一個）也沒有釋放。
- 【量】探針：v14 的 GBK 規則（CN 字格）四行讀回成一行，尺寸從 32x64 變成 64x16；v14 的 SJIS 規則三行、v13（XPE 版本 3）三行、首尾的換行，讀回都是一行；同一份五行的存檔讀兩次，第一次讀出的 5 個行字串都還在（[before.tsv](before.tsv)）。
- 這是寫與讀兩邊不一致的缺陷：存檔的寫法本身修前修後都一樣，所以修後讀以前的存檔，換行就補回來。

### 2. 影片聲音每格多送緩衝區尾端的樣本

- 【讀】`audio_callback` 每次把一格解碼結果交給混音器。修前的樣本數是 `linesize[0]` 除以每個樣本的位元組數，那是一個平面緩衝區的大小；一格實際只有 `nb_samples` 個樣本。比緩衝區短的格（Vorbis 短區塊後的那一格、被串流結尾裁掉的最後一格）會把格尾之後的內容也送出去，片頭的時鐘也跟著多算。只有 seek 之後的第一格原本就用 `nb_samples - trim`，兩條路的算法不一致。
- 【讀】遊戲片頭的聲音走的就是這條路：`movie_load` 把 APEG 檔的 SOND 區塊（一段 Ogg Vorbis）抽出來交給 FFmpeg，APEG 的影像解碼器不處理聲音；片頭的日誌只有一行音訊格式（44.1 kHz、雙聲道、平面 float），沒有視訊串流。
- 【量】片頭的聲音解出 4419 格：前 4418 格各 1024 個樣本，最後一格只有 1 個，緩衝區仍是 1024。實際的樣本共 4524033 個，緩衝區合計 4525056 個，修前在片頭結束時多送 **1023 個樣本（約 23.2 ms）**。只有最後一格不同。串流標的長度（4525057）不是解出的樣本數：第一個 Vorbis 封包不出聲音，第一格從時間戳 1024 開始。兩種計數方式（和引擎相同的 FFmpeg 呼叫逐格印出、ffprobe 逐格列出）格數與每格長度都相同。
- 【量】探針的合成素材也一樣：寫入 52920 個樣本（1.2 秒）的立體聲 Vorbis 解出 53 格，第一格 576、最後一格 120，緩衝區合計 54272，修前多送 1352 個，時鐘停在約 1.2307 秒（應為 1.2）。

### 3. parts 用完沒有釋放的記憶體

- 【讀】動畫狀態（SetLoopCG）保留一份 CG 名稱的副本：狀態釋放時不釋放它，同一個狀態再 SetLoopCG 一次時舊副本也不釋放。
- 【讀】`SetNumeralLinkedCGNumberWidthWidthList_by_index`（任何版本）與 v14 以前的 by-name 版，只為了確認 CG 存在而載入它，之後不釋放；字型函式其實不用這個 CG（它自己載入）。v14 的 by-name 版早已改寫成不載入。
- 【讀】`PE_Load` 讀出 CG 狀態的名稱後交給 `parts_cg_set`，`parts_cg_set` 自己會複製一份，讀出的那份沒有釋放。
- 【量】探針：動畫狀態的名稱在三種釋放時機（釋放元件、狀態換成 CG 狀態、`PE_Load` 取代元件）都沒有釋放（v14 與 v13）；第二次 SetLoopCG 沒有釋放第一個名稱；by_index 與 v13 的 by-name 6 次呼叫留下 6 個 CG（結構與像素）；三個 CG 狀態的存檔讀一次留下 3 個名稱字串。

### 4. Asin／Acos 回傳度

- 【讀】`Math_Asin`／`Math_Acos` 修前回傳 `asinf`／`acosf` 的結果換算成度。同一個檔的 Atan、Atan2 本來就回傳弧度。
- 【讀】這兩個函式是本分支 `99ac346`（2026-07-06，加入多娜多娜要的 v14 HLL 模組）加的，那時就是度；上游在 `e61f4b3` 之前沒有 Asin、Acos，之後所有版本都回傳弧度。
- 【量】探針：v14 的 Asin(1) 是 89.9999924、Acos(0) 是 90（度）。
- 【讀】多娜多娜的 AIN 只在 `AFL_Asin`／`AFL_Acos` 裡各呼叫一次，這兩個包裝函式沒有任何呼叫者；英文版戰國蘭斯（AIN v5）沒有宣告 Asin、Acos。所以兩款遊戲的實機都看不出這一項。

## 原版依據

### 反組譯看到的【反】

只有第 4 項有原版可讀。位址是中文版解殼檔。

- Math 的分派 `0x4c6520`：Cos、Sin、Tan（case 0–2）取參數之後先乘一個常數（`0x81306c`，單精度 0.0174532924，也就是 π/180）再呼叫；Asin（case 3）取參數之後直接呼叫 `0x78641d`，Acos（case 4）直接呼叫 `0x786040`，之後都跳到共用的結尾，把回傳值原樣當作 float 存回去，沒有乘任何常數。Atan（case 5）也一樣不乘。
- 所以 v14 的 Asin、Acos 回傳的就是那兩個函式的結果，單位是弧度。HLL 表裡 Math 的第 3、4 個宣告是 `float Asin(float x)`、`float Acos(float x)`，對應這兩個 case。
- 參數乘 π/180、結果不換算，和移植版 Cos、Sin、Tan 收度、Atan、Atan2 回弧度的做法一致。

### 推論【推】

- `0x78641d`、`0x786040` 是 C 函式庫的 asinf、acosf：反組譯裡有反三角函式典型的分段門檻（√3/2）與 `sqrt(1 − x²)`，還用到常數 1.0，但沒有符號名；哪一個是 asin、哪一個是 acos，只靠分派表的順序。
- 原版播片頭聲音用的是自己的播放器，最後一格怎麼處理沒有讀；推論原版只播實際的樣本。
- 原版 PartsEngine 的存檔格式沒有和移植版的 XPE 對照（XPE 是移植版自己的格式）。

### 沒有原版依據的三項

第 1、2、3 項修的都是移植版自己的錯，不是原版語意的改變：存檔格式是移植版的，讀與寫兩邊不一致；影片聲音的長度是解碼結果，和遊戲版本無關；洩漏的修正只是釋放，回傳值、建出的字型與畫面都不變。

## 做法

- **多行文字**（`load_parts_text`）：從第 2 行起，每一行之前先 append 一個換行再 append 那一行；換行字串與每一行讀出的字串用完都釋放；迴圈變數改成 `int`（行數是 `int`）。append 的字元序列和 `PE_SetText`（各行以換行接起來的原文）走的是同一條路，所以行數、每行的字元、行高與寬高都和存檔前相同。存檔的寫法不動。
- **影片聲音**（`audio_callback`）：每格一律用 `nb_samples - trim`；`trim` 只在 seek 後的第一格不是 0，所以 seek 後的第一格和以前相同。時鐘用同一個數字推進。只有平面的樣本格式（s16、s32、float）會進這個回呼，`nb_samples` 是每聲道的樣本數。
- **parts 的洩漏**：動畫狀態釋放時一併釋放名稱；`parts_animation_set_cg` 成功時先釋放舊名稱再複製新名稱（失敗時狀態不動）；by_index 與 v14 以前的 by-name 在存在檢查之後立刻 `cg_free`，字型函式拿掉沒用的 CG 參數（兩個呼叫端跟著改）；`load_parts_cg` 把讀出的名稱交給 `parts_cg_set` 之後釋放。存在檢查仍然解碼一次 CG（`asset_cg_load`），所以檔在但解不開時照舊回傳 false。
- **Asin／Acos**：`ain->version >= 14` 時直接回傳 `asinf`／`acosf`（弧度）；v13 以下照舊換算成度。程式註解寫明原版分派的讀法、那兩個函式是推論，以及 v15 以上與 v13 以下都沒有讀過原版。

## 移植策略與範圍【移】

主線的三個決定：

- **D1：多行文字與影片聲音不限版本、不限字集。** 硬規則「v13 以下與 SJIS 的行為必須保留」的用意，是不要把 v14 或 GBK 專屬的新行為帶到舊遊戲；這兩項修的是所有版本共有的移植版錯誤：XPE 是移植版自己的存檔格式，各版本、各字集的寫法相同，修前是讀寫兩邊不一致；影片聲音的長度由解碼器決定，和遊戲版本無關。上游也是所有版本都修。量得到的影響：v13 的多行文字讀回由一行變成多行（SX6，可量到的改變），v14 的 SJIS 規則也一樣（SX2）；英文版戰國蘭斯（AIN v5）的兩部影片修前修後每格長度相同（下面〈量測〉）。v13 以下、聲音是 Vorbis 的其他遊戲沒有量。
- **D2：Asin／Acos 的 v14 照原版回傳弧度；v15 以上跟 v14，v13 以下保留度。** v15 以上沒有讀過任何執行檔，照移植版其他 v14 邏輯的慣例（`ain->version >= 14`）跟 v14 相同，這是移植版的選擇（MI6）。v13 以下也沒有讀過原版，保留的「度」是本分支 `99ac346` 的舊行為，**沒有原版依據**，只是保留舊行為（MI4、MI7）；上游對所有版本回傳弧度，也沒有附原版依據。兩款手上的遊戲都不呼叫這兩個函式，所以實際的風險是 0。
- **D3：parts 多修兩處**：v14 以前 by-name 版的存在檢查（PK4）與 `load_parts_cg` 的名稱（PK6）。只是釋放，不改回傳值與畫面；上游 `5d032d7` 也有這兩處。PK6 在例行路線上沒有實機走到（下面〈實機沒有走到的兩項〉）。

不在這一組：v14 以前 gauge 的 CG（上游 `5d032d7` 也補了 `cg_free`；移植版只在 v14 釋放，v13 以下仍然留著），留到之後的組。

## 和原版仍不同的地方

1. **存檔格式**：XPE 是移植版自己的格式，原版 PartsEngine 的存檔沒有對照；這一組只讓移植版的寫與讀一致。
2. **片頭聲音**：移植版由 FFmpeg 解 APEG 裡的 Vorbis，修後播到每格的 `nb_samples` 為止，和參考解碼器逐樣本相同（ML1–ML3）；原版的播放器沒有讀（推論只播實際的樣本）。
3. **存在檢查**：移植版仍然解碼一次 CG 再釋放；原版怎麼檢查沒有讀。
4. **Asin／Acos 的 v13 以下與 v15 以上**：沒有原版可讀（〈移植策略與範圍〉）。

## 驗證

### 探針

說明與各案內容見 [harness](../../harness/README.md) 的五個條目（`forked_cases.inc` 與四個模式）。資料全部合成，不用遊戲資產；每案在 fork 出來的子行程裡跑，兩種字集都跑。

- `save-text-lines`（8 案）：經正式的 `PE_Save`／`PE_Load`。SX1 v14 GBK 規則四行含空行（含首位元組落在 SJIS 首位元組範圍內、存成一個字的 GBK 字），SX2 v14 SJIS 規則三行，SX3 首尾的換行、只有換行，SX4 讀出的字串與補換行用的字串一個都不留，SX5 守衛（單行與空文字），SX6 v13 三行，SX7 守衛（v13 單行），SX8 守衛（存檔的格式不變）。寬高只在 GBK 規則的 CN 字格上比得出來（SX1、SX3）；SJIS 規則與 v13 的案例用沒有字形的字型，寬高修前修後都是 0x0，只比行數、字元與行高。

- `parts-leaks`（7 案）：PK1 動畫狀態的名稱隨狀態釋放（三種時機，v14 與 13），PK2 第二次 SetLoopCG 釋放第一個名稱、同名再設也換成新副本，PK3 by_index 不留 CG（結構與像素），PK4 v13 的 by-name 同上，PK5 守衛（v14 的 by-name 本來就不載入 CG），PK6 讀檔讀出的名稱不留，PK7 守衛（SetLoopCG 失敗時狀態不變）。

## 沒做與沒驗證

- **兩項的實機**：多行文字讀檔與 `PE_Load` 的 CG 名稱沒有在例行路線上走到（上面），回想模式的路線沒有做。

- **verify 證明不了分派齊全**：整合審查者把一個新模式在 `runtime_probe.c` 的分派拿掉，那個模式掉進 `main` 預設的 timer 路徑，印 TIMER PASS、rc 0、sanitizer 0，verify 照樣判 ok。這一組的分派是齊全的（提交後兩組 verify 各 130 行、沒有重複的模式，TIMER PASS 只出現在 timer 那一行，四個新模式印的都是自己的標籤；提交前那兩組由整合審查者核對過，相同），但 harness 本身沒有自我檢查。下一個動 `runtime_probe.c` 的組可以讓 verify 檢查：timer 以外的模式最後一行不能是 TIMER PASS。
- **只靠 sanitizer 中止殺掉的 7 個突變**：沒有 ASan 的建置下沒有驗證。
- **洩漏偵測**：用 ASan 掛鉤計數加內容辨認，不是 LeakSanitizer 或 `leaks`；沒有做「沒有 ASan 的探針加 `leaks`」（案例都在 fork 出來的子行程裡跑，`leaks` 只看它啟動的那個行程）。
