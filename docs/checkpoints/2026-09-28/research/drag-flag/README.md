## 問題與修正範圍

修前的 pactex 載入器不讀拖曳旗標；只在 pactex 設為 1、而載入後腳本沒有設定可拖的元件，在拖曳中不會跟著游標移動。【反組譯】腳本分析找到受影響的兩類使用處：客人立繪的判定元件，以及戰鬥行動面板的拖曳範圍。編隊與人材清單在載入後自行設定旗標，因此修前已能拖曳。

【策略】本次只在一般屬性套用時補讀 GBK／SJIS 兩種鍵的原始位元組，整數值等於 1 才呼叫 `PE_SetDrag`。不改按鍵派送、拖曳門檻、放下目標選取、換位演算法或滑動。版本閘門排除 AIN v14 之前；v13 載入由 DG5 守住，不能據此宣稱所有舊遊戲都已驗證。程式對高於 v14 的版本也會套用，本組沒有更高版本的遊戲覆蓋。

## 移植策略與原版的界線【策略】

- 正常載入先配置旗標為假的新 parts，因此只在值為 1 時設定真，與原版每次寫入真假得到相同結果。跨程序還原後又載入而碰到既有 parts 的情形不在這個等價論證內。
- 兩種鍵任一個整數值為 1 就啟用。原版中英文執行檔各讀一種，雙鍵衝突的結果並不等價；既有資料未見雙鍵並存，探針未涵蓋衝突。
- 移植版只接受整數，浮點當成缺鍵；原版會截斷。既有資料盤點的 2,706 筆屬性都是整數，這是資料範圍的證據，不能推廣成一般格式規則。
- 屬性只在載入時套用，後來的腳本 `Parts_SetDrag` 仍能開啟或關閉；本次沒有改存讀檔格式。

## 仍有差異與未涵蓋項目

- 浮點屬性、雙鍵衝突與跨程序還原後重載的界線見〈移植策略〉。根元件帶拖曳值與 SJIS 鍵的字串值沒有獨立子案。
- 【量測】DG8 證明切層期間提供者仍處於拖曳中，卡片保留位置與高 Z；切回後歸位是 G8b 既有行為。【推論】原版每層保留管理器，因此切走期間應有相同殘留；沒有原版畫面。
- 拖曳中刪除所在層不同於切層。移植版會釋放該層 parts，畫面不留卡片；仍存活的腳本提供者可能留在拖曳狀態【推論】。原版此時是否送 DragEnd 未分析，DG8 沒有刪層操作。
- DG9 的快速移動並放開、callback 內讀值，以及兩份清單自身的換序 callback 不在探針內；後者只由已測實機路線支持。
- 原版拖曳畫面、顯示中的受影響客人判定元件、戰鬥行動面板的修正效果、拖曳中按右鍵，以及完整編隊插入流程，沒有本組有效畫面驗收。
- 其他 SJIS 屬性鍵的相容性、`Parts_GetPartsDrag`、每層取樣／取消、滑動、放下訊息與右／中鍵拖曳都沒有在本次擴充。
