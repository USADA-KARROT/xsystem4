# CG 的翻轉：戰鬥結算的頭像與系統選單的白底

2026-10-19。程式 `ac2356e`，基準 `229f2f5`（前一組程式 `0bf82e6`），libsys4 固定 `247f544`。提交前、後的預設與 GBK 各 111 個模式 PASS。

## 症狀

- 戰鬥結算下方的四個隊員頭像，移植版和原版左右相反。使用者 10/19 發現；回查留有結算畫面的建置，最早到 10/10 的都是這樣。
- 系統選單右側斜切的白底，斜邊的方向也和原版相反。
- 戰鬥中換人面板的頭像方向本來就正確。

## 原因（實機紀錄加讀程式）

- 原版每個狀態的 CG 都有一個翻轉值（1 是左右、2 是上下）。畫面設定檔（pactex）的 CG 部件用 `変形` 這個鍵設定它。
- 結算頭像的設定檔是 `変形` 1，換人面板是 0；兩者換上隊員的臉的腳本完全相同。
- 腳本換臉時會先把翻轉值讀回來，再連同新的 CG 名一起設定，所以翻過的圖換臉後仍然是翻的。
- 移植版有兩處把這個值丟掉了：載入設定檔時一律傳 0，讀回翻轉的函式也一律回 0。
- 全部 pactex 裡 `変形` 是 1 的共 9 處，見〈受影響的畫面〉。

## 原版依據

只做靜態分析，讀多娜多娜這一支執行檔。

| 項目 | 位址 | 內容 |
|---|---|---|
| 載入 | `0x59cd70` | CG 部件的載入器讀 `変形`（缺鍵是 0），連同 `ＣＧ名` 交給設定器。CG 判定部件是另一種物件（`0x59b600`、載入器 `0x59bd90`），不讀 `変形` |
| 設定 | `0x59c5b0` | 把翻轉存在該狀態 CG 物件的 `+0x20`；空名時也寫；CG 載不到時名稱和翻轉都不改。`SetPartsCG` 也走這裡 |
| 套用 | `0x5aa250` | 設定 CG 時就把翻轉套到 surface 上，所以只有 CG 會翻 |
| 讀回 | `0x598120` → `0x565540` | 號碼 ≤ 0 時回 0、不建立元件；其他號碼取得或建立元件。先呼叫 `0x5b77f0(0x13)` 把狀態變成 CG：原本不是 CG 的，換成新的 CG 物件，翻轉是 0 |

## 做法

- 每個元件的三個狀態各記一個翻轉值，只對 CG 狀態有效。繪製、像素命中判定與遮罩都用該狀態的值。
- 載入器的兩條路徑（低等級部件的路徑，與遊戲沒有用到的舊依序路徑）都對 CG 部件讀 `変形`；讀回翻轉的函式照原版處理號碼 ≤ 0 與「先變成 CG」。
- **存檔仍是 XPE 第 12 版**：翻轉值寫在清單之後的一段帶標記的選用資料。實測過 `0bf82e6` 的建置讀到這種存檔會乾淨地略過，只是少了翻轉。沒有元件的翻轉因狀態而不同時（例如完全沒有翻轉）不寫這一段，存檔和修改前逐位元組相同；從系統選單存檔時這一段通常會出現。
- **移植版的選擇**：
  - 原版在設定時翻 surface，這裡在繪製時翻。只有在 CG 只取一部分（`サーフェイスエリア` 不是整張）時兩者不同；遊戲的 9 處都是整張。
  - 讀回翻轉時，原版還會把元件的 widget 改成低等級部件，這裡不改，和既有的取值函式一致。
- **適用範圍**：
  - 對所有 v14 遊戲都適用，不分編碼（`変形` 的 SJIS 與 GBK 拼法都認）。
  - v14 之前的遊戲不受影響：載入器照舊傳 0，讀回照舊回 0，遮罩不翻。

## 驗證

- **探針 `cg-deform`**（9 案，說明見 [harness](../../harness/README.md)）：
  - 繪製、命中與遮罩的期望值由探針裡另寫的鏡像模型算出；v14 之前與依序路徑以修改前的行為為準。
  - 修改前 8/9 失敗，另 1 案是 v14 之前的守衛，見 [before.tsv](before.tsv)。
  - 31 個故意改壞的突變都有案例抓到。
- **兩組 verify**：提交前、後的預設與 GBK 各 111 模式 PASS，見 [verify.tsv](verify.tsv)。
- **和原版並排**（原版是 Wine 上的截圖，畫面只留在私人工作區）：
  - 戰鬥結算的頭像：提交後的執行檔在片頭重播的結算畫面上，四個頭像和原版的平均差 8–10，拿鏡像去比是 55–97；同一畫面用修改前的執行檔直接比是 47–56。
  - 系統選單的白底：斜邊在沒有被選單按鈕與背後貼紙擋到的列（上、下兩端）和原版差 1 px 以內，左緣的網點位置也相同。
  - 換人面板的頭像：第一版實作的建置和原版同向、和修改前相同（之後兩輪只加守衛，沒有重跑）。春銷結算畫面：提交後和修改前逐像素相同。
- **例行路線**：
  - normal150、haruuri、fightr、config、backlog、savedialog、garage、sysmenu 與片頭重播都跑完：exit 0、錯誤 0，對白和前一組（構築命令）逐字相同。
  - 點擊目標：片頭重播與其他路線都相同。fightr 少了一次點擊（171→170）：序號 64 的自動點擊（第 65 下）剛好碰上切換到結算畫面，只按下、沒有形成點擊，之後整串錯開一格。對基準差 140 處，其中 33 處在那一下之前（位置相同、點到不同元件，是戰鬥時序的差別），其餘在錯開之後。以前兩趟舊建置的紀錄也少了同一下，其中一趟和這一趟只差 2 處；是時序現象。
  - 片頭 50 張畫面仍和參考解碼器逐像素相同。
  - 見 [routes.tsv](routes.tsv)。

## 沒做與沒驗證

- **派遣結算**（只在特殊顧客的派遣時出現）整個畫面沒有走到，也沒有原版畫面，所以那裡兩個立繪的翻轉沒有驗證。
- **標題卡背面、成員畫面的底色**：只有修改前後對照，沒有原版畫面。
- **存檔**：選用資料段只在存讀檔的函式層級實測過，沒有拿遊戲的存檔在新、舊建置之間實機互讀。
- **探針沒有案例的守衛**（目前的程式是對的，複審另跑的突變存活）：鍵的 SJIS 拼法、依序路徑的狀態上限、不是整數的鍵、v14 之前遮罩不翻、讀檔時資料段的標記檢查、3D 圖層的翻轉、遮罩用 clipper 目前狀態的翻轉（探針的 clipper 都在狀態 1）。
- **舊存檔**：修改前存的檔沒有翻轉段，讀進來時每個狀態取元件最後一次的值；存檔時畫面上若有翻過的元件，讀檔後要等畫面重建才會翻（和修改前畫的一樣，不是退步）。
- **v14 之前**：只把合成的設定檔以 AIN 版本 13 載入驗證，沒有拿 v14 之前的真遊戲實測。
- **翻轉 3**（左右加上下）：原版另有處理，遊戲沒有用到，這裡照舊不翻。
- **CG 判定部件**：原版讀回翻轉時會把它換成 CG，這裡不換；遊戲碰不到。
- **其他平台**：Windows、Linux 沒有建置。
