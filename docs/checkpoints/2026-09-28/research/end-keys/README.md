# Activity 的結束鍵：設定與回顧用右鍵、Esc、空白鍵關閉

2026-10-20。程式 `2ae5ab5`，基準 `4707bd1`（前一組程式 `bf58d4b`），libsys4 固定 `247f544`。提交前、後的預設與 GBK 各 114 個模式 PASS。

UI 盤點的 G6。

## 症狀

設定的各頁、劇情回顧、情節回顧，不能用右鍵、Esc 或空白鍵關閉，只能按畫面上的返回。使用者回報「設定很多不能用」的一部分。

## 哪些鍵、怎麼知道的

不是靠試玩猜的，是遊戲自己的資料與腳本寫的：

- **畫面設定檔（pactex）**：每個畫面有一欄「結束鍵」，列 Windows 的按鍵代碼。設定的 9 頁與劇情回顧是 2、27、32（右鍵、Esc、空白鍵），情節回顧是 2、27（右鍵、Esc）。全部設定檔裡只有這 11 個有這一欄。
- **腳本**：`BindEndType` 為每個鍵建一個點擊偵測，`UpdateActivity` 每幀檢查，鍵**放開**時關閉畫面，並記下是哪個鍵。空白鍵在輸入欄作用中時跳過，Esc 在輸入法轉換中時重設。

## 原版依據

只做靜態分析，讀多娜多娜這一支執行檔。

| 項目 | 位址 | 內容 |
|---|---|---|
| 讀取 | `0x560210`（`0x5603df`..`0x56046f`） | 載入畫面時，在讀畫面的元件樹之前，先讀「結束鍵」清單 |
| 存放 | `0x562920` | 排序、不重複的整數集合 |
| 五個函式 | `0x58ae30`、`0x55e5f0`、`0x58ae90`、`0x58aef0`、`0x58af30` | 依畫面名稱設定、刪除、查詢、計數、依序取得；名稱找不到時什麼都不做，回假或 0；取得超出範圍回 0 |

## 做法

- 載入器讀結束鍵清單，五個函式照上表實作。
- **適用範圍**：這組函式只在 v14 註冊，v14 之前的遊戲不受影響。清單的區塊名稱只認 GBK 拼法，SJIS 版本（英文版）照舊沒有結束鍵。
- **測試工具**：自動排程新增 `key,T,VK[,MS]`，按住一個鍵 MS 毫秒（預設 100），不動游標。

## 驗證

- **探針 `end-keys`**（5 案，說明見 [harness](../../harness/README.md)）：經正式的載入器讀清單、經遊戲腳本的宣告呼叫五個函式、跑真的 `BindEndType`／`IsClickEndKey`、送真的鍵盤事件。修改前 5/5 失敗，見 [before.tsv](before.tsv)。修改前右鍵、Esc、空白鍵的「按下」本來就讀得到，只有「放開時關閉」失敗。16 個故意改壞的突變都有案例抓到。
- **兩組 verify**：提交前、後的預設與 GBK 各 114 模式 PASS，見 [verify.tsv](verify.tsv)。
- **實機**（提交前的建置）：設定頁用 Esc、空白鍵、右鍵各關一次，劇情回顧與情節回顧用右鍵關閉。每次關閉後的畫面，和按「返回遊戲」之後的畫面逐像素相同；對白在整段期間沒有前進。
- **例行路線**：
  - normal150、haruuri、fightr、config、backlog、savedialog、garage、sysmenu 與片頭重播都跑完：exit 0、錯誤 0，對白和前一組（滑過事件）逐字相同。
  - 點擊目標：片頭重播與其他路線都相同。fightr 的點擊位置序列相同，目標差 68 處；和先前幾組的執行只差 3 處，屬既有的分群（不同群之間差 44–73 處）。
  - 片頭 50 張畫面仍和參考解碼器逐像素相同。
  - 每一步前後的桌面游標位置都沒變。
  - 見 [routes.tsv](routes.tsv)。

## 沒做與沒驗證

- **設定只實機測了第 1 頁**；其他 8 頁的清單相同、走同一條路徑，沒有逐頁確認。
- **原版的關閉畫面沒有補拍**；驗收以「和按返回遊戲相同」為準。
- **空白鍵與 Esc 的例外**（輸入欄、輸入法）是腳本自己的行為，沒有驗。
- **右鍵的點擊訊息**：之後的 G8 會把右鍵點擊送給腳本，到時要確認設定頁按右鍵只關一次。
- **SJIS 版本**：區塊名稱沒有讀過，不猜。
- **其他平台**：Windows、Linux 沒有建置。
